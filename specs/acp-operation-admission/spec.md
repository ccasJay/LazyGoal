# ACP Prompt 与 Session 创建准入

## 目标与范围

同一 ACP Session 从输入校验开始只接纳一个 Prompt。连接关闭后，Agent 负责释放工厂迟交的 Session。
沿用 [ACP v1 与容器集成边界](../acp-container-runtime/design.md) 中的请求格式、能力声明、资源链接校验和 Runtime 所有权。

## 用户故事

- **S1** 作为 ACP 客户端，我希望同一 Session 的 Prompt 从校验到结算都有明确的占用和取消语义，以便避免重复执行，并在本次调用结束后安全重试。
- **S2** 作为 ACP 连接宿主，我希望创建途中断线也能释放交付给 Agent 的 Session，以便回收资源并保留请求的失败原因。

## 验收标准

| ID | 故事 | 类型 | 当 | 系统应 | 验证 |
|---|---|---|---|---|---|
| R1.1 | S1 | 状态 | 同一 Session 的首个 Prompt 正在校验或执行 | 以现有 `invalidParams` 和 Prompt 进行中诊断拒绝后续请求。后续请求不得进入校验、调用 Session 或排队执行。 | 通过 SDK 内存连接发两个同 Session 请求，挂起首个合法 `resource_link` 的异步校验，断言第二个立即被拒且未进入校验，首个最终只调用一次 Session。 |
| R1.2 | S1 | 异常 | 未取消的输入校验失败或 Session 执行失败 | 返回原有参数或执行错误。释放本次占用和中止监听，允许随后提交的新 Prompt 执行。 | 分别注入异步资源校验失败、Session 执行拒绝，断言错误原因与后续成功请求，并核对无额外执行。 |
| R1.3 | S1 | 事件 | `session/cancel`、请求中止或断线先于 Prompt 进入 Session | 中止该 Prompt。校验结算后不调用 Session，取消优先于校验结果。仍可回复的请求返回 `stopReason: "cancelled"`，SDK 已中止的请求保留 SDK 的取消或关闭结果。 | 分别在校验挂起时发送取消通知、触发 SDK 请求中止、关闭连接。释放校验闸门并断言零次 Session 调用，覆盖晚到校验成功和失败。 |
| R1.4 | S1 | 状态 | 已取消的 Prompt 仍在等待校验或执行结算 | 保持同一 Session 的占用。连接仍开放时，原操作结算后才允许新 Prompt 开始。执行中的取消沿用 Session 的中止信号与结果语义。 | 分别挂起校验和 Session 执行，在取消后、结算前后各尝试提交，断言拒绝和恢复顺序。 |
| R1.5 | S1 | 普遍 | 同一连接有多个已注册 Session | 不同 Session 可以并行。取消只作用于目标 Session。 | 挂起 A 的 Prompt，断言 B 可独立执行并成功，A 的取消不触发 B 的信号。 |
| R2.1 | S2 | 事件 | `session/new` 参数通过校验且连接仍开放 | 独立预留每次创建的 Session ID，只在工厂成功且预留仍属于当前开放连接时注册。成功后客户端可以使用该 ID，创建中的 Session 不可供调用或发送更新。 | 挂起两个工厂并逆序释放，核对不同 ID、各自的 Prompt 和更新路由，以及注册前更新被抑制。 |
| R2.2 | S2 | 异常 | 创建工厂拒绝，连接仍开放 | 保留工厂原错误，释放该次预留，之后的新建请求可以成功。Agent 不自动重试工厂。 | 工厂先拒绝，再由客户端显式重发，核对主错误、工厂调用次数与下一次创建结果。 |
| R2.3 | S2 | 事件 | 连接关闭时，已有 Session 正在处理 Prompt，且另一工厂仍未完成 | 中止连接和 Prompt 信号，禁止旧 Session 继续发更新。已注册 Session 等自己的 Prompt 结算后恰好释放一次，且其释放不受未完成工厂阻塞。 | 同时挂起已注册 Session 的 Prompt 与另一工厂，断线后分别控制两者结算，验证中止、通知抑制和释放顺序。 |
| R2.4 | S2 | 异常 | 工厂在连接关闭后才返回 Session，即使已注册 Session 的清理已经完成 | 不注册迟到实例、不发送创建成功或 Session 更新，并对实例调用一次 `dispose`。释放失败不得覆盖原关闭结果、触发重试或产生未处理拒绝。 | 用 SDK 关闭连接，等待已注册 Session 释放后再放行工厂，核对工厂信号、客户端拒绝、零更新和单次释放。分别让迟到实例的释放成功与失败。 |

组合：通过 `npx tsx --test packages/acp/test/*.test.ts` 验证上述场景，使用可控闸门和 SDK 内存连接确认顺序；运行 `npm test` 覆盖现有 Client、Benchmark 适配与文档回归。

## 决策

| 决策 | 理由 | 放弃 |
|---|---|---|
| [Agent](../../packages/acp/src/agent.ts) 在首个异步校验前把当前 Prompt 连同中止控制和结算归属登记到 Session。结算仅能释放自己占用的记录，已关闭记录保持终态。 | 同一占用记录为准入、取消和断线清理提供依据，覆盖校验失败、执行失败与晚到结算。 | 无 |
| 每次服务启动持有独立连接状态。Agent 在调用工厂前登记当前连接下的创建预留，在工厂交付时检查该预留与连接中止或关闭状态，同步决定注册或释放。 | 连接状态的身份即可限定归属。工厂可以在收到中止后交付资源，交付即将释放责任转给 Agent。 | 无 |
| 断线清理已注册 Session。仍未结算的工厂保留各自的交付收尾路径，释放错误留在清理路径处理。 | 正常清理可在慢工厂仍挂起时完成，原请求的错误保持可见。 | 无 |
| 使用现有 SDK 和 [公开接口](../../packages/acp/src/contracts.ts)。在 TSDoc 与 ACP 模块说明中同步 Prompt 排他、连接关闭及工厂交付的语义。 | 状态由 ACP Agent 持有，仅需进程内记录。 | 无 |

## 风险与否定性保证

| 等级 | 理由 | 关键操作 |
|---|---|---|
| medium | ACP 请求的准入和清理顺序影响所有现有宿主，需覆盖取消、断线和迟到结算。 | 无 |

工厂仍负责清理未交付给 Agent 的资源。回归用内存连接和临时文件验证，无需启动真实模型或容器。
