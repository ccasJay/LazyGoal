# 浏览器 Slash Command 接入需求

## 审批摘要

### 目标

让浏览器会话能够发现并使用现有 `/plan` 和 `/model` 命令，且模型选择与实际 Run 执行、恢复保持一致。

### 范围

- 包含：浏览器输入框的命令候选与选择、现有 `/plan` 行为、当前 Provider 的 `/model` 选择，以及草稿、等待状态和终态的模型选择。
- 不包含：新增其他命令、跨 Provider 切换、运行中的换模、TUI 重做或会话页面整体改版。

### 核心行为

- 输入 `/` 时按前缀展示候选并支持键盘和鼠标选择；普通文本和 `//` 转义保持有效。合法命令只执行界面操作，不成为 Goal 消息或 Step；未知命令和非法参数明确拒绝。
- `/plan` 保持当前或下一 Run 的现有模式选择规则。`/model` 展示当前 Provider 的模型、当前选择、目录来源及不可选原因；离线兜底须明确标注，支持取消和失败反馈。
- 新 Goal 草稿的模型选择随首条消息创建 Goal 时保存；未创建的草稿刷新后仍按现有行为丢弃。安全等待点可切换当前 Goal 模型；已完成或失败时可预选下一 Run 的模型，选择持续适用于该 Goal，直到再次切换。Action 审批和运行中不得换模。
- 已保存的选择在刷新、重启和后续执行时保持一致；保存或构造失败不得出现界面模型与实际调用不一致。过期请求与并发执行必须拒绝或安全排序，并让用户看到可恢复的错误。
- 浏览器接口沿用现有会话授权，仅传输必要的非敏感模型信息；API Key、认证头等凭据不得进入页面、Goal 消息或持久化选择。

### 风险与待确认

- 风险等级：medium；理由：跨越浏览器 UI、公共 API 和 Runtime 持久化选择，但沿用现有本机会话授权与 Provider 凭据所有权。
- 关键操作：无。
- 风险：多 Goal 共用进程模型 Binding 可能导致错误模型被调用；终态预选与下一 Run 启动并发时可能丢失选择；目录错误可能泄露凭据或误导用户。
- 待确认：无。

## 引言

浏览器会话复用现有 Slash Command 语义，补齐 `/model` 的选择和恢复闭环，并确保命令交互不改变用户任务消息。

## 需求

### 需求 1：命令发现与输入兼容

**用户故事：** 作为浏览器会话用户，我希望在输入时发现并选择 Slash Command，以便不用记忆命令且不影响普通消息。

#### 验收标准

1. <a id="req-1-1"></a> 当可用输入框中的首个非空白字符为 `/` 时，页面必须展示已接入命令，并随名称前缀过滤候选。
2. <a id="req-1-2"></a> 当候选可见时，用户必须能用键盘和鼠标选择命令，取消候选后仍可编辑原输入。
3. <a id="req-1-3"></a> 当用户提交合法命令时，页面必须执行对应操作，且不得将命令文本保存为 Goal 消息或 Run Step。
4. <a id="req-1-4"></a> 当用户提交未知命令或非法参数时，页面必须显示拒绝原因，且不得将该文本作为普通消息发送。
5. <a id="req-1-5"></a> 当用户提交 `//` 开头的转义文本或普通文本时，页面必须保持现有文本提交、换行与校验语义；转义文本只去掉命令位置的一个 `/`。

### 需求 2：浏览器中的 `/plan` 行为

**用户故事：** 作为浏览器会话用户，我希望从命令候选选择 `/plan`，以便为当前或下一任务启用已有的提案审批模式。

#### 验收标准

1. <a id="req-2-1"></a> 当新 Goal 草稿接受 `/plan` 时，页面必须把随后首条任务创建的 Run 设为 Plan Mode，且不得仅因执行命令就创建 Goal。
2. <a id="req-2-2"></a> 当已完成或失败的 Goal 接受 `/plan` 时，下一 Run 必须按现有一次性模式选择规则进入 Plan Mode。
3. <a id="req-2-3"></a> 当当前 Run 不允许切换模式或会话身份已过期时，页面必须显示拒绝并刷新到最新状态，不得伪装为已选中。

### 需求 3：模型目录与选择交互

**用户故事：** 作为浏览器会话用户，我希望通过 `/model` 查看并选择当前 Provider 的模型，以便知道下一次模型调用会使用什么。

#### 验收标准

1. <a id="req-3-1"></a> 当用户打开 `/model` 时，页面必须显示可取消的加载状态，并只查询当前 Provider 的模型目录。
2. <a id="req-3-2"></a> 当目录返回时，页面必须区分当前选择、可选模型和不可选模型，并显示不可选原因及现有目录所提供的来源或能力信息。
3. <a id="req-3-3"></a> 当用户选择模型时，页面必须只接受目录标记为可选且与当前 Provider 兼容的模型；选择当前模型不得产生重复切换。
4. <a id="req-3-4"></a> 当用户取消选择、离开原会话或较新的目录请求已经发出时，迟到结果不得覆盖当前页面状态或模型选择。
5. <a id="req-3-5"></a> 当目录加载或切换失败时，页面必须说明失败并允许重试，且保持原模型生效。
6. <a id="req-3-6"></a> 当现有模型目录因临时故障使用离线兜底时，页面必须标明访问权限未经验证；鉴权、权限或响应协议错误不得显示为成功的兜底目录。

### 需求 4：各 Goal 状态的模型选择时机

**用户故事：** 作为跨多个 Run 使用 Goal 的用户，我希望在安全时机选择模型，以便当前等待任务和下一任务分别使用我确认的选择。

#### 验收标准

1. <a id="req-4-1"></a> 当用户在未创建的 Goal 草稿中选择模型时，首条任务创建的 Goal 必须保存该选择并用它启动首个 Run；如果草稿在创建前刷新，选择随草稿丢弃。
2. <a id="req-4-2"></a> 当 Goal 处于可安全切换的用户输入等待点时，用户必须能打开 `/model`；如果等待交互使用独立表单，也必须提供该命令入口，且切换不得提交或清除待回答内容。
3. <a id="req-4-3"></a> 当 Goal 已完成或失败时，用户选择的模型必须在下一条任务启动 Run 前保存；该选择随后持续适用于此 Goal，直到再次切换。
4. <a id="req-4-4"></a> 当模型调用、Tool 执行、Action 审批或其他不安全状态正在进行时，页面与服务端都必须拒绝切换，不得改变当前模型或等待状态。
5. <a id="req-4-5"></a> 当用户切换 Goal、Run 身份变化或页面持有过期状态时，模型选择必须绑定到正确的 Goal 与 Run；旧请求不得改写新状态。

### 需求 5：选择、执行与恢复一致

**用户故事：** 作为浏览器会话用户，我希望看到的模型与实际执行模型一致，以便刷新或重启后仍可预测后续行为。

#### 验收标准

1. <a id="req-5-1"></a> 当模型选择成功时，系统必须在下一次相关模型调用前保存必要的非敏感选择，并用该选择构造实际调用所需的完整模型能力与预算。
2. <a id="req-5-2"></a> 当模型能力构造或持久化失败时，系统必须保留原有有效选择，不得报告切换成功或让后续调用使用未保存的选择。
3. <a id="req-5-3"></a> 当页面刷新或进程重启后读取已有 Goal 时，页面显示与后续模型调用必须依据该 Goal 已保存的选择；恢复失败不得静默改用其他模型。
4. <a id="req-5-4"></a> 当不同 Goal 选择不同模型时，推进其中任一 Goal 的模型调用必须使用该 Goal 的已保存选择，不得被另一 Goal 最近的切换覆盖。
5. <a id="req-5-5"></a> 当终态模型预选与下一 Run 启动同时发生时，系统必须给出明确先后结果；已接受的预选不得被下一 Run 悄然跳过。

### 需求 6：浏览器授权与信息保护

**用户故事：** 作为本机浏览器会话用户，我希望模型选择不暴露 Provider 凭据，以便仍由本机 Runtime 控制模型访问。

#### 验收标准

1. <a id="req-6-1"></a> 当浏览器读取模型目录、当前选择或提交切换时，所有请求必须受现有浏览器会话授权保护；无效或过期授权不得返回模型信息或改变状态。
2. <a id="req-6-2"></a> 当模型信息返回页面或持久化到 Goal 时，系统不得包含 API Key、认证头、Provider 密钥配置或其他凭据。
3. <a id="req-6-3"></a> 当浏览器提交无效模型、跨 Provider 模型或非法请求时，服务端必须拒绝，且不得因此改变 Goal 或实际模型 Binding。
4. <a id="req-6-4"></a> 当目录或切换错误显示在页面时，错误信息不得包含凭据或未经筛选的 Provider 响应内容。
