# Web 与后端分离及终端产品退出需求

## 审批摘要

### 目标

将 Web UI 作为 LazyGoal 唯一的产品交互界面，使 Web 前端、后端服务和核心执行组件具有独立的工程边界，取消终端交互产品。用户已批准需求；两项预留边界已在后续设计问答中明确。

### 范围

- 包含：Web 与后端的代码、依赖和构建解耦；后端脱离 TUI 装配；终端页面、交互命令和 Benchmark `--tui` 模式退出；保留现有 Web 功能与当前版本数据；补齐中断执行的 Web 恢复入口；维持本地访问控制、单活动 Goal 和可靠关闭。
- 保留 Web 服务的薄启动入口，以及无界面的 Benchmark、评分、数据准备和 GEPA 机器命令；保留它们不代表继续维护终端产品。
- 不包含：多 Goal 并行执行、多用户服务、云端部署、新的模型配置编辑界面、Benchmark Web 控制台或历史开发数据迁移。
- 运行边界：前端代码、依赖和构建独立，生产环境由本地后端同源提供页面与 API；本次不要求分别部署，也不扩大本地服务的访问范围。

### 核心行为

- Web 仅通过明确的 API 与实时事件协议访问后端，不依赖后端实现、执行对象或本地文件系统；后端与无界面评测不加载终端界面。
- 普通产品入口提供 Web 服务，不再提供终端首页、Goal 会话、模型选择、Settings 或 Inspector。移除的终端命令明确拒绝，不静默切换到其他执行行为。
- 已有 Web 的 Goal 管理、会话执行、审批、模型选择与工作区偏好、权限、计划、轨迹和指标保持可用；当前版本 Goal 与工作区记录不因工程重组丢失或被重置。
- 服务重启后，用户可以在 Web 显式恢复中断的 Run；读取页面不自动执行，恢复沿用已提交边界和该 Goal 保存的模型，不因恢复重复创建 Goal、Run 或已确认副作用。
- 服务继续保护工作区与凭据，核验 Goal/Run 身份和授权，维持一个活动 Goal；连接断开不伪造终态，关闭时保留可恢复事实并释放资源。
- 现有无界面评测及 GEPA 流程保持可执行，终端专属模式不再可用。

### 风险与待确认

- 风险等级：high；理由：取消已存在的产品入口并调整跨组件依赖，影响启动、模型绑定、持久化通知、恢复、关闭和评测装配；必须覆盖授权、恢复及删除影响边界。
- 关键操作：实施阶段删除终端产品源码、专属依赖与交互评测分支；本需求不授权删除 LazyGoal Home 数据、工作区文件或评测产物。
- 风险：直接删除现有 TUI 包会使 Web 失去后端装配；遗漏恢复入口会使中断的 Run 停留在 Running；删除机器入口会破坏 GEPA 等进程调用；工程解耦不得将模型凭据或内部对象暴露到前端。
- 待确认：无。

## 引言

当前 Web 使用位于 TUI 模块的后端装配入口，前端还直接引用后端导出的表示类型；终端产品因此同时承担界面和服务依赖。此次需求收窄为独立的 Web 产品，并保持 LazyGoal 执行、授权和持久化能力。

## 需求

### 需求 1：Web 前端与后端工程独立

**用户故事：** 作为维护者，我希望 Web 前端只依赖公开通信契约，以便独立维护界面和后端实现。

#### 验收标准

1. <a id="req-1-1"></a> 当构建或检查 Web 前端依赖时，前端必须能够独立构建，且不得导入 TUI、Runtime、Agent、LLM、Storage、Tool、后端服务装配或服务端路由实现；共享契约不得通过依赖或导出间接引入这些实现。
2. <a id="req-1-2"></a> 当 Web 发起业务操作或订阅执行进展时，系统必须通过明确的 API 和实时事件协议通信，并在通信边界校验请求和响应；前端不得直接读写 Goal Snapshot、调用本地 Tool 或持有完整执行对象。
3. <a id="req-1-3"></a> 当构建或启动后端时，系统必须不依赖前端源代码、React、Ink 或终端 Controller；现有页面托管方式所需的静态产物可以作为输入，缺失时必须明确报告，不能影响无界面核心组件的使用。

### 需求 2：取消终端交互产品

**用户故事：** 作为维护者，我希望只维护 Web 产品界面，以便移除终端渲染、交互状态和重复适配的维护成本。

#### 验收标准

1. <a id="req-2-1"></a> 当从普通产品入口启动 LazyGoal 时，系统必须提供可访问的 Web 入口，且不得挂载 Ink、等待终端交互输入或创建仅服务于终端界面的状态与订阅。
2. <a id="req-2-2"></a> 当检查产品源码和依赖时，终端首页、Goal 输入与选择、Session、Settings、Inspector、终端模型选择、终端流式渲染及其专属依赖必须退出；仍被后端使用的执行、保存通知和关闭能力必须保留，并脱离终端实现。
3. <a id="req-2-3"></a> 当调用已取消的终端交互入口或 Benchmark `--tui` 模式时，系统必须明确报告该入口不可用，不得执行另一任务、自动恢复 Goal 或退回旧终端实现。

### 需求 3：现有 Web 功能与当前数据连续可用

**用户故事：** 作为使用者，我希望取消终端后继续使用已有 Web 功能和保存记录，以便工程重组不打断任务。

#### 验收标准

1. <a id="req-3-1"></a> 当通过 Web 管理 Goal 时，系统必须继续支持列表、详情、新建、归档与删除，以及普通消息、后续 Run、Plan Mode、结构化问答、任务批准或反馈和 Action 批准或拒绝。
2. <a id="req-3-2"></a> 当通过 Web 查看或调整当前能力时，模型目录、Goal 模型选择、工作区新 Goal 模型偏好、权限模式与授权撤销、GoalPlan、Activity、Trajectory、保存的模型输入和会话指标必须保持现有行为。
3. <a id="req-3-3"></a> 当工程重组后的服务读取当前版本数据时，系统必须继续使用原工作区身份和 LazyGoal Home 记录，保留 Goal/Run 身份、提交边界、模型选择、偏好及授权；不得要求用户清空记录，也不得把已保存状态改为新的默认值。
4. <a id="req-3-4"></a> 当保存记录损坏或不符合当前版本时，系统必须明确报告读取失败，不得把它解释为空工作区、静默重建记录或覆盖原文件；本需求不增加旧开发版本兼容承诺。

### 需求 4：通过 Web 显式恢复中断执行

**用户故事：** 作为使用者，我希望服务退出后能在 Web 恢复中断的 Goal，以便取消终端不会失去断点恢复能力。

#### 验收标准

1. <a id="req-4-1"></a> 当服务重启后发现当前版本可恢复的未终态 Run，且该 Run 不在当前服务中执行时，Web 必须提供明确的恢复操作；列表、会话读取和页面刷新不得自行推进执行。
2. <a id="req-4-2"></a> 当用户恢复中断的 Run 时，系统必须沿用同一 Goal/Run、已提交恢复边界及该 Goal 保存的模型；不得重新应用工作区默认模型或新增任务消息。模型无法恢复时必须报告原因并保留原记录。
3. <a id="req-4-3"></a> 当恢复涉及已提交工具结果、结果未知的副作用、待批准 Action、任务提案或模型纠错检查点时，系统必须遵守现有 Runtime 恢复与审批规则；不得重复执行已确认的副作用，不得替用户批准，也不得将恢复本身当作完成证据。
4. <a id="req-4-4"></a> 当恢复请求身份过期、同一 Run 已在执行或另一个 Goal 占用执行位置时，系统必须明确拒绝推进；并发或重复请求不得重复启动该 Run、创建新 Run 或绕过单活动 Goal 限制。

### 需求 5：保持后端执行与访问边界

**用户故事：** 作为使用者，我希望前后端解耦后仍由后端控制执行和授权，以便界面变化不会扩大工作区访问权限。

#### 验收标准

1. <a id="req-5-1"></a> 当 Web 调用后端时，系统必须继续限制本地服务访问并验证有效会话凭据与允许的来源；生产页面与 API 必须同源，工程分离不得默认启用公网监听、任意跨域或无鉴权接口。
2. <a id="req-5-2"></a> 当前端读取配置、会话、模型或执行数据时，后端必须仅提供对应接口允许的内容，不得暴露 Provider 凭据、完整配置或非授权的内部对象；精确工具输入和轨迹详情继续遵守现有访问限制。
3. <a id="req-5-3"></a> 当收到业务命令时，后端必须继续核验 Goal/Run、等待请求或 Action 身份以及工具授权，并由 Runtime 完成状态转换与提交；页面不得以本地状态代替持久化事实，仍只允许一个 Goal 活动执行。

### 需求 6：后端独立生命周期与可靠关闭

**用户故事：** 作为使用者，我希望浏览器连接和服务退出各自遵守清晰的生命周期，以便任务记录可靠恢复。

#### 验收标准

1. <a id="req-6-1"></a> 当关闭或刷新页面、断开实时连接时，已受理的任务必须继续由后端管理；重新连接后必须从已提交记录恢复展示，未提交活动不得被视为最终回复或完成状态。
2. <a id="req-6-2"></a> 当后端通过受支持的关闭方式退出时，系统必须停止受理新的推进，冻结检查点、中止执行并等待已进入的保存和受管资源清理；退出不得伪造新的 failed 或 cancelled 快照。
3. <a id="req-6-3"></a> 当后端启动失败、静态资源缺失或资源关闭失败时，系统必须提供可诊断的结果，按已有生命周期规则清理已创建资源，不得依赖终端 Controller 或浏览器仍然连接才能完成清理。

### 需求 7：保留无界面自动化入口

**用户故事：** 作为评测维护者，我希望机器调用与终端产品分开，以便移除 TUI 后仍能运行 Benchmark 和 GEPA。

#### 验收标准

1. <a id="req-7-1"></a> 当调用现有无界面 Benchmark 执行、评分、数据准备、Prompt Evaluation 和 GEPA 入口时，系统必须保持对应参数、机器输出和退出码语义，且不得加载终端渲染与交互模块。
2. <a id="req-7-2"></a> 当启动 Web 或导入核心执行组件时，系统不得因此启动评测、加载 Benchmark 专用运行环境或建立机器命令的额外服务。
3. <a id="req-7-3"></a> 当取消交互评测模式时，系统必须继续保留既有无界面评测的隔离、持久化、评分和资源释放规则；本次不要求将评测功能新增到 Web 页面。
