# 契约渐进迁移

本路线将自研 Contract AST 逐步替换为原生 TS 类型与按需生成制品。[数据契约参考](../data-contract-foundation/design.md)与[执行契约参考](../execution-contract-foundation/design.md)保存整体方向，不是两个待整体批准、整体实施的功能。此前针对这两份整体 Spec 的审阅请求由本路线替代。

开发者每次只需阅读当前小 Spec 及其明确引用的源码；六个维度用于设计者检查边界，不要求每个小 Spec 重复六层设计。下表是后续切片的选择路线，不是一次性执行计划，也不表示这些功能已经批准或实现。

## 当前交付单元

[第一步：在线模型列表响应改用 TS 类型](../ts-provider-models-contract/spec.md)。只替换 `BrowserProviderModels` 成功响应及模型条目，打通生成、运行时读取和真实浏览器消费，删除对应两个 AST 节点。其他 Provider 数据和 Runtime 保持原有路径。

## 后续切片路线

| 顺序 | 切片方向 | 每次独立交付的范围 | 前置条件与完成标志 |
| --- | --- | --- | --- |
| 1 | 单个 Web 响应试点 | 当前在线模型列表成功响应。 | 同一次交付包含原生 TS、生成校验/Schema、未知字段提取和真实消费者；对应 AST 删除。 |
| 2 | 其他 Web 边界 | 每次选择一个端点的输入或响应契约族，例如模型查询输入、Provider 设置读取。 | 复用第 1 步生成链；只增加当前契约需要的可选、空值、字典或联合能力，不一次迁移整个包。 |
| 3 | 独立模型载荷 | 先选择完成审查等结构较小的载荷，每次覆盖其声明、解码与真实调用方。 | 复用生成链；补齐该载荷实际需要的判别联合和 Provider 投影验证，不连带重写所有决策。 |
| 4 | 工具与模型声明的接缝 | 将工具输入的消费边界改为类型化读取器与标准 Schema，解除模型声明对工具 AST 的直接遍历。 | 本步先写小 Spec 明确新旧工具如何在不同注册项中共存，并用真实工具证明接缝；不能要求先迁移全部工具。 |
| 5 | 单个工具输入 | 每次替换一个工具或紧密共享同一输入结构的工具族。 | 依赖第 4 步；输入 TS、准备、模型可见 Schema、必要 RPC 制品一起切换，删除对应 AST，不调整授权语义。 |
| 6 | 模型决策与 wire 投影 | 按可独立闭合的决策分支组替换，而非一次迁移全部 canonical 定义。 | 使用第 3/4 步接缝，逐步退出请求级 AST 拼装与 wire AST 遍历，保留阶段绑定和证据检查。 |
| 7 | 持久化及其余解析边界 | 每次选择一个文件 DTO/Codec 或配置边界及其真实读写方。 | 涉及模型或工具载荷的 DTO 等其类型稳定后再迁移；验证当前数据往返与对应恢复行为，不做历史迁移。 |
| 8 | 删除自研引擎 | 清理无消费者的 AST、Parser、编译器、推导类型和导出。 | 以生产引用扫描证明没有剩余消费者；保留有实际消费者的 JSON 原语，完成全仓集成验证。 |

第 2、3 步在试点后可按实际依赖选择下一项，不要求迁完所有 Web DTO 才处理模型载荷；第 5 步也不要求全部工具完成后才能开始独立的持久化边界。只在前一步交付证据清楚后展开下一份具体 Spec，不提前生成一批依赖未定的 Spec 或 Plan。

## 每个小 Spec 的边界

- **有实际替换成果。** 指定一个契约族、真实消费者和本步删除的 AST；不把“搭好通用基础设施”单独当成首个大项目。
- **只有一个维护源。** 已迁移契约由原生 TS 定义，不同时保留同一结构的 AST；生成物不得手改。
- **允许按契约分批共存。** 未迁移契约继续使用 AST，已迁移契约使用生成链；不添加旧 wire 兼容层、不在新解析失败后回退、不把 TS 重新编译为旧 AST。必要接缝需在对应小 Spec 写明消费者与删除条件。
- **按需扩大能力。** 第一片只处理固定对象和数组；后续首次遇到联合、递归、字典等结构时，在当步验证所需能力。不得把首片的有限实现宣称为通用解析方案。
- **执行语义保持。** 每步只改完成数据替换所需的执行接缝；超时、重试、审批、授权、状态、恢复和关闭不附带重设计。
- **独立验收。** 小 Spec 自身写清数据行为、失败规则、非目标、删除范围及真实集成验证；不以“满足整体参考的全部要求”作为开发前提。

每个交付单元分别经历 Spec 审阅、Plan 和实施；本轮只编写第一步 Spec，不创建 Plan、不修改生产代码。
