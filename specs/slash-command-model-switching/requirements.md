# Slash Command 与模型切换需求

## 审批摘要

### 目标

为 LazyGoal 提供可供 TUI 与未来 Web View 复用的 Slash Command 基础设施，并交付 `/model` 命令，使用户能在当前 Provider 内发现、选择、切换并随 Goal 恢复模型。

### 范围

- 包含：独立 Slash Command Package、TUI 命令提示与派发、当前 Provider 模型发现、交互式选择、完整 Model Binding 切换以及 Goal Snapshot 恢复。
- 不包含：Web View 实现、跨 Provider 切换、新凭据录入、`.env` 写回、模型调用中的强制切换、其它业务命令、OAuth 或旧开发期 Snapshot 迁移。

### 核心行为

- `/` 输入显示和过滤可用命令；未知或非法命令被拒绝，`//` 可提交字面量 `/`，普通输入保持原有行为。
- `/model` 优先展示当前凭据在线列出的兼容模型；可恢复故障降级到明确标注的离线目录，鉴权、权限或协议故障不得伪装成降级成功。
- 模型选择界面支持加载、方向键、Enter 和 ESC；切换只在安全等待点发生，成功后后续 Preparation 与 executing 调用统一使用新模型及其预算。
- 模型选择的非敏感恢复参数进入 Goal Snapshot；恢复失败时阻止推进并要求重新选择，不静默使用环境默认模型。

### 风险与待确认

- 风险等级：medium；理由：新增公共 Package，并改变 TUI、LLM、Runtime、Storage 间的模型所有权、Snapshot Schema 与恢复路径。
- 关键操作：无。
- 风险：在线目录元数据不完整可能导致不可安全选择；Binding 与 Snapshot 若更新顺序错误可能造成显示模型和实际模型不一致；Provider 错误分类不当可能掩盖凭据问题。
- 待确认：无。

## 引言

本功能以 UI 无关的 Slash Command 契约统一不同交互入口，并以 `/model` 建立当前 Provider 内的模型发现和可恢复切换闭环；命令交互不进入 Goal 对话，凭据不进入持久化状态。

## 需求

### 需求 1：可跨界面复用的 Slash Command 契约

**用户故事：** 作为 LazyGoal 界面开发者，我希望通过独立 Package 注册、解析和派发 Slash Command，以便 TUI 与未来 Web View 使用相同命令语义而不耦合具体 UI。

#### 验收标准

1. <a id="req-1-1"></a> 当调用方注册一个合法命令时，Slash Command Package 必须能按稳定名称查询其描述、用法和派发结果。
2. <a id="req-1-2"></a> 当 TUI 使用 Slash Command Package 时，该 Package 必须不依赖 React、Ink、TUI Controller、Provider SDK 或持久化实现。
3. <a id="req-1-3"></a> 当未来调用方使用同一 Package 时，命令解析和候选结果必须通过 UI 无关的公开 TypeScript 契约提供。

### 需求 2：命令输入与普通文本兼容

**用户故事：** 作为 TUI 使用者，我希望在现有输入框中发现并执行命令，同时仍能提交普通文本和绝对路径，以便命令能力不破坏原有会话输入。

#### 验收标准

1. <a id="req-2-1"></a> 当可输入面板中的首个非空白字符为 `/` 时，系统必须展示已注册命令，并随命令名前缀变化过滤候选。
2. <a id="req-2-2"></a> 当使用者提交已注册且参数合法的 Slash Command 时，系统必须派发该命令，并且不得把命令文本追加到 Goal Conversation。
3. <a id="req-2-3"></a> 当使用者提交未知命令或非法参数时，系统必须显示明确拒绝信息，不得把该文本发送给 Agent。
4. <a id="req-2-4"></a> 当使用者提交首个非空白字符为 `//` 的文本时，系统必须移除其中一个 `/` 并按普通文本提交剩余内容。
5. <a id="req-2-5"></a> 当输入不属于 Slash Command 或转义文本时，Intent、question、planning feedback 与 blocked 输入必须保持原有校验、消息和推进语义。

### 需求 3：当前 Provider 模型发现

**用户故事：** 作为 TUI 使用者，我希望看到当前 Provider 对当前凭据开放且与 LazyGoal 生成链路兼容的模型，以便在不更换 Provider 或凭据的情况下选择模型。

#### 验收标准

1. <a id="req-3-1"></a> 当 `/model` 获取模型时，系统必须只查询当前配置的 Provider，并优先使用该 Provider 在线返回的完整分页结果。
2. <a id="req-3-2"></a> 当在线结果包含当前文本生成链路不支持的模型时，系统必须将其排除或明确标记为不可选择，不得允许产生已知不兼容的 Model Binding。
3. <a id="req-3-3"></a> 当在线模型缺少展示名、上下文容量、输出上限、推理或视觉能力时，系统必须按模型 ID 使用内置 pi-ai Catalog 补全，并区分在线可用性来源与元数据来源。
4. <a id="req-3-4"></a> 当网络、超时、Provider 暂时不可用或端点不支持模型列表时，系统必须降级到内置目录并标注“访问权限未验证”；`openai-compatible` 只能回退到当前配置模型及其显式能力。
5. <a id="req-3-5"></a> 当在线请求发生鉴权失败、权限拒绝或响应协议非法时，系统必须显示对应错误并禁止切换，不得将其表示为成功的目录降级。

### 需求 4：模型选择交互

**用户故事：** 作为 TUI 使用者，我希望通过键盘查看和选择模型，以便在不中断当前输入流程的情况下完成切换或取消。

#### 验收标准

1. <a id="req-4-1"></a> 当 `/model` 被派发时，系统必须立即显示可取消的加载状态，并在结果到达后展示模型 ID、展示名、上下文容量、来源和当前生效标记。
2. <a id="req-4-2"></a> 当列表可用时，方向键必须移动选择项，Enter 必须确认可选择项，且不可选择项必须展示原因并拒绝确认。
3. <a id="req-4-3"></a> 当使用者在加载或选择阶段按 ESC 时，系统必须取消未完成的目录请求、保持当前模型不变并返回原输入位置。
4. <a id="req-4-4"></a> 当选择成功、失败或被取消时，原 Goal 等待点、未提交用户消息和 Action 审批状态必须保持不变，并显示对应的英文结果提示。

### 需求 5：一致且原子的模型切换

**用户故事：** 作为 TUI 使用者，我希望模型切换完整生效或完全不生效，以便界面显示、Provider 请求和上下文预算始终一致。

#### 验收标准

1. <a id="req-5-1"></a> 当使用者确认模型时，系统必须在当前 Provider 和结构化输出模式内校验并构造完整 Model Binding，包括 Adapter、模型能力、输出上限、输入估算器与上下文预算。
2. <a id="req-5-2"></a> 当目标 Binding 构造、Goal 状态提交或 Snapshot 保存任一步骤失败时，系统必须保留旧 Binding 和旧模型选择，并显示失败原因。
3. <a id="req-5-3"></a> 当切换成功时，Preparation 与 executing 阶段的下一次模型请求必须使用同一新 Binding，且不得在单次进行中的模型调用中途换模。
4. <a id="req-5-4"></a> 当当前界面不是 Intent 或等待用户文本输入的安全等待点时，系统必须拒绝打开或确认模型切换。

### 需求 6：Goal 级模型恢复

**用户故事：** 作为恢复长期 Goal 的使用者，我希望系统继续使用该 Goal 已确认的模型，以便恢复前后的执行可追溯且不会静默改变模型行为。

#### 验收标准

1. <a id="req-6-1"></a> 当新 Goal 被创建时，系统必须把当时生效的非敏感模型选择和恢复所需能力参数保存到当前 Goal Snapshot。
2. <a id="req-6-2"></a> 当活动 Goal 成功切换模型时，系统必须在继续推进前保存新的模型选择；该状态不得包含 API Key、认证头或其它凭据。
3. <a id="req-6-3"></a> 当进程恢复 Goal 时，系统必须使用 Snapshot 模型选择和当前进程凭据重建 Binding，不得自动改用环境变量中的不同模型。
4. <a id="req-6-4"></a> 当 Snapshot Provider 与当前配置不一致，或模型不可用、能力不足、模式不兼容时，系统必须阻止 Goal 推进并要求使用者重新选择兼容模型。

### 需求 7：验证与现有行为保护

**用户故事：** 作为 LazyGoal 维护者，我希望命令、目录、切换和恢复边界具有自动化证据，以便跨组件变更不会削弱现有输入、执行或敏感信息保护。

#### 验收标准

1. <a id="req-7-1"></a> 自动化测试必须覆盖 Slash Command 解析、候选、未知命令、`//` 转义、普通输入透传以及独立 Package 的依赖边界。
2. <a id="req-7-2"></a> 自动化测试必须覆盖各 Provider 在线映射、分页、目录补全、去重、兼容性过滤、取消和全部错误分类，且不得执行真实付费模型请求。
3. <a id="req-7-3"></a> 自动化测试必须覆盖 ModelSelector 键盘交互、切换失败回滚、Preparation/Step 后续调用、Snapshot 重启恢复和凭据不进入 Snapshot、Trajectory、Trace 或 UI 错误。
