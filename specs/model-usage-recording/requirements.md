# 模型用量记录 需求

## 审批摘要

### 目标

记录每次模型调用的实际 token 用量并在评测报告按任务聚合,使成功率可与实际用量对照;缺失用量如实记为缺失,不伪装为 0。

### 范围

- 包含:两个 Adapter 提取 usage 归一化进 `providerMetadata`;usage 随既有 Diagnostic Trace 通道落盘;执行路径累计单任务用量并透传;ALFWorld 报告新增按任务聚合用量字段(含缺失计数)。
- 不包含:跨阶段预算、调用次数限制、预算耗尽恢复点;usage 进 Domain Event/Goal Snapshot/模型上下文;供应商重试用量归因;TUI 展示。

### 核心行为

- 供应商响应携带用量时,`providerMetadata` 含归一化的输入/输出(及可用缓存)token 数;不携带时相关字段缺省。
- 缺失用量的聚合语义为显式缺失计数,不产生 0 值、不参与求和。
- 评测报告每个任务含聚合 token 用量(或缺失计数),与成功率、步数、时长并列。
- trace 记录失败不影响执行结果,usage 不进入 Domain Event、Snapshot 或模型上下文。

### 风险与待确认

- 风险等级:medium;理由:跨 llm/agent/benchmark 三层新增数据流与报告字段,但不触碰 Runtime 状态与恢复语义,变更可逆。
- 关键操作:无。
- 风险:供应商字段形态差异(兼容端点、Gemini)导致部分调用只有缺失计数;本地 CLIProxyAPI 环境已实测转发 usage(2026-09-07),实施期需一条真实调用复核。
- 待确认:无。

## 引言

当前 `LLMResponse.providerMetadata` 通道已存在且 Diagnostic Trace 已落盘,但 OpenAI-compatible Adapter 丢弃了响应中的 `usage`,Gemini 未映射,评测报告没有用量字段。本 Spec 定义用量从提取、落盘到报告聚合的完整数据流,并确立缺失用量的诚实语义。

## 需求

### 需求 1:Adapter 提取归一化用量

**用户故事:** 作为分析模型成本的使用者,我希望每次调用的响应用量被自动提取并记录,以便无需手工查询供应商账单。

#### 验收标准

1. <a id="req-1-1"></a> 当 OpenAI 兼容响应携带 `usage` 时,系统必须在 `providerMetadata` 中记录归一化的输入 token 数、输出 token 数,以及响应可用时的缓存相关 token 数。
2. <a id="req-1-2"></a> 当响应不携带 `usage`(或 Gemini 响应无用量字段)时,系统必须使相关字段缺省,不得以 0 或估算值代替。
3. <a id="req-1-3"></a> 当调用失败或中止时,系统不得为该次调用记录任何用量(失败的调用没有完成的响应)。

### 需求 2:用量随 Diagnostic Trace 落盘

**用户故事:** 作为审计单次模型调用的开发者,我希望每次调用的用量出现在该调用的 trace 记录中,以便逐调用核对成本。

#### 验收标准

1. <a id="req-2-1"></a> 当一次模型调用完成时,该调用的 Diagnostic Trace 记录必须包含提取后的用量字段(存在时)或不含用量字段(缺失时),trace 结构本身不变。
2. <a id="req-2-2"></a> 当 trace 写入失败或 trace 未启用时,系统的执行结果必须与用量记录功能存在前完全一致。

### 需求 3:评测报告按任务聚合用量

**用户故事:** 作为比较各任务成功率与成本的评测者,我希望报告每个任务包含聚合 token 用量,以便识别高成本任务。

#### 验收标准

1. <a id="req-3-1"></a> 当一个任务完成一次尝试后,报告必须为该尝试记录聚合的输入 token 数、输出 token 数与用量缺失的调用次数。
2. <a id="req-3-2"></a> 当聚合范围存在缺失用量的调用时,报告必须保留显式缺失计数,缺失调用不向 token 总数贡献任何值(包括 0)。
3. <a id="req-3-3"></a> 当基础设施重试产生新尝试时,每个尝试独立聚合自己的用量;报告聚合(如有)按尝试分开,不跨尝试混合。
