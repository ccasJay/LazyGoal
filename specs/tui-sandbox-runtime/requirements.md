# TUI 沙箱透明代理运行时需求

## 审批摘要

### 目标

开发者能在 TUI 中运行单个 Benchmark 任务，实时查看执行进展，并选择自动执行或逐次审批沙箱动作。

### 范围

- 包含：GAIA、SWE-bench 的单任务 TUI 入口、沙箱工具代理、`auto` / `review` 策略、实时状态、独立持久化、产物回收和退出清理。
- 不包含：修改未启用 TUI 的批量评测行为、多任务 TUI、通用第三方工具发现、销毁容器后的跨进程续跑、自动触发 SWE-bench 官方评分。

### 核心行为

- `eval <benchmark> --tui --task <id> --output-dir <path> [--mode auto|review]` 启动一个会话；省略模式时使用 `review`，任务和配置无效时在创建容器前失败。
- 宿主会话控制唯一的 Goal 执行流；沙箱文件和命令工具在容器内执行，联网工具仅使用明确配置的宿主后端。`auto` 自动批准预定义任务和授权工具；`review` 只自动放行明确列出的只读工具，其余动作逐次批准或拒绝。Agent 请求补充输入时，`review` 可等待，`auto` 以未完成结果结束。
- 输出目录保存本次快照、轨迹、诊断及领域产物；Profile 和容器工作目录独立配置，正常开发 Goal 列表不受影响。保存的检查点供审计，本期不提供沙箱跨进程恢复入口。
- TUI 在任务完成前显示已提交的执行进展。正常完成、启动失败和 Ctrl-C 都进入有界清理；超时可牺牲未完成的产物回收以删除容器，清理失败必须明确报告。
- 执行及必要清理成功返回 0，运行或清理失败返回 1，参数错误返回 2，Ctrl-C 返回 130；GAIA 的错误答案独立显示为评分结果，不改变执行成功退出码；SWE-bench 官方评分保持独立。

### 风险与待确认

- 风险等级：high；涉及远程工具授权、容器销毁及中断后的产物完整性。
- 关键操作：创建并删除本次隔离容器。
- 已知风险：强制清理可能留下不完整的领域产物；Docker 不可用时不能承诺容器已删除，必须保留可定位诊断。远程调用中断后不自动重放可能已执行的动作。
- 待确认：无独立待决选项；本修订稿及新增边界待整体审批，尚未验证实现。

## 引言

本功能把单个 Benchmark 任务接入现有 TUI 的 Goal 会话与审批体验，同时保留沙箱执行边界。

## 需求详情

### 1. 隔离沙箱生命周期托管

**用户故事：** 作为开发者，我希望启动、完成或中断测试时都由同一运行入口管理沙箱，以便避免遗留容器和丢失清理诊断。

1. <a id="req-1-1"></a> 当启动 TUI Benchmark 任务时，系统必须建立本次独立沙箱，并在环境预检和工具握手成功后才开始模型与工具执行。
2. <a id="req-1-2"></a> 当 Goal 到达正常终态时，系统必须停止工具服务，收集领域产物，再销毁本次容器，完成上述流程后才退出 TUI。
3. <a id="req-1-3"></a> 当用户通过 raw-mode Ctrl-C 或 SIGINT 中断时，系统必须拒绝后续操作、中止在途执行、保留最后成功提交的检查点，并进入同一幂等清理流程；不得把中断伪造为新的 Goal 失败或取消事实。
4. <a id="req-1-4"></a> 如果镜像准备、Worker 启动、握手或 TUI 初始化失败，系统必须清理已经取得的资源，并同时报告原始失败与清理失败。
5. <a id="req-1-5"></a> 如果正常清理超过限定宽限期，系统必须停止继续回收产物并有界地强制终止 Worker、删除本次容器；删除失败或产物不完整时必须明确报告，不能宣告清理成功。

### 2. 持久化与工作区隔离

**用户故事：** 作为用户，我希望临时评测的状态和产物集中保存，以便查看结果且不影响正常开发记录。

1. <a id="req-2-1"></a> 当指定 `--output-dir` 时，系统必须在该目录内为本次任务和尝试建立独立持久化目录。
2. <a id="req-2-2"></a> 当保存或查询本次会话时，Goal 快照、Trajectory、Diagnostic Trace、检索 Sidecar 和 Attempt 记录必须使用本次输出目录；原开发工作区的 Goal 文件和 Catalog 查询结果不得改变。
3. <a id="req-2-3"></a> 当输出目录为空时，系统必须仍能使用 Benchmark 的显式 Profile 和工具配置启动；修改输出目录不得改变容器中的工具工作目录，也不得要求复制日常默认 Profile。
4. <a id="req-2-4"></a> 当回收答案或补丁时，系统必须将领域产物与本次唯一的 Goal/Run 记录关联；不得用容器文件覆盖宿主已提交的 Runtime 状态，也不得额外创建独立的 `catalog.json`。
5. <a id="req-2-5"></a> 当用户请求恢复已结束进程的沙箱会话时，本期 TUI Benchmark 入口必须明确拒绝续跑；保留的快照和轨迹只能作为审计材料，不能在新容器或宿主工具上自动重放。

### 3. 沙箱工具代理与双模策略

**用户故事：** 作为开发者，我希望相同的任务可以自动执行或接受人工审批，以便控制容器操作的时机。

1. <a id="req-3-1"></a> 当沙箱工具准备就绪时，宿主模型必须看到本次 Benchmark 显式声明的工具定义，并将对应调用交给本次 Worker；不得混入宿主文件或 Shell 工具。联网工具仅能使用该 Benchmark 显式配置的后端。
2. <a id="req-3-2"></a> 在 `auto` 模式下，系统必须自动放行当前 Profile 授权且已注册的工具；仍须执行输入校验和权限校验，且不得自动重试执行结果未知的远程调用。
3. <a id="req-3-3"></a> 在 `review` 模式下，只有本次适配器明确列出的只读工具可以自动执行；`bash`、写文件、编辑文件、提交答案及未列入只读名单的工具，必须在调用发往 Worker 前等待用户对当前 Action 的明确批准。
4. <a id="req-3-4"></a> 当用户拒绝 Action 时，系统必须保证该动作没有发往 Worker，将拒绝原因作为 Observation 交还 Agent；批准只授权该次 Action，不得自动批准后续同名工具调用。
5. <a id="req-3-5"></a> 如果工具定义不匹配、协议数据非法、调用超时或连接断开，系统必须拒绝继续远程执行并显示错误，保留可审计状态；不得降级为宿主执行或自动重发可能已执行的调用。

### 4. 单任务启动与结束

**用户故事：** 作为开发者，我希望使用已有 Benchmark 命令启动一个完整的交互会话，以便无需手工创建 Goal 或填写评测任务。

1. <a id="req-4-1"></a> 当使用 `--tui` 时，入口必须要求明确的 `--task` 和 `--output-dir`，解析一个匹配任务，接受 `auto` / `review` 且默认 `review`；无效模式、缺失参数、任务不唯一或不支持的恢复参数必须在容器创建前失败。
2. <a id="req-4-2"></a> 当任务有效时，系统必须传入该任务的 intent、objective、completionCriteria、Profile、模型配置和步数限制，自动完成确定性 Preparation 并批准该预定义任务；两种模式均不得停留在 intent 或 Planning 确认页面。若执行中 Agent 请求用户输入，`review` 可等待输入，`auto` 必须记录未完成结果并结束。
3. <a id="req-4-3"></a> 当本次流程结束时，参数错误必须返回 2，SIGINT/Ctrl-C 必须返回 130，其余运行、未完成或清理失败必须返回 1；执行与必要清理成功返回 0。GAIA 的 correct=false 不改变执行成功退出码，但必须展示真实评分，不能被模型完成状态掩盖。
4. <a id="req-4-4"></a> 当未传入 `--tui` 时，现有 Headless 命令、批量评测、参数和报告语义必须保持原行为；普通 TUI 启动不得加载 Benchmark 适配器。

### 5. 实时观测与结果展示

**用户故事：** 作为开发者，我希望在任务仍在执行时看到真实进展，以便判断当前动作、审批等待和最终结果。

1. <a id="req-5-1"></a> 当开始运行任务时，TUI 必须显示初始化状态，并在 Goal 建立后自动进入 SessionScreen；用户无需另建会话。
2. <a id="req-5-2"></a> 当 Runtime 成功提交执行状态时，TUI 必须在整个任务结束前更新对应的 Step 数、Action 和 Observation；未提交的轨迹尾部不得显示为已经完成的动作。
3. <a id="req-5-3"></a> 当运行、审批或清理状态变化时，TUI 必须显示当前模式、任务身份和状态；只有真实的审批等待点允许批准或拒绝，执行进行中不能因界面刷新而重复提交。
4. <a id="req-5-4"></a> 当清理结束时，TUI 必须显示执行状态、产物路径和清理错误。GAIA 使用已有答案评分；SWE-bench 显示补丁导出结果及尚未进行官方评分的状态，不以 Goal completed 表示 resolved。
