# Runtime 会话输出与局部资源生命周期

## 目标与范围

落实 RC07–RC10：同一 Goal 订阅持续观察后继 Run，慢消费者的待交付输出有界，交互恢复和输入清理的异步错误得到处理。用确定性时序验证 RC11，并修复证实的竞态。
范围限于内部 Session 输出、输入消费和宿主处理器连接，沿用 [Session 执行所有权](../runtime-create-answer-execution-ownership/spec.md) 及 Supervisor 默认 Browser feed 的现有契约。

## 用户故事

- **S1** 作为会话输出消费者，我希望持续观察同一 Goal 的后继 Run，以便正确区分当前进度与迟到的旧片段。
- **S2** 作为 Runtime 宿主，我希望慢订阅有明确的缓冲和关闭结果，以便隔离资源占用并恢复可信状态。
- **S3** 作为接入输入源或自动处理器的宿主，我希望解除和关闭后不启动新的工作，以便可预测地管理宿主资源。

## 验收标准

| ID | 故事 | 类型 | 当 | 系统应 | 验证 |
|---|---|---|---|---|---|
| R1.1 | S1 | 事件 | 同一订阅从 Run A 切换到后继 Run B，B 的首个活动先于定时核对 | 在原订阅上交付 B 的开始和当前临时片段，保留真实 Run 与执行单元身份。B 的身份经当前状态或已提交切换事实确认。确认切换后过滤迟到的 A 临时片段，并继续交付应见的 A 正式事实和控制结果。 | 通过真实 Session FIFO 后继执行，保持单一订阅并暂停定时核对。交错 A 终态、B 开始和首片段、迟到 A 增量及 A 控制事件，核对顺序和来源身份。 |
| R1.2 | S1 | 状态 | 初始快照读取与事件发布并发，或后续同步读取乱序完成 | 首个成功同步建立 Goal 基线，已由基线覆盖的通知按既有身份去重。同步修订单调接纳，旧快照不能切回前一 Run 或撤回已显示的状态。末次通知丢失仍可通过只读核对恢复，读失败沿用同步故障语义。 | 挂起初始读取与两次并发核对，交错跨 Run 提交、旧读晚到、读取失败与通知丢失。检查同步序列、正式消息和等待通知。 |
| R2.1 | S2 | 状态 | 调用方从未消费或持续慢消费，Core 与 Session 之间仍可交付，且同步可派生正式消息和交互通知 | 从 Core 到调用方的待交付事件有明确固定上限，包含 Session 侧同步及派生事件。公开临时文本沿用现有有界投影；如果合并积压增量，合并结果也受上限约束，且只合并同 Run、同来源的相邻兼容片段。 | 使用小容量、受控消费者和分批生产，每批让后台泵有机会排空 Core。分别施加控制事件、同块高频增量和派生通知，断言最终队列峰值及合并上限。 |
| R2.2 | S2 | 异常 | 缓冲不足以保留控制事件，或临时增量出现缺口 | 无法保留控制事件时，仅结束该订阅，调用方可观察一次 `closed/backpressure` 后结束迭代，并可新建订阅重新同步。若订阅仍开放但临时内容不完整，显式报告缺口并重新同步。另一订阅和已受理执行继续，正式消息与收据按既有只读入口核对。 | 分别触发 Core 与最终消费者边界溢出，检查停止后晚开始迭代、关闭原因、快订阅与 Runner 进度、重连快照及原 inputId 查询。对保留开放的缺口路径核对同步。 |
| R2.3 | S2 | 事件 | 调用方结束迭代、解除句柄、Runtime 关闭或背压结束订阅 | 释放该订阅的积压、监听和核对注册，保留可观察的终止结果。挂起读取晚到不再派生输出，其他观察者持有的核对和会话不受该订阅单独退出影响。 | 挂起同步读取，在关闭前后推进修订，核对终止原因、关闭幂等性、监听及定时器释放与另一订阅连续性。 |
| R3.1 | S3 | 事件 | 匹配当前 Run 与修订的显式 `resume` 发现仍待交互，无处理器、处理器有效或刚解除 | 沿用 `INTERACTION_REQUIRED`。有且仅有当前有效连接才可解锁并尝试投递该等待。没有处理器时保持等待，由宿主显式回答。派发错误由既有诊断边界观察，进程无未处理拒绝。 | 以 Node 未处理拒绝严格模式执行三种 Session 路径，并覆盖过期修订、busy 和正常处理器，核对返回值、调用次数和收据。 |
| R3.2 | S3 | 事件 | detach 或 close 停止输入消费，或输入受理失败需要清理来源 | Runtime 至多请求一次 `iterator.return()`，观察同步抛错和异步拒绝，并通过现有宿主诊断入口标识 Goal、清理阶段及原因。消费和关闭不等待来源结束，受理失败继续作为主错误。停止后迟到的 `next()` 不受理，既有收据和已开始的受理遵循原结算语义。 | 严格拒绝模式下覆盖阻塞 next、迟到 resolve／reject、return 抛错／异步拒绝／永久挂起，以及受理失败与清理失败同时发生。核对诊断次数、原错误、消费与关闭结果及持久收据。 |
| R3.3 | S3 | 状态 | 连接初始基线读取在途时收到修订通知或合法显式恢复 | 建立一致基线前不启动宿主函数；随后重新核对当前等待。基线中的历史等待只在合法显式解锁后投递。初始化期间合法解锁不丢失，较新的可投递请求按稳定身份至多启动一次。初始读取失败不得把基线当成空历史。 | RC11 补证一。挂起初始读取，令通知先返回，分别验证历史等待、初始化期间显式解锁、基线读取失败与基线后的新等待。先在当前实现记录函数调用和收据，再据此定位修复。 |
| R3.4 | S3 | 异常 | 派发读取或宿主函数在途，原连接解除、被替换或 Runtime 开始关闭 | 读取完成后只有同一当前有效连接可启动宿主函数。已启动的调用收到中止信号；不合作的函数不阻塞关闭。迟到结果不能提交新决定或影响替代连接，已受理的决定继续按原结果结算。 | RC11 补证二。先挂起派发读取再解除、重新连接或关闭，断言旧函数是否启动；另在函数和返回后的核对在途时解除，核对中止信号、迟到拒绝及收据，保留先受理后解除对照。 |

组合：使用真实 Session、事件 Core、受控模型及可暂停的 Store，串联后继 Run、缺口重连和关闭。交互竞态测试使用显式闸门及严格未处理拒绝模式。运行 `npm test` 和 `npm run check:docs`。

## 决策

| 决策 | 理由 | 放弃 |
|---|---|---|
| [GoalSessionStream](../../packages/runtime/src/session-stream.ts) 持有每个订阅的当前观察身份，使用 Snapshot 提交修订和已提交的 Run 切换事实。初始交接与持续观察使用同一个单调接纳边界。 | Goal 订阅跨 Run，实时 cursor 仅标识发布位置。 | 无 |
| 由最终交付边界承担有限缓冲；优先复用 [事件 Core](../../packages/execution-stream/src/publisher.ts) 的有界队列、相邻增量处理和关闭原因。若保留 Session 投影缓冲，其容量与终止信号须纳入可验证总上限。 | 初始同步、派生事件和实时事件最终都经过同一消费者，快泵不能绕过背压。 | 无 |
| [SessionManager](../../packages/runtime/src/session-manager.ts) 观察源迭代器清理结果，通过已有后台诊断通道报告，宿主仍拥有来源资源。 | 消费结算可先完成，迟到清理故障仍有明确归属。 | 无 |
| RC11 先用现有连接与派发入口补证。证实竞态时在原 attachment 上表达基线未就绪、可派发和已解除，异步结果使用前复核连接身份和当前等待，宿主函数留在 mutation Gate 外。两条时序分别记录结果，行为已满足的路径保留回归即可。 | 已有迟到结果校验，需独立验证是否提前投递或解除后启动函数。 | 无 |

## 风险与否定性保证

| 等级 | 理由 | 关键操作 |
|---|---|---|
| high | 自动交互派发可能触发批准及后续工具；订阅故障可能让宿主遗漏控制结果。 | 用临时存储、隔离工具和受控宿主函数验收。 |

连接与订阅状态留在内存。事件反馈沿用当前 DTO，重连按 Snapshot 和收据查询恢复。宿主关闭或 detach 不生成用户 Interrupt。
