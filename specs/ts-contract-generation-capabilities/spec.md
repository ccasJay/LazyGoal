# TS 契约生成能力 Spec

## 目标与范围

扩展已交付的 Catalog、生成器和共享绑定，使其能表达并验证本次迁移实际需要的 TS 契约；不迁移具体业务消费者。

## 需求与验收标准

- <a id="spec-req-1-1"></a>**1.1 覆盖实际结构**：依据 Catalog 与消费方核对所需的可选、联合、判别联合、递归、开放 JSON、数组元素、数值与字符串约束；对支持项从 TS/JSDoc 生成 Schema、校验器和绑定，未支持项明确失败，不手写第二份字段表。
- <a id="spec-req-1-2"></a>**1.2 读取策略**：生成绑定支持 `strip` 与 `reject`；联合先确定合法分支再处理额外字段，无法唯一确定分支或已知字段无效时失败，不因清理而误选分支。深复制、非 JSON 拒绝、有界安全诊断保持。
- <a id="spec-req-1-3"></a>**1.3 模型投影**：以同源本地约束派生 Provider 可用 Schema 和配套解码；可选与 `null`、联合和模型可移植限制均有确定映射。Provider 无法表达的本地约束不得悄然删除：只有明确标识并在解码时强制验证，才能使用较宽的 wire 表达；无法安全转换则失败。
- <a id="spec-req-1-4"></a>**1.4 生成一致性**：登记、生成和 `--check` 对所有启用项确定且可复现；未知注解、无法表达的类型、缺失或漂移制品失败。临时源修改字段或约束时，制品和读取行为同步变化。
- <a id="spec-req-1-5"></a>**1.5 验证**：用来自工具、模型、Web、Storage 的代表性隔离样例覆盖上述能力及失败路径；已有生成制品、模型投影和完整回归通过。样例不视为生产迁移。

## 架构与核心决策

本 Spec 唯一负责共享生成器、`contract-binding` 和通用投影能力；各领域拥有自身类型、绑定登记和消费接缝。领域可按已定义输入输出接口并行实现，以替身验证准备工作；最终集成须使用本 Spec 已验证的实际提交。AgentProfile 和两个 Provider 既有 Spec 已获批准，其字段、边界行为与各自验收不被覆盖；如共享能力调整使其目标受影响，先修订相应 Spec。

## 风险与否定性保证

风险等级：高。关键风险是联合清理误选分支、Provider 投影放宽约束及递归处理失控。本步不承载授权、执行和持久化规则，不切换生产消费者。
