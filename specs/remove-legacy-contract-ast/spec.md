# 删除旧 Contract AST Spec

## 目标与范围

在所有真实消费者迁移完成后，删除自研 Contract DSL、AST、推导、Parser 和 AST Schema 编译器及其专属制品；保留仍被使用的非 AST 能力。

## 需求与验收标准

- <a id="spec-req-1-1"></a>**1.1 前置证据**：工具、模型、Web、Storage 和其他边界均已完成真实集成及验收；Catalog 和源码、测试、脚本、评测及装配入口核对不再依赖待删除 AST。任一必要消费者未迁移时停止删除并报告。
- <a id="spec-req-1-2"></a>**1.2 删除专属实现**：移除 AST 构造、节点、推导、解析、编译与仅为它们存在的测试、依赖、生成或文档；不以兼容包装、双实现或失败回退保留旧契约体系。
- <a id="spec-req-1-3"></a>**1.3 保留必要原语**：核对并保留 `canonicalJson`、对象守卫、冻结等仍有实际消费者的非 AST JSON 能力；必要时迁至合适的独立所有者并更新引用，不改变其可观察行为。
- <a id="spec-req-1-4"></a>**1.4 验收**：全仓扫描及 Catalog 不含旧 AST 生产使用；生成检查、类型、依赖、文档和完整回归通过，并覆盖模型、工具、Web、Snapshot 恢复及跨进程真实链路。

## 架构与核心决策

本 Spec 依赖前六方向的实际交付和联合验收，而非仅依赖它们的设计；只在上述证据齐备后删除。`contracts` 包是否整体移除由非 AST 原语的实际归属决定，不能仅以包名判定死代码。

## 风险与否定性保证

风险等级：高。错误删除会破坏边界验证、模型投影或恢复；不以删除测试、弱化检查或保留隐藏回退替代消费者迁移。
