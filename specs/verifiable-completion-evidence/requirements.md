# 可验证完成证据 需求

## 审批摘要

### 目标

为编码任务的完成判定引入可验证的验收结果:Goal Task 的每条完成条件可携带验收声明,Runner 在 complete 校验时验证引用证据满足声明,使模型声明无法覆盖明确失败的验收结果。

### 范围

- 包含:完成条件扩展可选验收声明(预期 Tool、预期结果);Runner 校验扩展(携带声明的条件,其引用证据中至少一条须匹配声明);预期失败任务支持;Benchmark descriptor 注入声明。
- 不包含:验收命令的定义/生成(任务创建方提供);Evidence Gate 来源范围放宽;报告层成功语义变更;多声明组合逻辑。

### 核心行为

- 携带 `expectTool`/`expectOutcome` 声明的完成条件:引用证据中至少一条必须是预期 Tool 的 Observation 且结果符合预期,否则 complete 被拒绝。
- 预期失败(声明 `failure`)的条件引用 success Observation 时被拒;引用 failure Observation 时通过。
- 未携带声明的条件保持现状:仅引用合法性校验。
- 模型声明 complete 但存在明确失败的验收 Observation 时,complete 被拒绝;模型声明不能覆盖明确失败的验收结果。

### 风险与待确认

- 风险等级:medium;理由:触碰 Runner 校验核心与 Task 领域结构,涉及 Snapshot 结构演进(就地更新当前版本)。
- 关键操作:无。
- 风险:声明匹配基于 Observation 的工具名与 success/failure 结果形态,不解析 Observation 内容语义——声明粒度是工具级结果,非命令级断言。
- 待确认:无。

## 引言

当前 Runner 的完成证据校验验证引用合法性(覆盖每条完成条件、引用 committed Observation),但不校验证据内容与条件的对应关系;合法但不相关的 Observation 仍可用于宣告完成。本 Spec 为完成条件引入验收声明,使编码任务的完成判定具备客观依据。

## 需求

### 需求 1:完成条件的验收声明

**用户故事:** 作为定义编码任务的任务创建方,我希望每条完成条件能声明预期的验收工具与结果,以便完成判定有客观依据而非仅依赖模型自述。

#### 验收标准

1. <a id="req-1-1"></a> 当任务定义携带完成条件时,系统必须支持为每条条件附加可选验收声明,声明包含预期工具标识与预期结果(`success` 或 `failure`)。
2. <a id="req-1-2"></a> 当完成条件未携带验收声明时,系统必须保持与现状完全一致的校验语义(仅引用合法性)。
3. <a id="req-1-3"></a> 当 benchmark 任务描述包含验收声明时,系统必须在创建 Goal Task 时将声明写入对应完成条件。

### 需求 2:Runner 验收校验

**用户故事:** 作为运行 Agent 的执行方,我希望 complete 决策引用的证据被验证满足验收声明,以便模型无法用无关证据宣告完成。

#### 验收标准

1. <a id="req-2-1"></a> 当模型提交 complete 决策且某条携带声明的条件引用的证据中无任何一条匹配声明(预期工具的 Observation 且结果符合预期)时,系统必须拒绝该 complete 决策并返回明确错误。
2. <a id="req-2-2"></a> 当模型提交 complete 决策且携带声明的每条条件均有匹配声明的证据时,系统必须放行现有校验流程的后续环节。
3. <a id="req-2-3"></a> 当条件声明 `failure` 而引用的证据中包含预期工具的 success 结果 Observation 时,系统必须拒绝该 complete 决策。
4. <a id="req-2-4"></a> 当拒绝发生时,拒绝原因必须指向具体的完成条件与证据缺口,Agent 可据此继续执行或修正。

### 需求 3:预期失败任务与报告边界

**用户故事:** 作为验证"应报错行为"的评测者,我希望预期失败的任务能以 failure Observation 作为有效验收证据,以便这类任务不被误判为未完成。

#### 验收标准

1. <a id="req-3-1"></a> 当条件声明 `failure` 且引用证据包含预期工具的 failure 结果 Observation 时,该条件验收通过。
2. <a id="req-3-2"></a> 当验收 Observation 失败但无验收声明的任务环境最终判定成功(如 ALFWorld `won=true`)时,报告成功仍以环境事实为准,本 Spec 不改变报告成功语义。
