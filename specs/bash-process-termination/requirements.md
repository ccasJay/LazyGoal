# Bash 进程终止保障 需求

## 审批摘要

### 目标

修复 BashTool 超时/中止后无法保证执行时长上限的缺陷:命令在超时或中止后确定终止并按时返回,不遗留受管进程。

### 范围

- 包含:超时/中止时对整个进程组执行双阶段终止(SIGTERM → 固定宽限期 → SIGKILL);后台派生进程随进程组终止,输出管道不再悬置;最迟 `timeoutMs` 加宽限期内返回 `COMMAND_TIMEOUT` 或中止结果。
- 不包含:Windows 进程组语义(维持现有单进程兼容行为)、宽限期可配置化(固定常量,不新增输入字段)、命令内容审查、并发控制、exactly-once 承诺。

### 核心行为

- 超时后命令(包括忽略 SIGTERM 的命令)最迟在 `timeoutMs` 加固定宽限期内返回 `COMMAND_TIMEOUT`。
- 命令派生的后台进程随进程组一并终止,返回后无遗留受管进程。
- 中止(abort)使用同一双阶段终止并保持 `ExecutionAbortedError` 传播语义。
- 现有对外契约不变:`COMMAND_TIMEOUT`/`COMMAND_FAILED`、有界尾部输出、`manual` 重放策略与中断后 `outcome_unknown` 恢复语义。

### 风险与待确认

- 风险等级:medium;理由:触及 Tool 进程生命周期与中止恢复边界,但对外契约不变、变更可逆。
- 关键操作:无。
- 风险:命令主动脱离进程组(如 `setsid`)的场景不受进程组终止约束。
- 待确认:无。

## 引言

BashTool 当前在超时或中止时只对直接子进程发送一次 SIGTERM 后等待退出,命令忽略信号或后台进程持有输出管道时无法保证执行时长上限,并可能遗留进程。本 Spec 定义超时/中止的确定终止行为,同时保持全部现有对外契约。

## 需求

### 需求 1:超时后命令确定终止并按时返回

**用户故事:** 作为依赖 BashTool 执行时间预算的调用方,我希望超时命令在最迟 `timeoutMs` 加一个固定宽限期内被强制结束并返回 `COMMAND_TIMEOUT`,以便执行时长上限得到保证。

#### 验收标准

1. <a id="req-1-1"></a> 当命令运行超过 `timeoutMs` 时,系统必须在 `timeoutMs` 加固定宽限期(内部常量,约 2 秒)内终止命令并返回 `COMMAND_TIMEOUT` 领域失败。
2. <a id="req-1-2"></a> 当命令忽略 SIGTERM(如 `trap "" TERM`)时,系统必须在宽限期结束后使用强制信号终止命令并仍按时返回 `COMMAND_TIMEOUT`。
3. <a id="req-1-3"></a> 当命令的退出被后台进程持有的输出管道阻塞时,系统仍必须在超时上限内返回结果,不等待管道关闭。

### 需求 2:超时/中止不遗留受管进程

**用户故事:** 作为在同一工作区连续执行多条命令的调用方,我希望超时或中止的命令连同其派生的后台进程一并终止,以便不遗留受管进程占用资源或持有句柄。

#### 验收标准

1. <a id="req-2-1"></a> 当命令派生了后台进程(如 `sleep 600 &`)且发生超时或中止时,系统必须将后台进程随命令一并终止,返回后无遗留受管进程。
2. <a id="req-2-2"></a> 当命令主动脱离进程组(如使用 `setsid`)时,系统不强求终止该脱离进程,此为已知边界。

### 需求 3:中止使用同一确定终止路径

**用户故事:** 作为可中止 Run 的推进方,我希望中止 BashTool 时命令与超时一样被确定终止,以便中止语义同样有时长保证。

#### 验收标准

1. <a id="req-3-1"></a> 当调用方发出中止信号时,系统必须对命令执行与超时相同的双阶段终止,并按现有语义抛出 `ExecutionAbortedError`。

### 需求 4:现有对外契约保持不变

**用户故事:** 作为 BashTool 的现有调用方,我希望修复只改变终止的内部执行路径,以便现有行为与测试不受影响。

#### 验收标准

1. <a id="req-4-1"></a> 当命令正常退出或以非零退出码退出时,系统必须保持现有 `success`/`COMMAND_FAILED` 观察语义与有界尾部输出(每流 10000 字符)不变。
2. <a id="req-4-2"></a> 系统必须保持 `manual` 重放策略与中断后 `outcome_unknown` 恢复语义不变,不自动重放可能已产生副作用的命令。
3. <a id="req-4-3"></a> 当运行平台不提供进程组语义(Windows)时,系统必须维持现有单进程终止行为,不引入新的平台分支承诺。
