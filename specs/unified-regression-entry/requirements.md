# 统一确定性回归入口 需求

## 审批摘要

### 目标

将根 `package.json` 中直接失败的 `npm test` 占位替换为统一、可复现的确定性回归入口:一条命令完成类型检查、依赖边界检查与全部确定性测试。

### 范围

- 包含:`npm test` 按固定顺序串联类型检查(`tsc --noEmit`)→ 依赖边界(`check:dependencies`)→ 全部确定性测试文件(packages、benchmarks、scripts);任一环节失败整体非零退出;新环境按已声明依赖安装后运行 `npm test` 即可复现。
- 不包含:付费模型调用(`llm:agent-smoke`)、需要外部环境的评测(`eval alfworld`、Conda)、CI 平台配置。

### 核心行为

- 三项检查按固定顺序执行,静态检查在前、测试在后,失败快停不继续后续环节。
- 测试环节覆盖仓库内全部确定性测试文件,不遗漏 packages 之外的 benchmarks 与 scripts 测试。
- 既有快速子集入口(单包测试命令)与独立入口(`llm:agent-smoke`、`eval`)行为不变。

### 风险与待确认

- 风险等级:low;理由:纯本地命令组装,无公共接口、持久化或权限变更,完全可逆。
- 关键操作:无。
- 风险:全量执行耗时随测试规模增长;类型检查范围当前仅覆盖 `packages/**`,benchmarks 的类型覆盖缺口是既有现状,不在本 Spec 扩大。
- 待确认:无。

## 引言

根 `npm test` 仍是直接失败的占位命令,仓库的回归检查分散在多个手工命令中。本 Spec 定义单一确定性回归入口:类型检查、依赖边界与全部确定性测试按固定顺序串联,任一失败即非零退出,使新环境可以按声明步骤复现完整回归结果。

## 需求

### 需求 1:统一回归入口按固定顺序执行三项检查

**用户故事:** 作为本仓库的开发者,我希望运行 `npm test` 即完成类型检查、依赖边界检查和全部确定性测试,以便一条命令确认完整回归状态。

#### 验收标准

1. <a id="req-1-1"></a> 当运行 `npm test` 时,系统必须按固定顺序执行类型检查、依赖边界检查、确定性测试三段检查,前一段失败时不执行后续段落并以非零码退出。
2. <a id="req-1-2"></a> 当三段检查全部通过时,系统必须以退出码 0 结束;任一段失败时以非零码结束。
3. <a id="req-1-3"></a> 当任一段检查失败时,系统必须在输出中可定位到失败的具体环节与失败详情。

### 需求 2:测试环节覆盖全部确定性测试文件

**用户故事:** 作为依赖回归结果判断变更安全性的开发者,我希望测试段覆盖仓库内全部确定性测试,以便不存在遗漏的已有测试。

#### 验收标准

1. <a id="req-2-1"></a> 测试段必须覆盖 packages 全部测试文件、benchmarks 全部确定性测试文件与 scripts 全部 `.mjs` 测试文件。
2. <a id="req-2-2"></a> 当仓库后续新增确定性测试文件时,无需修改入口配置即自动纳入测试段。
3. <a id="req-2-3"></a> 当测试段包含需要外部环境(Conda、真实模型凭据)的用例时,这些用例必须保持可跳过或已由现有替身机制隔离,入口本身不引入对外部环境的依赖。

### 需求 3:既有入口行为不变

**用户故事:** 作为日常快速迭代的开发者,我希望现有单包测试命令与独立入口保持原行为,以便既有工作流不受影响。

#### 验收标准

1. <a id="req-3-1"></a> `llm:agent-smoke`、`eval` 评测入口及各包文档化测试命令必须保持既有行为不变,付费模型调用与外部环境依赖不进入 `npm test`。
2. <a id="req-3-2"></a> 新环境按仓库已声明的依赖安装步骤完成后,运行 `npm test` 必须可以复现回归结果,不要求额外未声明的外部准备。
