# 会话指标投影 需求

## 审批摘要

### 目标

仓库内组件及本机 HTTP 客户端可以通过本机 HTTP 服务按 Goal 查询运行中及历史会话的指标，观察每个 Run 与全会话的执行规模、模型用量、缓存命中和生成速度。

### 范围

- 包含：全会话汇总、逐 Run 明细、运行中更新、重启后查询接入后已记录的历史指标，以及可供其他组件复用的 HTTP 服务包和本机只读指标入口。
- 不包含：远程网络访问、TUI 或网页展示、费用估算、缓存写入量、基于指标的预算或执行控制，以及既有开发期会话的指标回填。

### 核心行为

- 一个至少完成一个 LazyGoal Step 的 Run 计为一轮；同一 Run 在等待后恢复不增加轮数。Step 数沿用 Runtime 已提交的 Step 口径，不声称与 DSH 的 Step 定义相同。
- 输入、输出 token 只累计供应商真实上报的用量，同时报告缺失调用数与统计覆盖情况；pi-ai 的正式用量不可用，不把诊断数混入合计。
- 缓存命中率只根据上游模型接口明确上报的缓存读取数与对应输入数计算；生成速度只根据真实输出用量及可测得的首 token 后生成时长计算。条件不足时指标不可用，不以 0 或整次请求耗时替代。
- 组件通过本机 HTTP 接口读取当前及已完成 Run 指标并订阅运行中更新，重启后仍能读到已记录结果；HTTP 服务包可供其他组件挂载自己的路由并显式启动、关闭。本次指标服务实例只监听本机且只读，不开放跨域浏览器读取。指标或客户端故障不改变 Goal 执行或恢复，查询不得把可检测的缺口表现为完整统计。

### 风险与待确认

- 风险等级：medium；理由：跨模块增加持久化统计和后端读取契约，并在本机开放只读 HTTP 入口；影响范围可界定，但计数遗漏、重复或错误暴露会误导使用者。
- 关键操作：无。
- 风险：供应商字段缺失、非流式响应及指标写入故障可能使部分数值不可用或统计不完整；查询结果必须呈现覆盖情况。本机其他进程可访问只读指标入口。
- 待确认：无。

## 引言

现有 Run 状态可提供 Step 数，原生 Adapter 可提供部分真实 token 用量，但 Diagnostic Trace 不提供可靠的会话读取与聚合。本功能定义可通过本机 HTTP 服务查询的会话指标及其缺失语义，并提供可供其他组件复用的 HTTP 服务包，不改变 Goal 的执行与恢复依据。

## 需求

### 需求 1：会话与 Run 计数

**用户故事：** 作为查看会话进展的使用者，我希望按 Goal 读取轮数和 Step 数，以便区分多次执行与每次执行的工作量。

#### 验收标准

1. <a id="req-1-1"></a> 当查询一个 Goal 时，系统必须返回全会话汇总及当前、已完成 Run 的逐 Run 指标，并以稳定的 Run 身份区分明细。
2. <a id="req-1-2"></a> 当一个 Run 已完成至少一个 LazyGoal Step 时，系统必须将该 Run 计为一轮；没有已完成 Step 的 Run 不增加轮数，同一 Run 等待后恢复也不重复计数。
3. <a id="req-1-3"></a> 当 Step 提交或 Run 结束时，查询结果中的 Step 数必须与 Runtime 对应 Run 的已提交 `stepCount` 一致；全会话 Step 数必须等于各 Run Step 数之和。

### 需求 2：真实用量与缺失情况

**用户故事：** 作为分析模型消耗的使用者，我希望同时看到真实上报的 token 数和缺失范围，以便判断统计是否覆盖整个会话。

#### 验收标准

1. <a id="req-2-1"></a> 当模型调用返回供应商可确认的输入、输出 token 数时，系统必须将该次调用的数值计入所属 Run 及 Goal 的对应合计，且恢复或重复读取不得重复累计。
2. <a id="req-2-2"></a> 当调用没有可确认用量，包括 pi-ai 仅提供诊断数时，系统必须增加所属 Run 及 Goal 的缺失调用数，不得将诊断数或 0 计入真实用量合计。
3. <a id="req-2-3"></a> 当聚合范围内存在缺失用量的调用时，查询结果必须标明合计只覆盖已上报调用；当没有任何真实上报用量时，输入和输出合计必须标为不可用，不能显示为完整的 0。

### 需求 3：缓存命中与生成速度

**用户故事：** 作为分析模型效率的使用者，我希望看到有依据的缓存命中率和生成速度，以便比较会话与 Run 的效率。

#### 验收标准

1. <a id="req-3-1"></a> 当上游模型接口为聚合范围内的调用明确上报缓存读取数及对应正数输入量时，系统必须按这些调用的缓存读取 token 合计除以输入 token 合计给出命中率，并标明未提供缓存字段的调用未参与该比率。
2. <a id="req-3-2"></a> 当没有满足条件的缓存数据时，系统必须将缓存命中率标为不可用，不得推断缺失的缓存读取数为 0。
3. <a id="req-3-3"></a> 当模型调用同时具有真实上报的输出 token 数、首个非空输出增量的时间及晚于该增量的生成完成时间时，系统必须以这些调用的输出 token 合计除以首 token 后生成时长合计给出生成速度，并标明未满足条件的调用未参与该速度。
4. <a id="req-3-4"></a> 当没有满足条件的生成时间与用量时，系统必须将生成速度标为不可用，不得以整次模型调用耗时替代首 token 后生成时长。

### 需求 4：运行中读取、重启与故障边界

**用户故事：** 作为接入指标的组件开发者，我希望通过本机 HTTP 入口读取当前快照及后续更新，并在重启后复查历史，以便持续观察同一个 Goal。

#### 验收标准

1. <a id="req-4-1"></a> 当运行中的 Run 产生新的已记录指标时，本机 HTTP 消费者必须能够取得更新后的 Goal 汇总及逐 Run 明细；尚未完成的模型调用不得提前贡献最终用量或生成速度。
2. <a id="req-4-2"></a> 当进程重启后再次查询同一 Goal 时，系统必须返回接入后已记录的历史指标及其归属；接入前的既有开发期会话不要求回填指标。
3. <a id="req-4-3"></a> 当指标记录或读取失败时，Goal 执行结果与恢复依据不得因此改变；可检测的指标缺口或读取错误必须明确暴露，不得以完整统计或 0 值掩盖。
4. <a id="req-4-4"></a> 当本机 HTTP 客户端通过可复用 HTTP 服务包承载的指标路由查询存在的 Goal 时，系统必须返回只读指标快照；Goal 不存在或指标读取失败时必须返回可区分的错误结果。
5. <a id="req-4-5"></a> 当本机 HTTP 客户端订阅 Goal 指标时，服务必须提供初始快照及运行中的后续更新；客户端断开或读取缓慢不得阻断 Goal 执行。

### 需求 5：本机访问边界

**用户故事：** 作为运行 LazyGoal 的使用者，我希望指标 HTTP 服务仅供本机工具读取，以便避免意外向网络公开会话信息。

#### 验收标准

1. <a id="req-5-1"></a> 当指标 HTTP 服务启动时，系统必须只监听本机回环地址，不得接受来自远程网络接口的连接。
2. <a id="req-5-2"></a> 当 HTTP 客户端访问指标服务实例时，该实例只允许读取与订阅指标，不得提供修改 Goal、指标事实或执行状态的入口，也不得开放跨域浏览器读取。
3. <a id="req-5-3"></a> 当仓库内其他组件需要本机 HTTP 服务时，HTTP 服务包必须允许其挂载自己的路由并显式启动、关闭服务；这些组件无需启用指标路由。
