# 构建期契约 Catalog Spec

## 目标与范围

建立可由构建命令读取的 Catalog，登记全局盘点中的契约；先以在线模型列表成功响应贯通 TS 类型到 Schema、Reader 和 Manifest 的生成与检查。其他契约只登记现状及生成能力，不在本步迁移。Catalog 是数据契约的构建期索引，不拥有执行契约和运行时状态。

## 需求与验收标准

- <a id="spec-req-1-1"></a>**1.1 全量登记**：实施时，以 `codex/contract-inventory` 的 `676015c6` 盘点分册为基线，逐项登记其所有项目内具名类型、AST 节点及现有 Schema，并保留引用或派生关系。对照实施时源码核实已移动、删除或变化的声明；已删除项记录对应处置，不凭快照虚构现存契约。登记项可区分边界根和被引用声明，不要求每个声明独立生成。
- <a id="spec-req-1-2"></a>**1.2 现状可追溯**：查询登记项时，应能定位声明、所属模块、边界及消费者、定义方式、真实协议身份与版本、现有生成目标或动态组合入口。无声明、未知与不适用分别标记；登记用的内部键不冒充对外协议身份或版本。
- <a id="spec-req-1-3"></a>**1.3 能力明确**：生成时，只对显式启用且受支持的 TS 契约产生已声明的制品；AST、Zod、动态组合和其他未启用项按真实现状登记，不生成虚假的静态 Schema 或 Reader。若尝试生成不支持的契约、类型结构或约束，命令应明确失败，不静默忽略或降级。
- <a id="spec-req-1-4"></a>**1.4 统一入口**：执行 `contracts:generate -- --write` 或 `--check` 时，入口应读取 Catalog 的全部启用生成项。重复内部键、重复对外身份与版本、重复制品路径、缺失来源或无效登记使检查失败；`--check` 不写文件，缺失或漂移制品使其失败，重复生成结果确定，检查接入现有回归。
- <a id="spec-req-1-5"></a>**1.5 首个生成闭环**：在线模型列表成功响应以现有 TS 类型及 JSDoc 为唯一字段和约束来源，经 Catalog 生成同源 Schema、浏览器可用的校验器、契约专属薄 Reader 和 Manifest；Manifest 保留身份、版本、方言、来源摘要及工具版本。应用实际消费生成 Reader；不手写第二份字段表。
- <a id="spec-req-1-6"></a>**1.6 读取行为**：首个 Reader 保持现有接受、拒绝、深复制及未知字段剥离行为；诊断仅含契约身份和有界字段路径，不泄露字段值或原始响应。无效已知字段、非 JSON 值和不支持的注解仍被拒绝；不改变输入、不转换值、不补默认值。
- <a id="spec-req-1-7"></a>**1.7 验收**：核对盘点每项与 Catalog 的对应关系及变化处置，覆盖 Web、模型、工具和持久化及动态组合；验证登记冲突、缺失来源、错误注解、制品漂移和不支持生成的失败路径。通过首个 Reader 的现有测试、真实浏览器消费、干净检出构建及完整回归，确认只检查模式无写入。

## 架构与核心决策

Catalog 是可机器读取的登记信息，不是另一份数据字段 DSL。盘点是现状快照，不是构建输入；实施须取得上述盘点提交，且以执行分支当前源码核对，不能把尚未合入的 worktree 当成永久依赖。以声明位置与名称关联盘点项；动态组合只记录构造入口、组成与条件，不枚举所有运行时组合。

首批只启用已交付的 `web.providers.models.success`；在已有 `contracts:generate` 入口下接入 Catalog。生成的薄 Reader 将契约专属 Schema、校验器和身份绑定到共享读取逻辑；共享逻辑只承诺首例所需结构，遇不支持的结构须失败。保留现有公开调用接缝及浏览器行为，不建立旧 Reader 的回退路径。

[共享 JSON 类型](../shared-json-types/spec.md)只负责基础静态类型；若其实现先合入，登记时按新声明及别名关系核对。[模型查询输入](../ts-provider-model-query-contract/spec.md)和 [Provider 测试结果](../ts-provider-profile-test-contract/spec.md)各自拥有后续契约及行为，本步不替它们登记为已生成；集成时由其迁移接入 Catalog，并分别验证可选字段与判别联合，不预称本步已支持。上述 Spec 可并行准备，但最终集成须以实际合入内容解决生成入口和登记冲突。

## 风险与否定性保证

风险等级：中。关键操作是从大量盘点条目建立可检查登记，以及替换真实浏览器读取链；防止漏项、错误宣称生成能力或改变边界行为。本步不迁移其他业务契约、不修改协议或执行语义、不删除旧 AST/DSL，不把动态 Schema 固定为构建产物。
