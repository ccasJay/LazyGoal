# 其他数据边界契约迁移 Spec

## 目标与范围

迁移 Web、工具、模型和 Storage 四条线以外，仍依赖 AST 的生产数据边界与运行时消费者，包括跨进程、Worker、外部适配及相关 Runtime 边界。

## 需求与验收标准

- <a id="spec-req-1-1"></a>**1.1 范围核实**：从 Catalog、生产引用及真实装配建立剩余消费者清单；每个边界记录所有者、调用链、信任位置和由哪个 Spec 负责，避免与其他四线重复或遗漏。
- <a id="spec-req-1-2"></a>**1.2 实际迁移**：本线所属边界以 TS 类型和生成绑定取代结构 AST；跨进程、外部输入及排队数据在边界验证，类型化同进程调用依赖静态类型。边界特有规则和外部适配留在原所有者。
- <a id="spec-req-1-3"></a>**1.3 行为与验收**：未知字段按边界已确认规则处理；非法输入、身份、错误、取消及恢复语义按原边界保持。真实进程或 Worker、外部适配及 Runtime 消费链覆盖合法和拒绝场景，Catalog 与完整回归通过。
- <a id="spec-req-1-4"></a>**1.4 完成证据**：逐项记录迁移或归属其他 Spec 的证据；本线所属生产消费者不再构造、推导或解析旧 AST，非 AST 的 JSON 工具不计作遗留契约。

## 架构与核心决策

Web HTTP/SSE、工具注册、模型动态输出和 Storage 文件分别归其专属 Spec；本线只拥有其余边界。共享生成与绑定归[生成能力](../ts-contract-generation-capabilities/spec.md)，按 agreed 接口可并行准备，集成使用真实制品。状态转换、授权及恢复规则继续由原执行契约所有者维护。

## 风险与否定性保证

风险等级：高。跨进程及恢复链条容易遗漏真实调用方；不把 Catalog 静态清单或替身测试当作完整消费证明，不擅自改变外部协议或执行行为。
