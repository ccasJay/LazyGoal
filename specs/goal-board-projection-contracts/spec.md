# Goal Board 展示投影契约

## 目标与范围

为 Goal Board 建立动作可用性与原因、连接状态、工作区偏好恢复、阶段分段与审批展示四类投影契约，使界面状态可单独测试且不复制执行事实。
不新增 wire 字段，不修改 Runtime／Browser 控制协议，不重构视觉主题、Activity 内容路径或 Trajectory 查询。

## 用户故事

- **S1** 作为操作者，我希望动作不可用时看到具体原因，以便判断该等待、重连还是先处理其他状态。
- **S2** 作为操作者，我希望连接状态只有一种说法，以便不把断线误读为失败或仍在执行。
- **S3** 作为操作者，我希望重新打开工作区时恢复的是同一工作区的位置，以便不会串到别的目录。
- **S4** 作为维护者，我希望阶段与审批的展示状态由可测试的投影产生，以便扩展界面时不复制判断逻辑。

## 验收标准

| ID | 故事 | 类型 | 当 | 系统应 | 验证 |
|---|---|---|---|---|---|
| R1.1 | S1 | 事件 | 界面渲染动作入口（含现有运行控制）时 | 每个动作展示可用性与不可用原因，原因区分目标未选、Run 状态不符、命令在途、连接重建与状态过期 | 动作可用性纯函数单测 |
| R1.2 | S1 | 状态 | 选中 Goal、Run 状态、连接或在途命令变化时 | 可用性按当前控制状态重新派生，不沿用上一次渲染的结论 | 状态迁移与重算单测 |
| R1.3 | S1 | 异常 | 动作的提交结果不明 | 展示未知并按原 `intentId` 核验；确认未应用前不得以新身份重发，也不得显示为已生效 | 未知结果核验与重复提交单测 |
| R2.1 | S2 | 普遍 | 界面展示连接状态 | 只使用一份连接展示投影，区分已连接、重连中与最后状态可能过期；断线保留最后已知状态 | 连接投影单测 |
| R2.2 | S2 | 异常 | SSE 断开、状态过期或尚未完成权威同步 | 暂停执行动画与依赖最新状态的新决定，停止既有 Run 仍可用；不得把断线显示为失败或完成 | 断线与受限动作单测 |
| R3.1 | S3 | 事件 | 打开工作区并取得 `workspaceRoot` 后 | 按该 root 恢复侧栏、Activity 宽度、所选 Goal 与视图；不同 root 互不覆盖，端口变化不丢失 | 偏好解码与双工作区单测 |
| R3.2 | S3 | 异常 | 偏好缺失、损坏、身份尚未就绪，或所选 Goal 不存在 | 使用可操作默认并保留明确反馈；身份未就绪前不得应用任何已保存位置；不阻断会话控制 | 解码失败与身份等待单测 |
| R4.1 | S4 | 状态 | 时间线渲染 Stage 分段 | `running`／`waiting`／`accepted`／`rejected`／`attention`／`recorded` 与动画由纯投影产生；`continued` 只对同一 Run／Stage／revision 的后续分段生效；阶段接受不推断 Run 完成 | 阶段分段投影单测 |
| R4.2 | S4 | 普遍 | 审批区域展示预检、提交与结算 | 由既有 `ApprovalSession` 派生，界面不维护平行的预检或提交阶段机 | 审批区域测试与所有权审查 |

组合：真实服务与隔离数据下验证动作原因、断线受限与跨端口恢复（`npm run test:web-e2e`）；最终运行 `npm test`、`npm run build:web`、`npm run check:dependencies`、`npm run check:docs`。

## 决策

| 决策 | 理由 | 放弃 |
|---|---|---|
| 展示契约只落在 `apps/goal-board/src` 投影层，形态为类型加纯 selector 与映射测试。 | wire DTO 回答“服务端提供什么”，展示契约回答“显示什么、允许什么”；单消费方不需要新的包或运行时 Schema。 | 新增 wire 字段、独立 UI 契约包或 `contracts/` catalog 条目：为同进程类型引入重复校验与生成成本。 |
| 连接展示由 `StreamRecoveryState` 与 `ControlConnection` 共同派生，但不合并两个 reducer。 | 前者拥有会话同步与过期，后者拥有失效范围；展示统一不等于语义合并。 | 合并成一个连接状态机：丢失失效范围或同步语义。 |
| 工作区偏好存于 cookie 以跨端口恢复，键为 `workspaceRoot` 的稳定短哈希。 | cookie 不受端口限制且可限定 `path`；哈希桶键避免把本机绝对路径写入每个请求。 | 按端口使用 localStorage：换端口即丢失；直接存绝对路径：扩大暴露面。 |
| 审批预检改用既有 `selectApprovalSession`，删除界面内的平行阶段状态；解析错误等纯 UI 反馈留在组件内。 | 控制契约已决定派生 `ApprovalSession`，界面复制阶段机会与其失效规则冲突。 | 保留组件内 `reviewing`／`review` 状态：与 selector 产生两条真值路径。 |
| 与 `goal-board-workbench` 和 `browser-control-contract` 按接口协作：本 Spec 拥有展示投影，不复制其控制语义或动作面板行为。 | 展示投影可先独立实现并以纯函数验证，动作面板接入时只消费既有类型。 | 在本 Spec 内实现动作面板或修改控制协议：重叠所有权。 |

## 风险与否定性保证

| 等级 | 理由 | 关键操作 |
|---|---|---|
| medium | 动作可用性决定用户能否触发运行控制，错误收紧会阻断本应允许的操作。 | 执行前仍按控制协议重验；断线与过期只限制依赖最新状态的新决定，停止既有 Run 保持可用。 |
| medium | 偏好跨端口持久化，可能泄漏本机路径或把位置套用到其他工作区。 | cookie 只保存哈希桶键与布局、位置；身份未就绪前不应用；不保存消息正文、草稿、审批内容或执行事实。 |

展示投影只约束渲染，不构成授权；`ControlState` 与 `ApprovalSession` 仍是唯一控制事实来源（R1.1、R1.3、R4.2）。
