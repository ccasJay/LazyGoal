# 按需暴露工具 Schema 需求

## 审批摘要

### 目标

Agent 先用轻量工具目录发现当前可用能力，再让 Runtime 在后续模型请求中只提供已发现工具的完整 Schema，降低每次请求的上下文开销。

### 范围

- 包含：模型按需发现工具；工具可见范围受当前 Goal Profile 与注册状态限制；已发现工具在 Run 内累积并可恢复；Prompt、原生工具声明及 `execute_program` 使用一致的可见范围。
- 不包含：改变工具执行授权、审批、Policy 或沙箱规则；动态注册工具；按模型自行生成的路径或 ID 扩大权限。

### 核心行为

- Agent 可通过查询获得最多 5 个匹配工具的 ID 和简短描述；无匹配时返回明确空结果。
- 查询匹配的工具 Schema 从后续模型请求开始可用，并在当前 Run 内累积；新 Run 从空集合开始，恢复 Run 保留已发现集合。
- 未发现工具不可直接调用；`execute_program` 只能调用相同可见集合内的工具，但所有工具仍须通过既有执行授权流程。
- Prompt 和模型原生工具声明必须呈现相同的已发现工具集合；发现能力只在 `decide` 阶段提供。

### 风险与待确认

- 风险等级：medium；理由：跨 Runtime、Agent、Contracts 与 Snapshot 持久化的模型可见行为变更。
- 关键操作：无新增越权或外部副作用操作；工具执行继续沿用现有授权和审批边界。
- 风险：工具可见集合与工具执行授权若分离不严，可能造成未发现工具调用或 PTC 绕过；持久化错误可能导致恢复后 Schema 集合不一致。
- 待确认：无。

## 引言

本 Spec 定义 Agent 如何搜索当前授权工具并逐步获得其完整 Schema，同时保持可恢复性及既有工具授权边界。

## 需求

### 需求 1：发现当前可用工具

**用户故事：** 作为 Agent，我希望按任务查询可用工具，以便只加载相关能力的完整 Schema。

#### 验收标准

1. <a id="req-1-1"></a> 当 Agent 在 `decide` 阶段查询工具时，系统必须只从当前 Goal Profile 授权且已注册的工具中匹配，并返回匹配工具的 ID 与简短描述。
2. <a id="req-1-2"></a> 当查询匹配结果超过 5 个时，系统必须返回至多 5 个结果；当无匹配项时，必须返回明确的成功空结果。
3. <a id="req-1-3"></a> 当 Agent 不处于 `decide` 阶段时，系统不得暴露工具发现能力。

### 需求 2：按发现结果暴露工具 Schema

**用户故事：** 作为 Agent，我希望在找到合适工具后获得其完整输入 Schema，以便构造符合契约的调用。

#### 验收标准

1. <a id="req-2-1"></a> 当工具发现请求返回匹配项后，系统必须从后续模型请求开始暴露这些匹配工具的完整 Schema。
2. <a id="req-2-2"></a> 当一个 Run 多次发现工具时，系统必须累积其可见集合；未匹配工具的 Schema 不得因其他工具被发现而暴露。
3. <a id="req-2-3"></a> 当构造模型请求时，Prompt 中的工具描述与原生工具声明必须对应同一可见集合。

### 需求 3：保持工具调用授权边界

**用户故事：** 作为 LazyGoal 用户，我希望工具发现不改变执行权限，以便节省 Schema token 时仍沿用现有授权机制。

#### 验收标准

1. <a id="req-3-1"></a> 当 Agent 直接调用当前 Run 尚未发现的工具时，系统必须在执行前拒绝该调用。
2. <a id="req-3-2"></a> 当 Agent 通过 `execute_program` 调用工具时，系统必须限制其工具集合与当前 Run 已暴露集合一致，并继续执行既有 Profile、Registry、Tool Policy、审批和沙箱检查。
3. <a id="req-3-3"></a> 当某工具已被发现时，系统仍必须按现有授权规则检查其每次调用；发现结果不得扩大授权或跳过审批。

### 需求 4：恢复已发现工具集合

**用户故事：** 作为恢复中断 Run 的用户，我希望继续使用此前发现的工具，以便恢复执行时保持模型可见能力一致。

#### 验收标准

1. <a id="req-4-1"></a> 当 Run 发现工具后被持久化并恢复时，系统必须保留该 Run 已暴露工具集合。
2. <a id="req-4-2"></a> 当创建新的 Run 时，系统必须从空的已暴露工具集合开始，不继承其他 Run 的发现结果。
3. <a id="req-4-3"></a> 当已暴露工具 ID 不再属于当前 Goal Profile 或不再注册时，系统不得向模型暴露其 Schema 或允许其执行。
