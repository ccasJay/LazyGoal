# Context Epoch 工作窗口

## 目标与范围

所有受支持的 Goal 和模型统一使用可计量的 Epoch 工作窗口，支持阈值触发、`/compact`、一次超窗恢复，以及按 Goal 和 Run 组织存储。
提炼仅用于当前 Goal 的上下文接续。Working Memory 扩展、经验总结、跨 Goal 记忆和独立 Epoch 交接记录留待后续设计。

## 用户故事

- **S1** 作为 Goal 用户，我希望配置工作窗口并看到当前占用，以便判断上下文何时需要整理。
- **S2** 作为长任务用户，我希望 LazyGoal 能自动或按命令压缩上下文并安全恢复，以便继续当前任务。
- **S3** 作为本地工作区用户，我希望按 Goal 和 Run 管理执行数据，以便继续会话并查看历史轨迹。

## 验收标准

| ID | 故事 | 类型 | 当 | 系统应 | 验证 |
|---|---|---|---|---|---|
| R1.1 | S1 | 状态 | 模型窗口已知，或用户已配置有效上限 | 默认用模型标称容量。用户可设更小的 token 上限和整理阈值。模型窗口未知时，用用户上限作为 Epoch 容量和阈值基数。 | 参数化测试已知窗口、较小上限、未知窗口加配置以及非法配置。 |
| R1.2 | S1 | 异常 | 模型窗口未知且用户未设置 Epoch 上限 | 在发送前拒绝模型调用，并提示配置上限。 | 调用入口测试断言适配器调用数为零，返回配置提示。 |
| R1.3 | S1 | 事件 | 普通模型调用结束，或实际保留的工作窗口变化 | 结算占用取当次输入加输出，缓存输入计入一次，历史不跨调用累加。新窗口按实际内容重计。用量缺失时允许 token 估算并标记。Context 主行显示已用比例。基数来自用户配置且模型窗口未知时，悬停或键盘聚焦显示配置来源和 token 上限。 | 对重复历史、缓存、用量缺失、模型切换和压缩前后检查计量。浏览器用例断言百分比、估算标记和鼠标及键盘可访问的详情。 |
| R1.4 | S1 | 异常 | Epoch 容量缺失，或实际及估算占用都无法取得 | 显示 Context 不可用图标，缺少占用的样本不用于阈值触发。 | 指标和 Runtime 测试断言不可用状态、无伪造百分比及零次提炼。 |
| R2.1 | S2 | 事件 | 具备有效容量的普通请求发起并结算 | 完整工作窗口先发送给供应商，预计超窗不提前裁剪、拒绝或触发压缩。结算后占用严格超过阈值时执行一轮模型提炼，其余可计量样本继续普通执行。提炼调用计入成本，但不作为下一轮自动触发依据。 | 用可控适配器覆盖阈值下、等于、超过以及预估超限，断言实际请求内容、顺序和额外调用次数。 |
| R2.2 | S2 | 事件 | 用户在已打开的 Goal 输入无参数 `/compact` | 即使占用低于阈值，也按同一规则执行一次 Compact。命令不进入对话或创建业务 Run。忙时在安全边界执行，等待外部动作且无法切换时说明原因。与自动触发重合时共用同一轮。无可压缩内容时给出反馈。 | 命令与 Runtime 测试覆盖低占用、忙碌、等待、终态、空历史及并发。断言提炼次数、业务 Run 和消息数量。 |
| R2.3 | S2 | 事件 | Compact 在完整交互和已结算执行单元边界完成提炼 | 模型只提炼候选移出历史，并参考当前接续状态及必要的近期片段。新窗口保留有效用户要求、任务状态及近期完整交互。压缩正文保留仍相关的已验证发现、未解决问题、关键决策理由及其来源。原始历史仍可查，提炼不写 Working Memory。 | 检查提炼请求、下一普通请求和原始轨迹，核对必保信息、引用、工具调用与结果配对及 Working Memory revision。 |
| R2.4 | S2 | 异常 | 提炼无效、未缩减、提交中断，或提交后重启 | 提交前恢复旧 Epoch，提交后按快照指针恢复新 Epoch。无效或未缩减时保持旧窗口，自动触发记录失败后继续，手动触发返回原因。迟到结果和未提交轨迹不能推进 Epoch。 | 在追加事件、保存快照、后续提交和并发续写处注入失败或中断，验证恢复内容、指针和业务状态。 |
| R2.5 | S2 | 事件 | 供应商明确以超出上下文窗口拒绝首次完整请求 | 使用可装入提炼请求的候选历史执行一次 Compact，成功后重试同一逻辑请求一次。保留执行阶段和操作身份。 | 可控适配器先拒绝再成功，核对请求顺序、上下文变化及已结算工具动作没有重放。 |
| R2.6 | S2 | 异常 | 超窗恢复无法完成 Compact，或重试仍被明确拒绝为超窗 | 结束本次 Run 并区分失败原因。其他请求错误走既有处理路径。 | 断言整理失败时未发送重试、持续超窗时只有一次重试、其他错误未触发 Compact。 |
| R3.1 | S3 | 状态 | 新布局中打开、续写、恢复 Goal，或查询多页 Run 历史 | Goal 根保存快照和完整对话，Run 子目录保存执行专属文件。用户能分页定位旧 Run 并查看事件和模型输入详情，轨迹页只读取所选 Run 的轨迹及其索引。 | 临时工作区验证路径、重启续写、超过一页的 Run 选择与详情，记录实际访问的轨迹路径。 |
| R3.2 | S3 | 事件 | 停写后切换到新布局 | 通过显式清理删除旧布局的全部本地 Goal 和专属记录，保留工作区共享数据。切换后所有新 Goal 使用新布局。 | 临时工作区混合放置旧 Goal、新 Goal 和共享文件，执行清理后核对删除和保留范围。 |

组合：用真实文件存储和可控模型适配器跑跨 Run、多次 Compact 的续写与重启流程，核对接续内容、调用开销及历史读取范围，并运行 `npm test`、`npm run check:dependencies`、`npm run contracts:generate -- --check` 和 `npm run check:docs`。

## 决策

| 决策 | 理由 | 放弃 |
|---|---|---|
| LazyGoal Home 的 `config.toml` 提供 `[context].epoch_limit_tokens` 和 `[context].compact_threshold_percent`。上限为正的安全整数，超过已知模型窗口时提示调整。阈值默认 80，接受 1–99 的整数。宿主重载后在下一请求绑定时生效。 | 复用现有配置入口，同一次请求和结算使用同一配置。 | 无 |
| Runtime 在普通调用结算后统一调度 Compact，替换请求构造阶段的容量检查点。提炼请求按完整历史前缀取候选，为输出留空间，超大候选工具结果可使用现有预览和来源引用。放不下的候选保留在工作窗口。 | 一次有界提炼可同时服务阈值、手动命令和超窗恢复，保留执行协议所需的完整交互。 | 按预计压力提前切换检查点。 |
| `/compact` 绑定 Goal 的当前 Epoch。最新 Run 已结束时可以提交上下文事件，保留业务终态与步骤。已归档 Run 只读。中断中的 Compact 不自动重放。新 Run 可引用最后一次已提交压缩，换模型时重计并结束旧供应商的原生续接。 | 让命令遵守现有 Run 边界，并为重复触发、重启和模型切换提供确定行为。 | 为 Compact 创建单独业务 Run。 |
| 压缩正文与来源范围写入当前 Run 的 Epoch 切换事件。复用 Goal 提交闸门，快照只保存新 Epoch、事件身份、实际序号和水位。恢复核验 Goal、来源 Run、事件及提交水位，无法解析已提交指针时报告存储错误。 | 以快照显式提交作为唯一切换点，允许从当前或历史 Run 恢复压缩文本。 | 将正文复制进每次快照，或根据日志尾部、临时文件及内存标志推断切换。 |
| `goals/<goalId>/` 下用 `snapshot.json`、`blobs/` 和 `indexes/` 保存 Goal 数据。`runs/<runId>/` 保存 `trajectory.jsonl`、`trajectory.index.db`、`model-inputs.jsonl`、`metrics.jsonl` 和 `trace.jsonl`。存储装配、查询和维护入口共用路径规则。 | 共享内容集中在 Goal，单次执行数据可按 Run 直接定位。 | 旧布局迁移和并行读写。 |

## 风险与否定性保证

| 等级 | 理由 | 关键操作 |
|---|---|---|
| high | R3.2 永久删除旧布局的 Goal 数据。共享调度、授权及配置可能同处一个工作区。 | 实际清理只覆盖已授权的旧 Goal 专属数据。测试使用临时目录。执行前核对具体数据根及清理边界。 |
| high | R2.3–R2.6 涉及跨文件持久化、进程中断和模型重试。部分提交或错误重放可能改变任务上下文。 | 以故障注入验证恢复边界。真实供应商调用使用已授权的模型和范围。 |
