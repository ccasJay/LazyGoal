# Worker 进程化与 Trigger 驱动的 Goal

## 目标与范围

在单机上以 Supervisor、独立可复用的 Worker 进程和统一 Trigger 接收、授权、派发并恢复细粒度 Goal，保留 Worker 上下文和实时观察能力。
不设计长期会话容器、普通后续消息、Worker 间协作、GitHub 等具体外部适配器、多机调度或旧数据迁移；受影响的评测执行入口暂不支持新架构。

## 用户故事

- **S1** 作为事件生产者，我希望通过统一 Trigger 传递 Goal 和事件，以便 Supervisor 可靠准入和处理。
- **S2** 作为用户，我希望 Supervisor 将 Goal 派给独立且可复用的 Worker，以便进程生命周期与工作状态分离。
- **S3** 作为权限所有者，我希望 Supervisor 在授权上限内处理 Worker 的请求，以便受限动作只在获准后执行。
- **S4** 作为运行所有者，我希望进程断开或退出后保留队列与上下文，以便恢复时不丢失事件或重复执行。
- **S5** 作为现有使用者，我希望用户入口、输出和不再支持的能力明确呈现，以便理解新架构的行为变化。

| R1.2 | S1 | 异常 | 传递重试、身份冲突或尝试创建已有 Goal ID | 已结算传递重试返回原结果，未结算项可继续处理；同一 Trigger 的不同传递可关联或创建不同 Goal；冲突载荷及占用的 Goal ID 包括无法读取的旧数据均拒绝覆盖；准入、Goal 创建、收据及排队恢复后保持一致，传递 ID 可查询待处理和结算结果。 | 在准入、创建、收据及排队各边界注入故障，验证同一传递至多创建并派发一次、旧数据不变、响应丢失可查询或重试。 |
| R1.3 | S1 | 事件 | 新工作 Trigger 到达 Supervisor | 先经确定性 Fast path 过滤和判断；未命中或不明确时由 Supervisor 直接调用 LLM 执行 Slow path，不创建决策 Worker；结果为忽略或接受，接受后才持久化携带来源 Trigger、独立 ID 和授权范围的 Goal，并按准入完成顺序进入持久队列。 | 新增 Fast／Slow path 集成及并发准入测试，覆盖忽略、规则接受、LLM 接受、顺序与保存前不派发。 |
| R1.4 | S1 | 异常 | Slow path 失败或无法作出判断 | 保留 Trigger 及待处理记录并报告原因，不丢弃事件、不创建 Goal；后续可重试且遵守 R1.2。 | 新增模型失败、异常载荷和重试测试，验证事件与待处理状态跨重启保留。 |
| R2.1 | S2 | 事件 | Goal 准入并进入待派发队列 | Supervisor 按入队顺序派发，不等待前一 Worker 完成且不设置 Worker 并发上限；结合工作区、上下文和授权选择空闲 Worker，无合适者启动独立进程；同一 Goal 同时仅由一个 Worker 执行，同一 Worker 同时仅执行一个 Goal，完成后可复用。 | 新增真实多进程调度测试：核对入队顺序、不同 Goal 并行、单 Goal 单写入执行和空闲 Worker 复用。 |
| R2.2 | S2 | 状态 | Supervisor 为 Goal 选择工作区 | Supervisor 按任务决定共享工作区或新建独立 Git worktree，并按决定执行合并和清理；项目、执行工作区及授权身份保持正确映射，不能因路径变化扩大授权；只复用绑定所需工作区的空闲 Worker；创建失败时保留待处理并报告，不回退共享工作区。 | 使用临时 Git 仓库验证选择、实际合并清理、权限映射、操作故障及创建失败，不操作用户仓库。 |
| R2.3 | S2 | 事件 | Worker 执行、完成或收到取消的 Goal | Supervisor 独占 Goal 状态写入，维护待派发、执行中、等待决策、成功、失败、已取消及待恢复；Worker 持久化自身上下文、授权历史与执行检查点，经 Trigger 报告进度和结果；等待决策保持原 Goal 绑定，取消后只有确认当前动作安全停止并结算报告才可复用 Worker。 | 验证状态转换、上下文及授权历史重建、取消竞态、离线完成后一致结算和未确认停止时不可复用。 |
| R3.1 | S3 | 事件 | Worker 执行工具或沙箱动作并需要授权决策 | 每个动作包括默认可用工具均受当前 Goal 范围、适用的宿主及用户上限和有效授权共同约束；请求通过关联 Goal、动作、请求和 Worker 进程代次的 Trigger 发送，原 Worker 暂停受限动作；Supervisor 可默认由 LLM 在上限内代替人工审批，并以 Trigger 回复，不新建 Worker。 | 新增权限往返、默认可用工具越界、历史授权复用、撤销与动作开始竞争及真实沙箱范围测试。 |
| R3.2 | S3 | 异常 | 权限上限缺失、损坏或无法判断，或决策尚未返回 | 保留请求并报告需要配置或人工处理，不批准、不执行受限动作；拒绝、过期、身份不符或来自旧 Worker 进程的回复不得解除其他等待或启动动作，已撤销授权不得恢复有效。 | 新增失败关闭、跨 Worker／跨 Goal 答复、旧代次、重复回复、撤销及离线待决测试，核验无受限副作用。 |
| R4.1 | S4 | 事件 | Supervisor 退出后重新连接仍存活的 Worker | Worker 独立运行并持久化离线 Trigger、检查点及结果；Supervisor 恢复后先逐项处理恢复时的积压，再处理期间入队的新事件；失败项保留待重试且不阻塞其余积压；核对已确认 Worker 的检查点、结果与 Goal 状态后重新接管，恢复待派发顺序。 | 真实进程测试覆盖离线已授权工具执行、权限等待、离线完成的检查点与报告故障、积压失败续扫及新事件不插队。 |
| R4.2 | S4 | 异常 | Worker 退出、身份或存活无法确认，或动作结果未知 | 可证实的 Worker 启动、正常退出和异常退出生成或补记生命周期 Trigger；无可靠证据时保持待确认，不伪造退出原因、不凭 PID 或超时重派；同一存储位置只能有一个有效 Supervisor 所有者，失效所有者不得写入或派发；已退出 Worker 可重建上下文，Goal 只经明确恢复操作推进，不盲目重放未知副作用。 | 真实进程验证双 Supervisor 竞争、旧所有者拒绝、Supervisor 离线时 Worker 强杀且无见证、身份复用及未知副作用。 |
| R5.1 | S5 | 事件 | 用户使用现有入口或查询执行结果 | 用户入口经 Supervisor 和 Trigger 创建工作；保留跨进程实时观察、断线状态同步及可见性过滤；问答、计划审批、未知动作恢复和控制通过 Trigger 往返，普通后续消息不支持并移除 `spawn_subagent`；旧数据保留，评测执行入口明确报不支持且不回退旧执行链。 | 真实入口测试覆盖上述交互、观察、拒绝及旧数据；更新被替代的旧测试而不跳过无关覆盖；运行 `npm run build:web`、`npm run test:web-e2e` 和 `npm test`。 |

组合：使用确定性模型和临时仓库，经真实用户入口提交 Goal、复用 Worker、暂停权限请求、关闭并重启 Supervisor、处理离线 Trigger、继续并观察结果；分别验证离线已授权动作与同时失去 Supervisor、Worker 的未知状态，不重复派发或盲目重放（真实多进程端到端测试）。

## 决策

| 决策 | 理由 | 放弃 |
|---|---|---|
| Goal 是独立工作指令；Supervisor 独占 Goal 工作状态写入，Worker 独占其可持久化上下文与执行检查点，逻辑 Worker 与每次 OS 进程身份分离。 | Goal 不依赖特定 Worker；保留上下文及确认恢复所有权，避免两个进程覆盖同一 Goal。 | 将 Goal 等同长期会话、Worker 或一次进程。 |
| Trigger 是统一事件事实，独立传递记录承载至多一个 Goal 及处理状态；传递身份而非 Trigger ID 用于重试去重。 | 一个事件可多次传递并关联多个 Goal，状态、权限请求和控制回复不必创建 Goal。 | Trigger 持有可变状态或每个 Trigger 只能创建一个 Goal。 |
| Supervisor 单机编排并可直接调用 LLM，Worker 独立进程可复用；仅保证入队后的派发顺序，默认不限制并发。 | 保持控制和执行分离，同时允许不同 Goal 并发。 | 为每次决策新建 Worker，或串行等待上一个 Goal 完成。 |
| Permission／Sandbox 继续拥有匹配与强制执行；所有新动作受适用上限和当前 Goal 范围限制，Worker 上下文复用暂不按 Goal 权限隔离；本功能验收跨进程撤销与动作开始的安全顺序。 | 历史授权不能扩大当前动作权限；[Permission 跨进程任务](../permission/tasks.md) 尚未交付，不能假定其实现已存在。 | 将动作限制误认为能过滤 Worker 已有上下文。 |
| 用户入口切换到新语义；[现有长期 Session](../streaming-session/spec.md) 的一 Goal 一会话及普通续聊不保留，结构化交互保留；旧数据不迁移，用户入口响应时机不规定；`lazygoal eval`、GEPA 和 Harness2 中受影响的评测执行暂不支持，独立评分及只读检查不在此限制。 | 避免第二套 Goal 执行语义，同时区分执行与评测结果读取；不要求整个历史 Spec 被替代。 | 静默兼容旧快照、普通续聊或受影响评测的旧执行路径。 |

## 风险与否定性保证

| 等级 | 理由 | 关键操作 |
|---|---|---|
| high | LLM 自动授权、外部事件及跨进程授权竞争可能导致越权；Worker 上下文复用不按新 Goal 限制，先前资料可能进入后续任务；不限制并发可能耗尽资源。 | 验收使用受控模型与临时环境；真实外部服务、凭据和超出既定宿主权限的动作须单独授权。 |
| high | Supervisor 退出后 Worker 仍运行，丢失事件、身份误认或重复派发可能产生不可逆副作用；文件 Store 现无跨进程事务。 | 使用真实子进程和故障注入验证 R1.2、R4.1、R4.2；不自动删除旧 Goal 数据或盲目重放未知效果。 |
| high | Supervisor 自动决定 worktree 合并和清理可能改动仓库或丢失未提交内容。 | 实施及验收只操作临时测试仓库；对用户真实仓库执行提交、合并、覆盖或删除前须取得该具体操作的授权。 |
