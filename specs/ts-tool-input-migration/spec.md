# 工具输入契约迁移 Spec

## 目标与范围

迁移所有实际注册的业务、Program 与评测工具输入，以 TS 类型及生成绑定取代工具输入 AST；不拥有模型协议和执行授权规则。

## 需求与验收标准

- <a id="spec-req-1-1"></a>**1.1 全量工具**：以默认工具、条件注册工具、Program、各评测注册入口及 Catalog 为基线核对清单；每个工具输入有 TS 权威定义、生成绑定及真实注册消费，删除其旧输入 AST 和派生类型。
- <a id="spec-req-1-2"></a>**1.2 执行准备**：注册与 `prepare` 消费新绑定，已知字段无效失败；未知字段剥离并产生有界安全诊断，成功数据隔离后进入原有语义校验和执行。授权、审批、沙箱、取消、重放和副作用语义保持。
- <a id="spec-req-1-3"></a>**1.3 共享交接**：每个工具向模型线提供同一绑定的身份、输入 Schema 和读取/投影能力；授权工具、工具发现与远程 Worker 声明使用相同事实，不再要求输入 AST 或维护第二套字段定义。
- <a id="spec-req-1-4"></a>**1.4 验收与切换**：工具族可在隔离分支并行准备，但实际生产装配与[模型迁移](../ts-model-contract-migration/spec.md)统一切换；覆盖全部注册入口、边界约束、非法输入、授权及跨进程评测链，运行完整回归。不得以替身测试宣称联合切换完成。

## 架构与核心决策

工具线拥有工具 TS 类型、注册与准备接口；模型线拥有模型请求的动态组合和 system tools。双方以 `ContractBinding` 及其生成的同源 Schema/投影交接，实际支持能力依赖[生成能力](../ts-contract-generation-capabilities/spec.md)。各工具可按互不重叠的领域文件并行实现；共享 Catalog、注册入口和测试环境集中协调。禁止在生产中按工具混用新旧输入绑定或为同一输入双读、失败回退。

## 风险与否定性保证

风险等级：高。未知字段从拒绝改为剥离是有意行为变更；必须验证剥离后的参数进入权限与执行流程，未知工具和未授权操作仍拒绝。本步不改变工具能力或权限策略。
