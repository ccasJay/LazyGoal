# TUI 交互控制台体验需求

## 审批摘要

### 目标

构建 LazyGoal 原生的全功能交互控制台：提供带有 ASCII Art 标识的导航主页，将执行期人机交互收敛为一体化流式输入条，支持通过 Shift+Tab 快捷键进行运行模式（Confirm / YOLO）热切换，同时提供事后全屏只读轨迹检查器（Inspector）。

### 范围

- 包含：
  - 默认启动主页（Home Screen）：渲染 ASCII Art 艺术字标题，并通过官方组件提供 New Goal、View History、Settings、Exit 四项主菜单。
  - 执行期流式交互收敛：统一单输入条，支持回车快速批准、非空文字直接作为拒绝理由回传；通过 Shift+Tab 快捷键即时切换运行模式（Confirm <-> YOLO）；状态栏显式模式提示。
  - 事后全屏轨迹检查器（Inspector）：支持从主页进入或通过 `lazygoal inspect [goalId]` 进入；未传 ID 时提供交互式会话选择列表；进入后全屏分页浏览、折叠 Reasoning 思考过程、调用外部工具检查原始 JSON。
- 不包含：
  - 底层 Goal 快照和 Trajectory JSONL 存储格式与持久化协议变更。
  - 绕过 Agent 决策直接在宿主或容器执行命令的旁路机制。
  - 多进程并发或后台 Worker 调度。
  - 复杂的 Slash 命令语法解析器（模式切换统一走 Shift+Tab 快捷键）。

### 核心行为

- 用户执行 `lazygoal` 默认进入主界面，展示 ASCII Art 标头并用标准选择组件呈现四项核心功能。
- 在执行期遇到待批准动作时，用户可敲击回车默认放行，或输入自然语言意见直接触发 Agent 纠偏规划；随时按下 `Shift+Tab` 即可无缝切换自动（YOLO）与确认（Confirm）模式。
- 用户选择查看历史轨迹或运行 `lazygoal inspect` 时，未指定 ID 则呈现会话选择列表，确认后在全屏终端中按步翻看历史与思考细节，按 `q` 干净退出。

### 风险与待确认

- 风险等级：medium；理由：涉及 TUI 页面状态空间扩充、按键事件监听与全屏生命周期管理，但底层数据与 Runtime 状态机完全向前兼容。
- 关键操作：无
- 风险：无
- 待确认：无

## 引言

本项目为 LazyGoal 提供现代化的终端控制台体验。通过引入首页导航、精简执行期待批准交互、补充事后轨迹回放，大幅提升开发者与 Agent 结对编码过程中的交互效率与复盘体验。

## 需求

### 需求 1：TUI 导航主页与菜单分流

**用户故事：** 作为开发者，我希望在启动 `lazygoal` 时直接看到清晰的品牌主页和功能导航，以便直观选择新建任务、复盘历史或调整设置。

#### 验收标准

1. <a id="req-1-1"></a> 当用户在终端执行不带任何子命令或选项的 `lazygoal` 时，系统必须渲染包含 ASCII Art 艺术字标题 `LazyGoal` 的导航主页。
2. <a id="req-1-2"></a> 在导航主页中，系统必须直接使用官方组件渲染包含 `New Goal`、`View History`、`Settings`、`Exit` 四个选项的单选菜单。
3. <a id="req-1-3"></a> 当用户选中 `New Goal` 并确认时，系统必须无缝切换到意图输入页面。
4. <a id="req-1-4"></a> 当用户选中 `View History` 并确认时，系统必须进入历史轨迹复盘流程。
5. <a id="req-1-5"></a> 当用户选中 `Settings` 并确认时，系统必须展示当前生效的模型、Profile、工作区根目录与持久化目录等只读信息，并提供返回主页的按键。
6. <a id="req-1-6"></a> 当用户选中 `Exit` 并确认或在主页按下 `q` 键时，系统必须干净退出当前进程。

### 需求 2：执行期一体化流式输入与按键模式切换

**用户故事：** 作为开发者，我希望在任务执行遇到等待点时使用统一的输入框并借助快捷键切换模式，以便以极低的心智负担完成放行、纠偏或切换自动运行。

#### 验收标准

1. <a id="req-2-1"></a> 当 Agent 提议了待批准的 Action 时，系统必须在流式终端底部展示一体化输入提示行，不再展示分离的二元确认框。
2. <a id="req-2-2"></a> 当处于待批准状态且用户直接按下 Enter 键（输入为空）时，系统必须自动批准并放行该 Action。
3. <a id="req-2-3"></a> 当处于待批准状态且用户输入非空文本并按下 Enter 键时，系统必须拒绝该 Action 并将该文本作为人工反馈理由提交给 Agent。
4. <a id="req-2-4"></a> 当用户按下 `Shift + Tab` 快捷键时，系统必须在 `Confirm` 模式与 `YOLO` 模式之间即时切换，无需使用斜杠命令。
5. <a id="req-2-5"></a> 当模式切换为 `YOLO` 时，后续所有待批准 Action 自动放行直至任务完成或进入 blocked 状态；切回 `Confirm` 时恢复人工逐项确认。
6. <a id="req-2-6"></a> 在待批准状态下，输入行的 Placeholder 或提示文案中必须包含 `[Enter] 放行 | [Shift+Tab] 模式切换 | 输入意见拒绝` 的提示说明。
7. <a id="req-2-7"></a> 当任务处于执行状态时，状态栏信息中必须显式标识当前运行模式（`[CONFIRM]` 或 `[YOLO]`）。
8. <a id="req-2-8"></a> 执行期的所有历史消息与观察结果必须继续通过终端流（Scrollback Stream）追加沉淀，严禁在执行期启用破坏原生文本复制的全屏备用缓冲区。

### 需求 3：事后只读全屏轨迹检查器（Inspector）

**用户故事：** 作为开发者，我希望能够在事后以分页、全屏的方式查看已生成的轨迹详情与思考过程，以便高效定位 Agent 的执行细节或排查错误。

#### 验收标准

1. <a id="req-3-1"></a> 当用户执行 `lazygoal inspect` 未指定具体 ID 或在主页选择 `View History` 时，系统必须展示历史可用轨迹的交互式列表，包含 Goal ID、更新时间与任务标题。
2. <a id="req-3-2"></a> 当用户从列表中选中某一轨迹或直接通过 `lazygoal inspect <goalId>` 启动时，系统必须在全屏模式（备用屏幕缓冲区）下打开该轨迹的复盘视图。
3. <a id="req-3-3"></a> 在轨迹复盘视图中，系统必须将该会话的消息按步骤（Step）进行切片分页展示，并在顶部 Header 标明当前步骤索引与总步数。
4. <a id="req-3-4"></a> 当用户在复盘视图中按下 `l` 或右方向键时，系统必须切换至下一步；按下 `h` 或左方向键时必须切换至上一步；按下 `0` 跳转至第一步；按下 `$` 跳转至最后一步。
5. <a id="req-3-5"></a> 当用户在复盘视图中按下 `j`/`k` 或上下方向键时，系统必须对当前步骤的内容进行垂直滚动查看。
6. <a id="req-3-6"></a> 当当前步骤包含模型思考内容（Reasoning / CoT）时，用户按下 `r` 键必须能够实时切换思考内容的展开与折叠状态。
7. <a id="req-3-7"></a> 当用户在复盘视图中按下 `e` 键时，系统必须临时挂起终端全屏模式，使用外部查看工具打开当前步骤的原始 JSON，并在外部工具退出后自动恢复全屏复盘视图。
8. <a id="req-3-8"></a> 当用户在复盘视图中按下 `q` 键时，系统必须干净退出并完全恢复用户终端原本的屏幕缓冲区。

### 需求 4：组件复用与命名约束

**用户故事：** 作为代码仓库维护者，我希望新功能完全复用现有技术栈官方组件且代码风格一致，以便保持仓库的极简性与高可维护性。

#### 验收标准

1. <a id="req-4-1"></a> 主页菜单选择与轨迹选择列表必须直接复用 `@inkjs/ui` 的 `Select` 组件，严禁自行实现手写选择菜单。
2. <a id="req-4-2"></a> 所有代码、注释、错误信息、CLI 帮助与文档中，严禁出现外部第三方项目名称，必须严格作为 LazyGoal 原生模块编写。
