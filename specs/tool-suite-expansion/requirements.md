# 工具集扩展 需求

## 审批摘要

### 目标

在同一个 Spec 中补齐文件发现、分段读取、补丁修改、网页访问、长进程管理和本地 Git 工作流，使 Agent 能通过有界、可验证的工具结果推进 Goal。

### 范围

- 包含：`list_directory`、`find_files`；扩展 `read_file`、`grep`；新增 `apply_patch`；接入已有 `web_search`、`web_fetch`；进程启动、日志/状态读取和停止；Git `status`、`diff`、`log`、`show`、`add`、`commit`，分支列举/创建/切换及 worktree 列举/创建/移除；默认工具注册、Profile 与现有授权流程接入。
- 不包含：浏览器自动化、进程跨宿主重启持续运行、交互式终端；Git 远端操作、merge/rebase/reset/clean、分支删除和强制删除；二进制补丁、补丁重命名和 fuzz 匹配；历史开发数据兼容或迁移。

### 核心行为

- 文件发现分别返回目录直接子项和路径模式匹配结果；读取支持行范围，搜索支持文件过滤、正则/大小写匹配和上下文行。结果携带路径及适用的行号，超过额度时明确截断及续查位置；不可访问或不支持的目标返回明确失败。
- `apply_patch` 接收 `{ patch: string }`，支持 unified diff/Git 文本补丁的新增、修改、删除；要求完整上下文唯一匹配，允许行号偏移，不使用 fuzz。全部路径和 hunk 校验成功前不写文件，歧义或冲突拒绝应用；成功报告实际修改，写入失败报告已知影响，结果未知按 `manual` 恢复，不承诺跨文件崩溃原子性。
- 网页工具使用已有搜索/抓取能力，返回有界搜索结果和网页文本及 URL 来源；超时、网络失败或取消不得被报告为成功，不新增浏览器能力。
- 进程启动后返回可用于后续观察和停止的标识；提供有界增量日志、运行状态和退出结果。只有所属 Goal 可管理该进程；正常关闭终止受管进程，重启后旧任务标为中断，不自动重跑或重连，不承诺异常崩溃时清理已完成。
- Git 工具提供本地查询、指定路径暂存及提交、分支列举/创建/切换、worktree 列举/创建/移除。拒绝会覆盖未保存改动的切换、移除主工作树或带未保存文件的 worktree，以及所有强制删除；Git 写操作返回可核验结果，结果未知不自动重放。
- 新增与扩展能力保持现有工作区、Profile、权限和证据边界；Git 元数据写入、额外工作树路径和网络能力不隐式越权。默认 Profile 暴露本次工具，显式用户 Profile 不被自动扩大。工具输出有界且可供直接调用和 `execute_program` 使用；新增或调整的工具说明与运行时诊断使用英文。

### 风险与待确认

- 风险等级：high；理由：涉及多文件写入、Git 状态修改、工作树移除、权限边界和进程生命周期。
- 关键操作：补丁删除/修改文件、Git 暂存与提交、分支切换、worktree 创建/移除、进程启动/停止；运行时仍须遵守现有授权，不因 Spec 获批直接执行这些操作。
- 风险：多文件写入可能在失败或崩溃时部分完成；补丁预检不能消除检查后文件变化；长进程可能产生不可逆副作用；异常退出不保证无遗留进程；查询和续查不保证跨调用的数据快照一致；Git 提交可能受本地配置和钩子影响。已有错误、超时和结果未知恢复规则继续适用。
- 待确认：无。具体工具 ID、参数、额度、匹配算法和资源管理实现留到 Design。

## 引言

本 Spec 定义 LazyGoal 在文件定位与修改、网页访问、长任务观察和本地 Git 操作中的工具行为及验收结果。各工具统一受现有授权和恢复规则约束，任务完成须以当前 Run 已提交的执行结果为依据。

## 需求

### 需求 1：定位目录与文件

**用户故事：** 作为在工作区执行任务的 Agent，我希望直接发现目录内容和符合路径模式的文件，以便定位目标而不必拼接 Shell 命令。

#### 验收标准

1. <a id="req-1-1"></a> 当调用 `list_directory` 指定目录时，系统必须返回其直接子项的相对路径和类型，不递归展开；目标不存在、不可访问或不是目录时必须返回明确失败。
2. <a id="req-1-2"></a> 当调用 `find_files` 指定搜索范围和路径模式时，系统必须递归返回符合模式的文件相对路径；默认递归必须跳过 `.git`、`.lazygoal` 和 `node_modules`，不得沿符号链接隐式越出获授权范围。
3. <a id="req-1-3"></a> 当文件发现结果超过单次额度时，系统必须返回确定顺序的有界结果、截断信息和续查位置；当没有匹配项时必须返回成功的空结果，不得把扫描失败描述为无匹配。

### 需求 2：按需读取文本文件

**用户故事：** 作为需要理解大文件的 Agent，我希望按行读取并知道未返回内容的位置，以便控制上下文用量。

#### 验收标准

1. <a id="req-2-1"></a> 当调用 `read_file` 提供行范围时，系统必须返回对应文本及实际行范围；未提供行范围时必须从文件起始读取，仍受输出额度约束。
2. <a id="req-2-2"></a> 当请求内容超过额度时，系统必须返回有界内容、截断信息和可继续读取的位置；空文件或合法范围内已到文件末尾时必须返回明确的空内容或结束信息，不得误报失败。
3. <a id="req-2-3"></a> 当行范围非法、目标不是可读取文本文件或读取失败时，系统必须返回可定位的失败原因；不得把未经解析的二进制内容当作完整文本成功返回。

### 需求 3：获得带上下文的文本搜索结果

**用户故事：** 作为定位实现或错误的 Agent，我希望限制搜索文件并查看匹配行上下文，以便减少后续读取调用。

#### 验收标准

1. <a id="req-3-1"></a> 当调用 `grep` 指定搜索范围、文件路径过滤、模式及大小写选项时，系统必须只搜索符合过滤条件的文本文件，保持正则匹配能力，并拒绝非法正则或参数。
2. <a id="req-3-2"></a> 当调用 `grep` 请求上下文行时，系统必须返回匹配文件路径、匹配行号及指定范围内的前后文本，并区分匹配行和上下文；文件首尾不足所需上下文时只返回实际存在的行。
3. <a id="req-3-3"></a> 当匹配、上下文或扫描范围达到额度时，系统必须有界返回并明确截断及续查位置；已知搜索失败必须区别于成功的零匹配结果，递归与路径访问继续遵守获授权范围。

### 需求 4：应用完整校验的文本补丁

**用户故事：** 作为修改多处代码的 Agent，我希望一次提交文本补丁并获得逐文件结果，以便完成可核验的代码修改。

#### 验收标准

1. <a id="req-4-1"></a> 当调用 `apply_patch` 提供 `{ patch: string }` 时，系统必须支持 standard unified diff 和 Git 文本补丁中的文件新增、修改、删除；格式不合法、二进制补丁或重命名必须在写入前明确拒绝。
2. <a id="req-4-2"></a> 当 hunk 行号与文件实际位置不同但完整上下文及待删除文本唯一匹配时，系统必须允许偏移后应用；当内容不符或匹配位置有歧义时必须拒绝，不得忽略上下文行、使用 fuzz 或修改待匹配文本来强行应用。
3. <a id="req-4-3"></a> 当补丁包含多个文件或多个 hunk 时，系统必须在首次写入前校验全部路径和完整补丁可应用性；任一校验失败时不得写入任何文件，必须指出失败文件和 hunk 或路径原因。
4. <a id="req-4-4"></a> 当全部写入成功时，系统必须报告实际新增、修改和删除的文件；当预检后发现目标变化或写入失败时，系统必须停止继续应用并报告已知已完成、失败及尚未应用的部分，不得把部分写入描述为完整成功，也不承诺跨文件原子回滚。
5. <a id="req-4-5"></a> 当 `apply_patch` 已开始执行但结果未提交或无法确定时，系统必须按 `manual` 策略进入现有恢复确认流程，不得自动再次应用补丁或仅凭目标内容推定成功。

### 需求 5：使用已有网页搜索与抓取

**用户故事：** 作为需要外部资料的 Agent，我希望在日常 Goal 中使用已有网页工具，以便获得可追溯的信息。

#### 验收标准

1. <a id="req-5-1"></a> 当已获授权的 Agent 调用 `web_search` 时，系统必须使用已有搜索能力返回有界的标题、URL 和摘要列表；搜索成功但无结果时必须明确返回空列表。
2. <a id="req-5-2"></a> 当已获授权的 Agent 调用 `web_fetch` 时，系统必须使用已有抓取能力返回网页文本及请求 URL 来源；内容超限时必须明确截断并提供可继续读取的位置，不执行页面交互。
3. <a id="req-5-3"></a> 当网页输入非法、请求超时、网络失败或调用被取消时，系统必须明确拒绝、失败或中止，不得返回伪造的成功内容；超时和输出均须有界，重试继续遵守现有安全重放规则。

### 需求 6：管理宿主生命周期内的长进程

**用户故事：** 作为运行长测试或构建的 Agent，我希望启动任务后分次观察并停止进程，以便不被单次 Shell 等待时间限制。

#### 验收标准

1. <a id="req-6-1"></a> 当进程启动请求获准执行时，系统必须返回所属 Goal 后续可使用的进程标识和初始状态，而不必等待命令退出；启动失败必须明确报告，启动结果未知时不得自动重复启动。
2. <a id="req-6-2"></a> 当所属 Goal 查询进程时，系统必须返回运行状态、有界 stdout/stderr 日志及适用的续读位置；进程退出后必须返回退出结果；日志截断、进程不存在或不可再管理必须明确区分。
3. <a id="req-6-3"></a> 当所属 Goal 请求停止进程时，系统必须终止受管进程及受管子进程并返回实际结果；进程已退出时不得影响其他进程；其他 Goal 不得仅凭标识查询日志或停止该进程。
4. <a id="req-6-4"></a> 当 LazyGoal 正常关闭时，系统必须终止仍运行的受管进程；宿主重启后，旧进程任务必须标记为中断，不自动重跑或重连，不将重新使用的系统进程 ID 视作原任务。异常崩溃不承诺已完成进程清理，主动脱离受管范围的进程不属于终止保证。
5. <a id="req-6-5"></a> 当单次进程启动、观察或停止调用被中止时，系统必须遵守现有中止与结果未知规则，不无限等待或自动重放副作用；日志存留和单次等待必须有界，不提供交互式终端或 stdin 会话。

### 需求 7：完成本地 Git、分支与 worktree 工作流

**用户故事：** 作为处理代码变更的 Agent，我希望检查、提交并隔离本地工作树，以便验证修改和组织开发工作。

#### 验收标准

1. <a id="req-7-1"></a> 当调用 Git 查询时，系统必须支持 `status`、`diff`、`log`、`show`，返回有界且可定位的工作树、暂存区或提交结果；不存在仓库、对象或查询失败时必须明确报告。
2. <a id="req-7-2"></a> 当 Git 写请求获准执行时，系统必须支持指定路径的 `add` 和对当前暂存区执行 `commit`，报告暂存结果或实际提交标识；不得隐式暂存未指定路径，也不得绕过提交失败或自动重复结果未知的提交。
3. <a id="req-7-3"></a> 当调用分支工具时，系统必须支持列举、创建和切换本地分支；创建冲突或切换会覆盖未保存改动时必须失败并保留改动，不执行强制切换、分支删除或历史重写。
4. <a id="req-7-4"></a> 当调用 worktree 工具时，系统必须支持列举、在获授权目标创建及移除 worktree；移除必须拒绝主工作树及包含未提交、未跟踪或其他未保存文件的目标，不得因文件被忽略就隐式丢弃，也不得使用强制移除；操作成功必须报告实际路径和关联分支或提交。
5. <a id="req-7-5"></a> 当 Git 操作已知失败时，系统必须返回失败及已知影响；写入结果未知时必须沿用人工恢复规则。系统不得自动清理或覆盖用户改动、调用远端操作、merge/rebase/reset/clean 或强制删除，查询超限时必须明确截断及续查位置。

### 需求 8：统一注册、权限与可验证结果

**用户故事：** 作为使用 LazyGoal 的用户，我希望新增工具沿用现有授权和证据规则，以便扩展能力时保持执行可控。

#### 验收标准

1. <a id="req-8-1"></a> 当使用默认工具配置启动新 Goal 时，系统必须注册并向默认 Profile 暴露本 Spec 的工具；显式用户 Profile 仅暴露其声明的已注册工具，不得被自动扩大，新工具必须可通过直接调用及已获授权的 `execute_program` 调用。
2. <a id="req-8-2"></a> 当任何工具调用涉及文件、网络、Git 元数据或额外 worktree 路径时，系统必须先遵守现有 Profile、工具授权和适用的沙箱权限规则；未授权或越界时不得执行副作用，工具不得自行扩张授权或修改 Goal 状态，持续授权及撤销继续按现有规则生效。
3. <a id="req-8-3"></a> 当工具执行完成时，系统必须返回有界且可序列化的成功或失败结果，提供适用的来源、截断和续查信息，并经现有提交路径成为当前 Run 可引用的证据；只读查询可安全重放，进程启动及结果未知的 Git 写操作和补丁不得自动重放；新增或调整的工具说明、错误和运行时诊断必须使用英文。
