# Goal Board 流式会话体验 Spec

## 目标与范围

LazyGoal 在 Activity 中按实际来源交错呈现用户消息、过程正文、工具活动、交互与最终答复。用户能够区分正在生成、候选待确认、已经保存和执行结算，向上阅读长会话时保持位置，断线后依据正式状态恢复。

本次重构会话时间线、流式正文呈现、历史加载、输入与控制区域的衔接，保留 Run／阶段分界和可折叠工具组。按已确认选择，作废候选在当前页面保留可展开的折叠提示，刷新或重连后不恢复；长历史允许在同一 Run 内分段加载，并明确显示未加载区间。包含为确定排序和有界历史所必需的消息位置关联、安全 Activity 读取投影及当前 wire 扩展，不增加持久化展示日志。

本次整合前五份 Spec 的实际能力：普通消息默认排队，Steer／Stop 显式操作，问答／审批使用已重设计的交互区域，工具参数修订仍由审批协议决定，正式消息和预览沿会话输出协议关联。沿用现有白色薄荷绿主题、字体、工作区外壳、Plan 路线、指标及 Trajectory 入口；不重做侧栏、看板、Provider 设置、模型目录或轨迹检查器。不提炼 SDK，不新增图片、MCP、子代理、终端 UI、Provider 协议、隐藏推理展示或新的执行／恢复算法。

## 需求与验收标准

### 需求 1：按真实来源重建交错时间线

作为用户，我希望按发生关系阅读过程说明和实际操作，刷新后仍获得相同顺序。

- <a id="spec-req-1-1"></a>**验收标准 1.1**：当同一 Run 包含多轮正文与工具活动时，Activity 应按实际来源交错显示，而非将所有用户消息放在步骤前、所有助手消息放在步骤后；保留 Run 分界、阶段标题及当前获批 Plan 路线，普通 Run 不生成虚构阶段。
- <a id="spec-req-1-2"></a>**验收标准 1.2**：当正式消息、工具活动、交互及 Run 结果从初始读取、分页或重复通知出现时，应按各自稳定身份归并，并从已保存的位置关联及已提交事实重建顺序；不得按正文相同、客户端时间或网络到达顺序判断正式历史。
- <a id="spec-req-1-3"></a>**验收标准 1.3**：当一次模型响应含多个公开正文块与工具块时，应保持公开正文块的原始相对顺序，区分生成工具请求与真正执行；工具活动只在 Runtime 提供对应事实后出现执行状态，不因块先收齐而提前调用工具或生成审批表单。
- <a id="spec-req-1-4"></a>**验收标准 1.4**：当 Steer、交互回复或后继 Run 的用户输入实际应用时，应出现在其真实 Run 和来源位置；尚未应用的普通队列和 Steer 留在输入状态区，不作为已经进入模型上下文的用户消息。
- <a id="spec-req-1-5"></a>**验收标准 1.5**：当刷新、重建存储或重新读取同一历史范围时，应恢复相同消息／活动身份和相对次序；来源损坏或位置不一致应明确报告读取问题，不以猜测位置、诊断 Trace 或未提交轨迹尾部填补历史。

### 需求 2：可辨识的预览、候选与正式消息

作为用户，我希望尽早阅读内容，同时知道它是否已被接受并保存。

- <a id="spec-req-2-1"></a>**验收标准 2.1**：当接收公开正文或 summary 预览时，应按 Goal／Run、调用／块及预览身份独立累积，明确显示生成中、待确认或待核对状态；新调用和不同块不得接在旧正文尾部，整块供应商结果直接显示，不伪造逐字动画。
- <a id="spec-req-2-2"></a>**验收标准 2.2**：当收到关联的正式消息时，应在原内容位置替换对应有效预览，按正式正文和用途呈现，且只保留一份正式消息；重复通知、先同步后通知和先通知后刷新均不得重复追加，未变化的历史项不因转正重新挂载。
- <a id="spec-req-2-3"></a>**验收标准 2.3**：当候选被明确作废时，应停止追加并收为标明“未采纳”的折叠项，允许用户在当前页面展开查看已接收的公开旧稿；后续候选独立显示，不把旧稿计作正式消息、完成证据或可响应审批。
- <a id="spec-req-2-4"></a>**验收标准 2.4**：当刷新页面、切换 Goal 或重建流连接时，应清除旧临时预览和作废候选正文，依据正式消息与当前有效状态重新建立视图；不得从 localStorage、历史动画或旧分片恢复已作废内容。暂时无法判定保存结果时，仍按协议显示待核对，不自行作废。
- <a id="spec-req-2-5"></a>**验收标准 2.5**：当预览缺失前缀、超过公开上限或最终正文与旧预览不一致时，应明确显示缺失／截断／替换状态；正式内容从权威消息读取，不能拼接猜测缺片、复活作废候选或让迟到分片修改正式正文。
- <a id="spec-req-2-6"></a>**验收标准 2.6**：当模型结束、阶段被接受或过程消息保存时，界面不得据此显示 Run completed；正式过程消息、阶段结果、最终答复与 Run 终态各自采用协议给出的用途和状态。

### 需求 3：工具活动与人工交互接入同一阅读过程

作为用户，我希望能查看执行细节、处理当前请求，而不会将生成计划误认成实际结果。

- <a id="spec-req-3-1"></a>**验收标准 3.1**：当展示相邻工具活动时，只能合并同 Run、同阶段、同白名单类别且在交错时间线上相邻的成员；用户／助手正文、交互、未知活动及阶段边界应断组。隐藏正文或关闭 Execution steps 筛选不能使原本不相邻的操作被错误合并。
- <a id="spec-req-3-2"></a>**验收标准 3.2**：当同一 Action 的尝试、实时返回和 Observation 提交陆续到达时，应更新同一成员并区分执行中、重试、结果待保存、已提交失败／成功和未知结果；结果详情保留真实来源，不把实时返回直接标为已保存成功。
- <a id="spec-req-3-3"></a>**验收标准 3.3**：当显示 PTC 子调用、修订后参数或未知结果重执行时，应复用真实父子身份、实际版本与本次恢复引用，区分原请求、实际执行及重执行后果；只公开既有安全摘要，完整参数及修订审阅仍走受授权详情与审批区域。
- <a id="spec-req-3-4"></a>**验收标准 3.4**：当存在已提交交互等待时，应在 Activity 下部接入 human-interaction 的唯一可操作区域，并在时间线保留相应请求／结算的只读关联；历史副本不可提交，新事件、分页和局部刷新不重置同一请求的草稿。参数修改流程复用 action-approval-revision，不再保留旧表单推进分支。
- <a id="spec-req-3-5"></a>**验收标准 3.5**：当展开工具组、阶段或已提交活动详情时，应保持成员身份、展开状态及 Trajectory 定位引用；运行结束或追加内容不强制收起用户正在阅读的详情。筛选只影响显示，不隐藏当前必须处理的请求、控制状态或改变 Step 计数。

### 需求 4：清楚的发送、排队、修正与停止入口

作为用户，我希望普通发送始终有一致含义，也能明确修正或停止当前 Run。

- <a id="spec-req-4-1"></a>**验收标准 4.1**：当在已有 Goal 输入普通文本并按 Enter／发送时，应直接走 Session 的普通 message 受理；运行或等待中明确标注 Queue next task，不再弹出必须选择 Steer／Queue 的菜单。Shift+Enter 换行，输入法组合期间的 Enter 不提交；首条消息仍创建唯一 Goal 和 Run。
- <a id="spec-req-4-2"></a>**验收标准 4.2**：当 Runtime 允许修正当前 Run 时，应提供显式 Steer 操作，并在提交前说明它会修改当前任务；待应用 Steer 与后续任务队列分别显示，拒绝或状态变化保留草稿，不能自动改成普通排队消息。
- <a id="spec-req-4-3"></a>**验收标准 4.3**：当当前 Run 可中断时，应提供不依赖输入框为空的独立 Stop run，存在草稿、排队提交或问答编辑时仍可达；中断受理、有限收尾、必要审批与最终 cancelled 按真实状态呈现，Stopping 不等于已取消或已回滚。
- <a id="spec-req-4-4"></a>**验收标准 4.4**：当普通队列被受理、应用、清空或暂停时，应仅从 Runtime 收据和状态呈现顺序及结果；清空须明确确认待清除范围，暂停队列与重启后的旧工作分别提供其合法继续／恢复入口。页面不得通过 effect、旧 localStorage 队列或连接成功自动提交后继任务。
- <a id="spec-req-4-5"></a>**验收标准 4.5**：当任一输入提交结果不明时，应保存原 inputId 与冻结载荷，提供核验／原身份重试，不能改用新身份重复发送或把未确认项显示为已受理；明确拒绝保留可编辑草稿。独立 Stop 不受该输入的单飞状态阻塞，控制之间仍由 Runtime 判定提交先后。
- <a id="spec-req-4-6"></a>**验收标准 4.6**：当切换 Goal、进入设置再返回或当前请求被其他客户端结算时，应按 Goal／Run／输入或请求身份隔离草稿和在途结果；迟到响应不能清空另一份草稿或提交给新目标。普通消息不代答问卷、批准范围或解除暂停，模型、模式与权限操作保留既有安全点。

### 需求 5：断线、状态核对与跨 Run 阅读连续性

作为用户，我希望看到真实连接和执行状态，重连不会重复任务或丢失正式结果。

- <a id="spec-req-5-1"></a>**验收标准 5.1**：当建立或重建连接时，应消费统一 Goal SSE 的 state_sync，再协调当前消息、等待、队列和后续事件；跨 Run 不重建一套执行订阅，旧 Run 的迟到活动只能归档到其真实来源，不能覆盖当前 Run 状态。
- <a id="spec-req-5-2"></a>**验收标准 5.2**：当连接断开或同步读取失败时，应保留最后确认的正式内容和当前草稿，明确标记状态可能过期，禁用依赖最新状态的新决定；SSE 无 token 或单纯断开不能被解释为执行失败、取消或可以重发任务。
- <a id="spec-req-5-3"></a>**验收标准 5.3**：当重新同步发现已保存消息、交互结算或终态时，应按身份和提交修订更新同一视图，不依赖另一条 token 才能结束等待；末次通知丢失复用基础会话的核对机制，不新增浏览器每连接的领域轮询或调度循环。
- <a id="spec-req-5-4"></a>**验收标准 5.4**：当服务重启、页面重新打开或切换订阅目标时，应展示是否需要显式 resume 及队列暂停原因；读取、连接、跳到最新或展开历史不得恢复执行、消费队列或自动决定交互。
- <a id="spec-req-5-5"></a>**验收标准 5.5**：当卸载视图、切换 Goal 或取消历史查询时，应释放本地订阅、请求、合并帧与观察资源，并阻止旧回调写入新目标；释放观察不发送 Interrupt，也不撤销已受理输入或关闭宿主 Runtime。

### 需求 6：同一 Run 内的有界历史读取

作为长会话读者，我希望按需查看较早内容，且知道当前窗口尚未包含什么。

- <a id="spec-req-6-1"></a>**验收标准 6.1**：当首次打开超长会话或单个超长 Run 时，应读取有界的最近 Activity 窗口，显示对应 Run／阶段上下文及可加载的前后区间；不得为了显示当前页面先下载全部消息、整段原始轨迹或完整 Run 的所有步骤。
- <a id="spec-req-6-2"></a>**验收标准 6.2**：当向前／向后加载历史时，应按稳定位置和固定消息／轨迹上界分页，使同一 Run 可被拆为多段；并发追加不混入已固定的历史页，页边界不能重复或遗漏正文与活动，同一阶段或活动组跨页时需标明不完整而非声称完整。
- <a id="spec-req-6-3"></a>**验收标准 6.3**：当正文、活动详情或历史范围未完整提供时，应明确区分未加载、已截断、不存在和读取失败，提供相应只读加载／重试入口；消息按 messageId 读取，活动沿已提交来源查询，不从预览补正文或通过扩大公开字段获取任意参数。
- <a id="spec-req-6-4"></a>**验收标准 6.4**：当用户加载、翻页、展开内容或有效预览转为正式消息时，应优先保持当前可见项与相对位置；用户向上阅读后暂停自动跟随，新增内容提供 Jump to latest。只有用户仍处于底部跟随状态或显式跳到最新时，才跟随新增正文和后继 Run。
- <a id="spec-req-6-5"></a>**验收标准 6.5**：当长时间生成、连续作废候选或反复翻页时，应限制历史页、临时正文及详情缓存并清理失效来源；移出窗口的已保存内容可重新读取，作废旧稿释放后明确提示不可恢复。不得无限累积 token 事件、DOM 或整份会话副本，也不得在背压时丢弃控制事实后假称同步完整。

### 需求 7：安全正文与可持续阅读的界面

作为键盘、移动设备或辅助技术用户，我希望生成期间仍能阅读、选择文本和处理当前任务。

- <a id="spec-req-7-1"></a>**验收标准 7.1**：当渲染流式和正式正文时，应使用相同的安全 GFM Markdown 规则，保留原始文本、表格、列表及代码语义；半截围栏／链接可暂时重排，但不能改写源文本、执行 HTML 或脚本、自动加载模型提供的图片或远程嵌入。只支持公开投影，reasoning、私有阶段、原始参数及签名不得因内容块布局而公开。
- <a id="spec-req-7-2"></a>**验收标准 7.2**：当高频增量到达时，应按帧合并当前预览的更新，正式结算与控制事件及时刷新且不丢字；不为每个 token 重算全部历史分组、重解析未变化正文或更新整个工作区树。整块响应与从存储恢复的消息直接显示，不模拟实时流。
- <a id="spec-req-7-3"></a>**验收标准 7.3**：当状态变化、候选转正或新等待出现时，应保留正在编辑的焦点和阅读选择，不逐 token 播报完整正文；关键状态用有界的可访问提示表达，待处理请求提供可聚焦入口。除显式用户导航外，新增活动不得自动抢走输入焦点。
- <a id="spec-req-7-4"></a>**验收标准 7.4**：当在 320px 至桌面视口、放大文本或 reduced-motion 环境使用时，应保持正文、历史导航、独立停止和当前交互可达；代码和表格仅在自身区域横向滚动，不能撑破页面或遮挡输入区。状态同时使用文字与视觉层级，不仅靠颜色或动画表达。
- <a id="spec-req-7-5"></a>**验收标准 7.5**：当采用新时间线布局时，应沿用既有主题 token、字体、Logo 与工作区外壳，用正文、紧凑活动行和明确状态区分内容层级；产品文案使用英文，未确认内容与正式结果始终可辨。既有 Plan 路线、指标和 Trajectory 可用性不因切换布局或关闭步骤显示而丢失。

### 需求 8：真实服务与浏览器验收

作为维护者，我希望界面行为能通过真实协议、持久化结果与浏览器操作共同验证。

- <a id="spec-req-8-1"></a>**验收标准 8.1**：当验收交错顺序与候选结算时，应通过正式组合根、本地确定性模型／工具和真实浏览器贯通多轮正文与工具、分块与整块结果、候选接受／拒绝／替换、保存不明及刷新重建，核对实际 Snapshot、消息身份、来源位置和工具次数；静态 HTML 或伪造最终 DTO 不能替代。
- <a id="spec-req-8-2"></a>**验收标准 8.2**：当验收控制与恢复时，应覆盖默认排队、显式 Steer、带草稿停止、收尾审批、问答三种响应、参数修订、未知结果恢复、多客户端失效、响应丢失、快速后继 Run、断线及服务重启，证明页面不重复执行、不隐式批准或自动恢复；不依赖付费模型和危险真实工具。
- <a id="spec-req-8-3"></a>**验收标准 8.3**：当验收长历史与阅读体验时，应使用超过单页的同一 Run 和多个 Run，验证固定上界、双向分页、缓存释放、缺片／截断、滚动锚点、键盘焦点、输入法、窄屏及安全 Markdown；高频分片应有确定性的合并／渲染证据，而非以等待时间估计流式正确性。
- <a id="spec-req-8-4"></a>**验收标准 8.4**：当功能交付时，应更新变化所有者的概览、语义表及公开中文契约 TSDoc，通过适用类型、依赖、文档和受影响回归；移除被替代的分区渲染、全局 liveText 与仅完整 Run 的窗口算法，不并存两条可推进或推断正式状态的实现。

## 架构与核心决策

### 当前依据与依赖边界

当前 [GoalSession](../../apps/goal-board/src/components/GoalSession.tsx) 在每个 Run 内分区排列用户消息、步骤、临时正文及助手消息；[useRunStream](../../apps/goal-board/src/hooks/useRunStream.ts) 维护单条、保留尾部 8,000 字符的 liveText，并在新阶段清除。[ActivityProjector](../../apps/goal-board/src/activity-projector.ts) 已按 Action 协调实时活动与已提交步骤，但历史组与临时组仍分别构建；[session-window](../../apps/goal-board/src/session-window.ts) 以完整 Run 为不可分窗口。[Browser 投影](../../packages/browser/src/browser-projection.ts) 对消息和每 Run 步骤分别限量，缺少可还原交错位置的共同视图。

### 展示投影与位置关联

```text
Snapshot 消息、收据与等待 + 已提交 Trajectory
                 │
       安全 Activity 历史投影／分页
                 │                         统一 Goal SSE
                 └───────────┬─────────────────┘
                             ▼
                会话局部协调状态与展示投影
              正式消息／活动 + 有界临时预览
                             │
              Run／阶段边界、正文、可折叠活动
                             │
              唯一当前交互区域 + 队列／输入／Stop
                             │
                    既有统一 Session inputs
```

`packages/runtime`／`packages/storage` 只补齐消息提交位置的赋值、校验与编解码；`packages/browser`／`packages/web-contracts` 拥有受授权的有界 Activity 读取 DTO 与 wire 校验；`apps/goal-board` 拥有窗口、合并、展开、草稿与滚动。Runtime 不依赖 Browser 或 React，Browser 不保存第二份会话账本。只读投影不能决定授权、重新运行或生成领域事实。

正式消息沿会话输出协议保留 messageId、来源及提交关联，并增加 Run 内的 `position`：已提交轨迹的 `afterSequence` 与同一锚点内的消息次序。含义是“该事实之后、下一事实之前的消息位置”，不是显示时间或新的 Step。Run 首个事实之前使用 afterSequence = 0；赋值发生在消息原有提交边界，重试复用既有位置；所有创建、普通输入、Steer、交互、模型正文和 Runtime 通知写入者必须覆盖。

过程正文依据其被接受的模型／执行来源放在对应响应位置；工具成员以其真实请求／开始事实定位，后续尝试及结果更新该成员，并在详情保留实际结果顺序。输入使用真实应用事实，未应用的受理不能占据正式消息位置。没有新事实的零工具正文或宿主结果使用当时已提交边界与稳定消息次序，不虚构模型调用。相同锚点的消息次序遵守 Snapshot 对话顺序，锚点不得超出所属 Run 的保存边界。若一条消息需要关联本次新增事实，应在同一提交中确定该事实序列与位置后保存，不能依赖保存后的通知补写。

历史展示按 Run 顺序、事实序列及锚点内次序重建，阶段归属取其位置上的真实阶段事实；不将所有阶段结果强行移到 Run 尾部。正文块顺序与工具执行时间分属生成和执行事实：即使模型在一个响应中交错输出文本和工具块，Runtime 仍在完整响应接受后执行；UI 不能将生成期占位当作实际开始。工具卡片定位与结果更新时间分别表达，不声称工具结束发生在卡片最初出现时。

统一 SSE、同步消息与历史页中的同一消息均携带相同 position。新增 position 是当前消息契约的必要排序元数据，不引入独立 timelineId、第二条持久化事件序列或新的展示数据库；当前 Schema 原位扩展。不可定位的损坏数据明确失败，不以历史数据兼容为由添加猜测分支或自动删除用户 Goal。

### Activity 历史读取

新增只读 `GET /api/goals/:goalId/activity`，接受可选 runId、互斥的 before／after cursor 和 limit。无 cursor 时返回最近窗口；默认 50、最多 100 个原子展示项，页内按正序返回，包含双向 cursor、实际范围、首尾缺口与 Run／阶段上下文。正文项引用 messageId 及位置；活动、交互历史与边界项引用真实事实身份。工具聚合放在前端且限于已加载连续范围，服务分页不会切开单个原子项，也不假称一页已经包含完整工具组。

首次读取固定每个涉及 Run 的消息上界 throughMessageId 与已提交轨迹上界；cursor 绑定 Goal、筛选和该读取窗口，后续页只投影这些上界内的事实，不要求保存历史版本 Snapshot。新提交通过统一状态同步与实时覆盖层合并；显式跳到最新建立新窗口。cursor 不充当实时 cursor、恢复命令或权限凭据，错配／非法范围拒绝，未知来源与底层读取失败分别报告。当前阶段／执行状态由最新 Session 给出，不能把旧历史水位的状态伪装为当前状态。

该接口复用现有消息来源及安全步骤／交互投影，不透传原始 Trajectory、参数或 Observation；默认正文每项最多 4,000 UTF-16 code unit 并标记截断，不拆断代理项，全文沿既有 messageId 正文读取，每次最多 64,000。旧有活动及显式 Think 只保留既有获准摘要／已提交输出和详情入口，不公开私有 Think、Provider reasoning 或审查内部内容。页面不能扫描原始轨迹后自行重做白名单。

为首屏和翻页增加 `GET /api/goals/:goalId?view=state` 的窄状态投影，使用明确的可辨识 DTO：省略旧内嵌 messages／steps／历史 stages 时，必须显式标记这些集合未内嵌且由 Activity 窗口提供，不返回语义含糊的“完整空历史”。当前 waiting、队列、收据、控制、模型选择、Plan 路线和指标入口不随历史分页而消失。消费端迁入此路径，不先请求旧完整投影再在 DOM 隐藏大部分内容；统一 SSE 和消息查询的权威含义保持不变。

响应与页面缓存有界不代表当前 Snapshot 或 JSONL 已获得磁盘随机访问。服务可以沿现有读取器读取文件，但不得借分页将整文件发送给客户端；不为本次新增数据库、文件索引或逐 token 落盘。

### 会话局部状态与候选结算

延续现有 Hooks／局部 Context 分工，将单一 liveText 替换为按来源索引的临时项及正式项引用；页面状态 reducer 只协调展示。稳定业务身份用于去重，展示位置不以数组下标作为 React key。有效预览转正式时保留其展示实例并换用规范正文；原预览被作废后则保持作废，不因同源正式替换通知重新显示为曾获确认。

```text
公开预览 → 生成中 → 待确认／待核对 → 正式消息引用
                       └─ 明确作废 → 折叠旧稿（当前页面暂存）

连接重建 → 丢弃临时项 → state_sync／正式历史 → 当前有效后续预览
```

每个临时正文沿输出协议最多保留 64,000 UTF-16 code unit。历史至多缓存三个 Activity 页；详情至多缓存三个正文分段。已作废旧稿正文按最近使用顺序最多暂存八份，同时最多展开一份，展开中的旧稿不淘汰；超出时释放其余更早旧稿并显示暂存已释放，不伪造刷新后的恢复能力。作废标记只保留在当前有界窗口，移出窗口不作为持久历史重新查询。阅读旧页时，新历史只更新最新水位与未读提示，不持续缓存窗口外正文；跳到最新时重新读取，不能为保留实时尾部而淘汰正在阅读的锚点页。隐藏标签页／慢帧下也必须有界合并；无法维持来源完整性时报告缺口并按协议同步，不能悄悄丢字。

高频更新仅影响当前预览和相关活动，沿用按帧合并；提交、作废、交互和终态先结算合并边界，清除旧来源待执行的帧。组件复用既有安全 Markdown，不为流式呈现自行补上源文本缺失的围栏或字符；未完成格式可以随后重排。关闭 Execution steps 隐藏活动主体但不隐藏正文、Run／阶段分界、当前等待和控制，不改变完整时间线上的断组判定。

观察连接、分页和 input 提交各有局部状态，不用单一 busy 锁住整页。输入身份及冻结载荷按提交尝试保存，草稿按 Goal 隔离；状态结果只作用于原目标。不得将已受理任务、答案、工具参数、预览或令牌写入 localStorage；本次只要求当前页面会话内的草稿保持，刷新后以服务端收据恢复已受理工作，不承诺恢复未提交文字。

### 阅读与操作结构

```text
Run／阶段标题与真实状态                    查看执行轨迹
未加载历史／较早内容入口
用户输入
过程正文／未保存预览
可折叠工具组：安全摘要、真实尝试与结算状态
后续正文
已作废候选（折叠，可在暂存期间展开）
当前候选：生成中／待确认／待核对 → 已保存答复
Run 真实结果
──────────────────────────────────────────────────
当前唯一交互区域（有等待时）
后续队列／暂停原因／待应用 Steer
普通输入                 显式 Steer       独立 Stop run
```

视觉沿用既有品牌：复用白色／薄荷背景、深绿正文与边线、Avenir 字体及现有字号 token。正式正文占主阅读宽度，工具采用紧凑行，展开详情沿正文对齐；未确认状态使用文字与轻量分隔，不把每个 token／块包成同样的卡片，不复制 Claude 品牌。无新字体、插图、渐变装饰或逐项入场动画。

滚动使用稳定可见项和项内偏移作为锚点；顶部加载、缓存窗口移动、候选转正和详情展开后恢复该锚点。距底部 60px 内视为跟随，用户主动向上滚动即暂停；程序恢复锚点不算用户重新选择跟随。Jump to latest 读取最新窗口并恢复跟随，不提交输入。正在阅读历史时，新 Run 在最新位置更新，不强制切换页面；当前交互和停止入口仍可通过固定但不遮挡正文的状态区到达。

普通输入 Enter 直接发送，Steer 是明确次操作，Stop 使用独立文字／可访问名称明确的按钮；不以“空输入框发送停止”作为唯一入口。当前交互沿其专用输入区域回答，普通输入明确说明是后续任务。请求出现时只提示并提供跳转入口，不抢焦点；进入问题导航、展开旧稿和关闭详情后按触发来源恢复焦点。reduced-motion 下保留状态文字，关闭装饰性光标或过渡；辅助技术只播报关键状态，不逐 token 朗读全文。

## 曾考虑的备选方案

- **交错时间线与持久化位置关联**：选择从真实消息／事实重建，保留 Run／阶段分界。备选只增强旧临时区仍会在保存后把正文统一移到工具后；按客户端到达时间排序又无法在重启和多客户端下重建，均不满足已确认体验。
- **窄的只读 Activity 投影**：选择复用 Snapshot／Trajectory 的安全投影并提供双向分页。备选下载全部历史后仅做前端虚拟列表不能限制网络与状态副本；让浏览器合并原始轨迹会复制安全规则；另建展示数据库引入双写，均不采用。
- **同一 Run 可分段、窗口有界**：选择保留上下文并明确未加载区间。备选坚持完整 Run 是旧窗口策略，会让单个长 Run 无界；无限向上累积 DOM 也不能满足长时间阅读，故采用可重新读取的分页窗口。
- **作废旧稿折叠暂存**：按用户确认，保留变化可解释性并明确未采纳。备选立即删除正文不便对照；持久化全部候选会改变正式历史与恢复协议，均不采用。暂存受上限约束，释放时如实提示。
- **规范消息替换预览**：选择身份协调而非正文匹配。备选生成结束就转正绕过保存和审查；正式消息再次追加造成重复；为整块结果拆字动画虚构流式能力，均不采用。
- **局部展示状态与既有控制入口**：选择复用前置协议和表单，按来源隔离高频更新。备选新建全局状态框架、第二条旧 SSE 或前端任务调度会重复所有权，不能以组件重写为理由引入。
- **用户控制阅读位置**：选择底部跟随、离底暂停和显式跳到最新。备选每次状态刷新滚到底部会打断长内容阅读；完全不跟随则削弱实时反馈，均不采用。

## 风险与否定性保证

- **风险等级：high**。时间线和控制区影响用户对已保存、批准、工具副作用和停止的判断；消息位置扩展、历史水位及预览替换错误可能重排事实、重复发送或误显示成功。即便 Runtime 执行算法不变，也需安全、恢复、并发及真实浏览器验证。
- **关键操作**：实现涉及当前消息位置元数据／编解码、有界安全读取及 Activity 主布局替换。批准设计不授权迁移／删除用户 Goal、真实付费模型、危险工具验收、发布 SDK 或同时执行前五份 Spec；测试使用隔离数据和确定性本地服务。
- **事实不变量**：预览不成为正式消息或证据；同一来源只产生一份正式项；保存不明先核对；已作废旧稿不复活；历史不能从未提交 tail、诊断或网络到达时间重建；不支持的数据明确报错，不自动清空。
- **控制不变量**：页面只提交显式输入；连接、分页、切换视图和组件挂载不恢复执行；普通队列不代答或批准；Stop 不被草稿占用或等同回滚；未知效果和修订后实际参数不能用旧摘要掩盖。
- **公开与资源不变量**：公开白名单不因新布局扩大，审批详情继续按当前身份授权；不在本地存储镜像正文／参数／凭据；临时项、页面缓存、帧和请求均有界并隔离目标；清理观察资源不取消 Runtime。
- **集成边界**：仅新增本 Spec；不改写已批准前置规范、不生成 Plan、不开始实现、不写入项目记忆。实施时删除被替代的当前展示路径，保留前置所有者的单一受理、输出和表单契约，不为旧开发数据或 wire 增加兼容分支。
