# Goal Board 工作台架构

## 目标与范围

统一工作台动作入口、界面状态归属和 Activity 状态展示，使导航、运行控制和恢复行为一致且可验证。
不重构 Trajectory、模型输入查询或视觉主题，不修改 Runtime 执行语义，不引入多工作区切换或多标签功能。

## 用户故事

- **S1** 作为用户，我希望从一个入口查找 Goal 和当前可用动作，以便用键盘完成导航与常用操作。
- **S2** 作为用户，我希望重新打开工作区时恢复布局和位置，以便继续工作并看到服务端最新状态。
- **S3** 作为用户，我希望 Activity 准确区分执行进度与连接状态，以便判断哪些工作仍在进行。
- **S4** 作为维护者，我希望控制、内容和工作区界面状态各有明确归属，以便扩展界面而不复制执行状态机。

## 验收标准

| ID | 故事 | 类型 | 当 | 系统应 | 验证 |
|---|---|---|---|---|---|
| R1.1 | S1 | 事件 | 用户使用 Cmd/Ctrl+K 或工作区入口 | 在同一面板按标题搜索已读取的 Goal（含归档 Goal），并分组搜索导航、视图和运行控制动作；支持方向键、Enter、Escape、关闭后焦点恢复及窄屏操作，已有模态对话框打开时保持其焦点边界 | Goal 搜索与动作面板组件测试；桌面和窄屏浏览器键盘检查 |
| R1.2 | S1 | 状态 | 目标、Run 或连接使动作不可用 | 显示动作和可理解的不可用原因，禁止执行；真正执行时重新检查当前 Goal、Run、连接和状态，变化时保留明确反馈 | 动作可用性与状态竞态测试 |
| R1.3 | S1 | 事件 | 用户选择导航、视图、允许的运行控制、审批或删除动作 | 导航和视图使用现有入口；运行控制复用统一控制意图及现有受理、核验、防重和授权；审批及删除只打开既有审阅或确认界面，不直接作出决定或删除 | 命令面板集成测试与 Browser 控制协议回归 |
| R1.4 | S1 | 异常 | 命令结果或状态读取不明 | 显示结果未知，按原身份核验；仅确定未应用时允许原身份重试，读取失败不推断未执行，也不生成新的重复操作 | 未知结果、读取失败与重试集成测试 |
| R2.1 | S2 | 事件 | 同一浏览器重新打开同一工作区或服务端口改变 | 按工作区恢复侧栏展开和宽度、所选 Goal 及视图；不同工作区互不覆盖，先确认工作区身份再应用位置，并从服务端重新读取权威状态 | 跨端口及双工作区浏览器集成测试 |
| R2.2 | S2 | 异常 | 偏好无法读取或保存、工作区无法识别，或已保存 Goal 不存在或不可访问 | 使用可操作的默认布局或 Goals 视图，保留明确反馈；不得应用其他工作区的位置，不阻断已有会话控制 | 偏好失败、身份不可用与 Goal 不存在测试 |
| R2.3 | S2 | 事件 | 用户刷新或重新打开 Goal | Activity 默认显示最新；当前页面内浏览历史时保留阅读锚点、未读提示及跳到最新能力，刷新不恢复历史阅读位置 | Activity 分页、锚点与重新打开浏览器测试 |
| R3.1 | S3 | 状态 | Run、真实 Stage、Activity Group 或工具尝试状态变化 | 分别根据所属事实和身份展示状态；已完成的展示片段停止动画，Stage 接受不推断 Run 完成，工具返回不等于 Observation 已提交；不根据相邻位置猜测归属 | 阶段分段、工具生命周期与 Run 状态组件测试 |
| R3.2 | S3 | 异常 | SSE 断开或尚未重新同步 | 保留并标注最后已知状态、显示断线且暂停执行动画，不把断线当作 Run 失败或完成；重新同步后按新权威事实恢复状态与动画 | 断线、重连、状态变更与旧事件测试 |
| R4.1 | S4 | 普遍 | 工作台渲染控制、内容和布局 | Runtime／Browser 控制事实通过现有 ControlState、receipt、事件和定向失效归约；Activity 历史和流式内容使用现有内容路径；布局、焦点、选择和展开只由工作区界面状态持有，不复制执行状态机 | reducer、投影和工作台集成测试；所有权源码审查 |
| R4.2 | S4 | 异常 | 持久化界面偏好或切换设置、Goal、视图 | 不保存凭据、消息正文、输入草稿、审批内容或执行事实；设置页切换继续保留当前挂载会话和草稿，切换 Goal 后迟到响应不覆盖新目标 | 存储内容检查与切换竞态测试 |

组合：真实服务与隔离数据下验证搜索 Goal、打开会话、执行可用动作、状态变化后禁用动作、断线重连和跨端口恢复（`npm run test:web-e2e`）；最终运行 `npm test`、`npm run build:web`、`npm run check:dependencies`、`npm run check:docs`。

## 决策

| 决策 | 理由 | 放弃 |
|---|---|---|
| 工作区拥有界面状态，控制事实复用现有 Browser 控制协议，Activity 保留独立窗口和内容路径。 | 执行权威与临时界面状态拥有不同生命周期。 | 新建统一执行状态机：重复事实与控制协议。 |
| Cmd/Ctrl+K 扩展现有 Goal 搜索；动作注册描述身份、上下文可用性与既有执行入口，执行时再次校验。 | 保持统一发现入口及原有权限、幂等和焦点边界。 | 平行建立直接调用后端的命令通道：绕过现有控制机制。 |
| 界面偏好按稳定工作区身份和浏览器隔离并支持跨端口恢复；只保存布局和位置。 | 服务端口会变化，执行状态和敏感输入不属于布局。 | 按端口的 localStorage 单独保存：无法跨端口恢复。 |
| Activity 使用现有有界窗口、稳定锚点及已提交／实时事实；连接状态独立于执行状态。 | 保持历史读取和生命周期各自的真实语义。 | 根据显示片段、断线或相邻事件推断领域终态。 |
| 与未提交的 shared-json-types 规范仅通过现有 Web 类型与边界协作；不改变其 JSON 类型归属或校验语义。 | 可独立实现并以现有类型验证，集成时重新运行交叉检查。 | 无。 |

## 风险与否定性保证

| 等级 | 理由 | 关键操作 |
|---|---|---|
| high | 动作入口触及运行控制和审批边界，持久化界面位置跨浏览器端口并可能暴露敏感信息。 | 仅执行 R1.3 明确允许的动作；审批、删除及任何外部发送须沿既有授权流程处理。 |
| medium | 多数据源、异步恢复和断线重连可能产生过期界面或重复操作。 | 按 R1.2、R1.4、R2.2、R3.2 验证竞态、失败和恢复。 |
