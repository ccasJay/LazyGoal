# 进程会话运行时

宿主拥有的后台长进程会话管理：启动受理、并发额度、输出追加、停止与自有句柄清理。本文描述当前实现、使用边界与限制；[公开入口](../src/index.ts)。

## 职责

`@lazygoal/process-runtime` 拥有 `ProcessManager`：按注入的进程存储 Port 与本次 `hostInstanceId` 启动、观察、停止并清理本实例实际创建的子进程。它只依赖 [Goal Runtime](../../runtime/README.md) 的 `ProcessSessionStore`/记录类型与资源契约，以及 [沙箱执行](../../sandbox/README.md) 的受限 spawn 与进程组终止能力；不依赖 Agent、LLM、Tool、Storage 实现或应用，不解析环境配置，也不选择数据目录。

管理器不构造 Goal、工具注册表或 HTTP 服务。`goalId` 是调用方提供的会话归属键，用于额度与读取隔离，不授予业务权限；沙箱策略、环境变量和权限仍由调用方（当前为 [内置工具](../../tools/README.md) 的进程工具）准备。管理器不扫描系统 PID、不重连或终止历史 PID，也不把会话记录当成 Goal 恢复或完成证据。

## 生命周期与结算

`startProcess` 在首次异步存储前同步受理并预留本次启动：额度覆盖已受理未结算启动与活跃句柄，每 Goal 4 个、宿主 16 个活跃进程与每 Goal 32 项历史记录上限在并发预留下仍准确，超出即拒绝，不排队。初始记录先于创建子进程保存；取得句柄后立即安装输出与退出监听，再异步结算 `running` 记录。同一会话由唯一所有者串行写入记录，迟到 `running` 不会覆盖终态；历史上限结合已确认磁盘记录与未落盘预留判定，不重复计数同一会话。stdout/stderr 按通道追加到注入 Store，具体解码、轮转与绝对字节游标由 [持久化实现](../../storage/README.md) 拥有。

关闭在受理后的每个异步边界被重新检查：尚未创建进程的启动被拒绝，已写记录用现有状态结算，已创建句柄纳入同一次清理。`stopProcess` 只对本实例持有的句柄发送进程组信号；没有活跃句柄的历史记录按现有读取语义返回，不重新获得 OS 控制权。`close`/`forceClose` 停止新启动受理并请求清理全部自有句柄，重复调用复用同一过程；`forceClose` 可在正常关闭等待期间升级终止，不等待 Store 写入成功。管理器不关闭借用的 Store、注册表或其它资源，也不自行退出宿主；实例级关闭期限与结果汇总由宿主生命周期所有者决定。已知失败使用 `ProcessSessionError` 携带阶段分类、会话身份与原始原因；清理步骤自身的故障保留在 `cleanupError`，不覆盖原始故障。

## 当前限制

额度只保证单个管理器范围：当前一个宿主装配一个管理器，不承诺多个管理器或共享注册表之间的全局配额。跨宿主的旧记录只由 Store 投影为 `interrupted`，不清扫、不重连。`waitForOutput` 只负责唤醒等待者，不证明日志已写入，读取仍以 Store 为准。
