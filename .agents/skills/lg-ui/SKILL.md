# lg-UI

面向管理 Goal、查看执行进度和处理授权的用户，优先让操作、状态和信息层级清楚。以下规则用于当前任务涉及的界面，不因加载本技能而扩大改动范围。

## 组件与样式来源

- 遵循根 `AGENTS.md`，优先复用现有组件和 shadcn/ui；涉及组件实现时同时使用 `shadcn` 技能。
- 从当前主题和组件查找已有实现，优先修改其来源，避免叠加相互覆盖的样式。主要入口为 [主题映射](../../../apps/goal-board/src/ui.css)、[共享样式](../../../apps/goal-board/src/style.css)、[工作区样式](../../../apps/goal-board/src/workspace.css) 和 [轨迹样式](../../../apps/goal-board/src/trajectory.css)。
- 文案同时遵循 [lg-prose-standard](../lg-prose-standard/SKILL.md)。本技能中的界面约束优先于通用设计技能中的装饰性建议。

## 配色

- 使用 Radix Colors，通过现有语义变量管理背景、文字、边框、交互和状态颜色。保留 LazyGoal 的绿色(或开发者后续加入的新主题色)品牌方向，不在组件中散落硬编码色值。
- 按官方色阶用途区分默认、悬停、按下、选中、禁用和聚焦状态，并检查实际前景与背景组合的对比度；不能仅凭色阶编号认定可读。
- 成功、警告、失败和品牌选中态应有明确语义。状态同时有文字或图标表达，避免只靠颜色区分。
- Logo、图片及用户内容自带的颜色保持原样，不机械替换为主题色。

## 字号与层级

- 默认只用三档字号：12px 辅助信息、14px 正文与主要控件、18px 页面与弹窗标题。使用共享字号变量和对应的 Tailwind 映射。
- 可用文字最小为 12px，包括代码、轨迹记录、徽标和表单提示。不要通过缩小字号来容纳更多内容。
- 优先用字重、字体颜色、间距、留白和分组表达层级。确有功能需要时最多四档；不要为单个组件随意增加字号。
- 浏览器核对实际计算字号，兼顾 `font` 简写、继承、断点和组件默认样式，不能只统计 `font-size` 声明。

## 对齐、边框、圆角与阴影

- 以共享内容边缘、文字基线和图标视觉重心建立光学对齐。结合截图判断，不仅依赖盒子几何中心；图标偏移不应缩小点击区域。
- 同一操作行的控件应有协调的高度与对齐方式。窄屏允许合理换行，不得造成文字、状态、日期或操作相互挤占、裁切。
- 使用线条、边框或聚焦轮廓时统一为 0.5px，包含分隔线和通过伪元素、阴影模拟的线条。同步处理 CSS 和组件工具类；注意普通屏与高像素密度屏的渲染差异。
- 圆角和阴影需要服务于功能。普通内容优先通过间距和分隔组织，不习惯性套圆角卡片；卡片、按钮和输入框不默认带阴影。
- 禁止用卡片左侧彩色线条作装饰。状态可用文字、图标和克制的浅色背景表达；表示层级的连接线或时间轴选区边界按其功能判断。
- 菜单、弹窗和抽屉可用轻量阴影区分浮层，数值应与浮层尺度相称，避免大范围浓重投影。
- 相邻嵌套圆角尽量同心：外圆角 = 内圆角 + 内距 + 外层边框宽度。先确定是否需要圆角，再计算关系，不为满足公式给所有容器添加圆角。
- 复合输入控件只在外层容器表达聚焦，内部文本框不再出现独立矩形轮廓或阴影。至少检查消息输入区、模型搜索框和鼠标、键盘聚焦路径。

## 文案与小标签

- 界面文案使用英文，面向实际操作用户，清楚、克制、易理解，长度与控件或场景相称；避免过于口语化的表达、随意造词和实现视角术语。
- 不使用中点 `·` 连接界面文案。通过布局、间距、换行或完整短语表达信息关系。
- 不添加冗余解释：标题、按钮和当前状态已经表达的信息，不再用副标题、说明段或空白状态正文复述。只保留影响操作判断的限制、后果或恢复方式。
- 删除重复或纯装饰的 Eyebrow / Overline。只有小标签提供主标题没有表达的分类、上下文或关键信息时才保留；不默认使用英文全大写或装饰性字距。
- 操作名称描述实际行为。例如重新读取模型输入记录用 `Reload`，避免让用户误以为会重试模型请求；权限选项用 `Ask when needed` 和 `Auto-approve`，保留必要的沙箱限制信息。
- 技术记录保留比较对象、状态和必要限制，删除面向用户无用的 Diff 算法、Adapter、Snapshot 等实现过程说明。

## 涉及 Activity 展示时

- 保留 Run → Stage → Activity 层级。Stage 来自 Runtime 的真实阶段；不要根据相邻位置猜测工作意图，也不要放宽助手消息、阶段边界和不可验证间隔对分组的打断规则。
- 优先使用现有明确标识关联事件，例如用 `lookupId` 将历史检索请求和结果显示为一个活动。检索失败与完成但未找到结果必须是不同状态。
- 使用服务端 `stages`、`actionGroups`、阶段 `target` 和 `completeWithinPage` 恢复跨页上下文。未完整加载时给出简短状态提示，不把局部记录展示为完整活动，也不添加长篇解释。
- 跨工具工作活动需要 Runtime 提供 `activityGroupId` 或等价的明确标识，不使用 LLM 或前端相邻位置推断关联。
- 工具标题用确定性规则概括实际操作，例如 Git 状态、Diff、提交历史或测试；未知命令使用通用标题。完整命令、授权、重试、结果、错误和 Trajectory 入口放到展开详情中。
- 活动摘要与技术详情分开。成功活动默认折叠；运行中、失败和等待处理的活动保持可见、可展开。关闭执行详情时隐藏普通过程记录，保留等待授权、失败、拒绝等重要状态。

## 验证与交付

根据实际改动选择现有构建、测试和浏览器检查，检查桌面与窄屏下的长文本、换行、溢出、点击区域及相关交互状态。配色调整检查对比度，字号调整检查计算字号，聚焦调整同时检查内外层样式。

验证当前真实界面，不把本技能当作已有实现全部合规的证明。浏览器验证优先使用只读操作；需要写操作时使用隔离测试数据，或依据已有明确授权执行。交付时用源码位置说明改动与已完成的验证；提交和推送遵循用户授权。
