# Goal Board

React 浏览器前端，呈现已提交会话及临时活动。通用 UI 采用 shadcn/ui（Radix 底座），按 [组件配置](../components.json) 将官方组件源码保存在 [components/ui](../src/components/ui/button.tsx)，由 Tailwind CSS 与 [品牌主题](../src/ui.css) 统一外观。业务状态仍由既有 Hooks、Context 和纯投影持有；通用弹层、菜单、单选、复选和折叠交互使用库组件。仅轨迹时间轴、记录网格、检查器分栏、详情正文、Markdown、像素动画及业务布局保留专用实现。

## 界面配色

配色从 `@radix-ui/colors` 的浅色标准色阶导入：Sage 提供中性色，Mint 提供品牌与交互色，Green、Amber、Ruby 提供成功、警告、错误色，Violet 区分模型事件。色阶在 [ui.css](../src/ui.css) 导入并映射到 shadcn 主题；[style.css](../src/style.css) 持有业务语义变量，组件通过这些变量取色。背景、悬停和选中使用不同色阶，聚焦环独立于选中边框；实色 Mint 按钮使用深色前景，错误按钮使用 Ruby 11／12 配浅色字，以满足小字号文字对比度。遮罩和阴影使用官方透明色阶。Logo、图片及用户内容不参与颜色替换，当前仍只提供浅色主题。

## 职责与使用

通过本模块的公开入口使用上述能力。状态或副作用由调用方在所属边界控制。

Goal Board 只消费 `@lazygoal/web-contracts` 导出的 DTO 与生成绑定，不导入 Contract AST 或 JSON Schema。响应未知字段在 API 边界剥离并通过有界诊断报告；Trajectory payload 等开放字段以只读记录视图展示，任意附加字段不会进入业务状态。

## 边界与限制

本模块不替代其依赖模块的协议或持久化职责；具体输入、失败语义与类型以链接的源码契约为准。

## 页面交互

Activity 页以服务端固定水位窗口中的来源位置交错显示已提交消息、公开活动事实、Run 边界与终态。助手正文按安全 Markdown 边界渲染，用户正文按纯文本展示；阶段目标只来自已提交的阶段声明 DTO。公开生成按来源显示：普通正文增量留在当前 Run 的临时区域；完成候选使用其稳定身份显示完整预览。`message_committed` 只启动保存核验，只有固定 Activity 页出现同 Run、同 `previewId` 的已保存消息才会在相同展示 key 上替换预览并显示规范正文。明确作废的候选立即从临时显示中移除，并保留有限身份标记以忽略迟到片段。刷新、切换 Goal 或重建 SSE 连接会清除候选临时正文，已保存内容仍从 Activity／状态重新读取。模型正文、阶段接受和过程消息都不推断为 Run 完成；页面不读取供应商隐藏推理。

工作区外壳保留 LazyGoal 的白色薄荷绿主题和原始 Logo。侧栏以紧凑行提供工作区详情、搜索、新建 Goal、Goals 与最近八个未归档会话入口；最近列表沿用服务返回的顺序，可展开或收起，选中项显示当前位置。搜索支持 Cmd/Ctrl+K 打开、按标题过滤当前已读取的全部 Goal（含已归档项）、方向键选择、Enter 打开与 Escape 关闭；关闭后恢复原先焦点。工作区详情只展示当前目录和分支，不切换执行位置。侧栏底部的 Settings 入口提供 Provider 管理与 Appearance 设置。切换设置页时保留已挂载会话及草稿；返回恢复原视图，选择 Goal、搜索结果或新建 Goal 会离开设置页。页面选择不持久化，刷新回到 Goals。侧栏通过主内容顶部的固定按钮完全隐藏或展开；隐藏后内容占满可用宽度，不保留图标栏。桌面侧栏右边缘支持拖动调整宽度，范围为 200–420px，并按窗口宽度为主内容预留空间；方向键微调，Home/End 调到边界，双击恢复默认 240px。宽度仅保存在当前页面，隐藏再展开保留，刷新重置。窄屏默认隐藏，展开时使用带焦点隔离的模态抽屉，点击背景、按 Escape 或选择导航项后关闭。项目名称与路径来自当前服务的工作区查询，仅展示当前执行目录，不提供多项目切换或多标签。看板使用等高列标题、浅底列容器和白色卡片；内容超出宽度时在看板内部横向滚动。阶段分组保留现有展开交互并显示明确的标题与状态。

Appearance 的 Activity width 可选 Standard（可用宽度的 85%，最小 480px、最大 840px）或 Wide（填满可用空间），同时作用于 Activity 内容和消息输入区。可用宽度不足 480px 时两种设置都填满可用空间。选择保存在当前浏览器的同主机 Cookie 中，服务使用新端口时仍可恢复；Cookie 不可保存时当前页面仍会应用选择，并提示刷新后重置。

`GET /api/project/workspace` 在同一访问边界内读取 Composition Root 的执行工作目录和当前 Git 分支、worktree 根路径；非 Git 工作区及 detached HEAD 明确区分。所有本机 Goal 共用启动工作区，这些值不表示 Goal 创建时的历史绑定。页面在打开会话、已提交会话刷新及重新获得焦点时读取位置，并在会话顶栏的紧凑一行中展示分支与 worktree；完整路径可悬停查看。

React 看板源码位于 [`apps/goal-board`](../README.md)，由 `WorkspaceShell`、会话 Context、业务组件和自治 Hooks 组成。`useGoalSession` 维护固定水位 Activity 与按需完整会话，当前 Goal 状态从控制 reducer 读取；`useRunStream` 负责 SSE 重连与临时正文；`useRunCommands` 提交支持的创建、结构化回答、停止与恢复命令。New Goal 的输入框只提交首个意图、稳定 `inputId` 和选定模型，成功后不再提供普通续聊、Steer 或队列控制。已有 Goal 只显示结构化等待项、Worker 运行状态、停止操作或可用的恢复操作。恢复运行中检查点会先展示未知副作用确认，确认后才通过 Trigger 提交决定。页面的状态、授权、模型、Activity 与轨迹读取仍来自同源受保护 API；Goal SSE 先给出 `state_sync`，断线重连重新读取服务端权威状态。

Goal 范围事件与 session metrics 两条 SSE 共用 [`readSseMessages`](../src/sse.ts) 分帧入口：`eventsource-parser` 的 `EventSourceParserStream` 与 `TextDecoderStream` 负责跨 chunk 行拼接、CRLF／LF／单独 CR、注释与多行 `data:`，事件名称映射与 DTO 校验留在 [`api.ts`](../src/api.ts)。Goal 事件接受 `update` 与未命名默认事件，metrics 只接受 `snapshot`；未知命名事件忽略，已接受事件的无效 JSON 或无效 DTO 结束本次生成器并按协议错误处理。`useRunStream` 与 `useGoals` 的 800ms 重连循环随后重新订阅；重连不发送 `Last-Event-ID`、不请求服务端补发，新连接以首个 `state_sync` 或最新指标快照恢复权威状态，并清空旧连接遗留的临时进度与未提交正文。

窄 HTTP 状态与 `state_sync` 共用控制快照接纳入口。切换或关闭 Goal 结束当前观察，后续重新打开同一 Goal 使用新视图代次。已结束观察的读取结果、错误与流事件不参与当前视图。Activity、Trajectory 和完整历史沿用各自的 Run、cursor 与查询水位。

未限定 execution unit 的轨迹列表按服务端 cursor 每段最多读取 100 条。首屏固定该 Run 的 `committedThroughSequence`，后续段与详情复用同一水位；游标由服务端签发并绑定 Run、水位与过滤条件，客户端不改写可见边界。左右箭头在相邻段之间移动，已读取的相邻段最多保留 3 段；移出窗口的段返回时按 cursor 重读，使事件列表与内存中的页数据都有界。页脚显示当前导航段末的匹配事件序数/总量，返回上一段时序数随之回退。切换段时滚动到该段第一条实际渲染的事件，跳过列表隐藏的边界事件。限定 execution unit 的轨迹视图不提供跨段导航。

首屏 Activity 查询从文件来源构建一个固定水位、有界页；打开后自动预取更早页直到 300 项预算，超出预算后滚动到顶部时继续按 cursor 读取。读取期间顶部显示只读加载提示；仍有更早页时可通过页面控件或滚动到顶部续读，阅读位置由稳定锚点保持。实时文本增量先进入按帧合并缓冲再提交渲染，跟随滚动以帧节流，流结束后逐字一致（[live-text-batch](../src/live-text-batch.ts)）。会话内容区与 Trajectory 视图的渲染异常由 SessionBoundary 捕获：在视图内显示错误摘要与 Reload session 入口，错误与组件栈进入控制台，顶层 shell 不受影响（[error-boundary](../src/components/error-boundary.tsx)）。

轨迹页将同源 API 的 Run、事件摘要、事件详情及独立保存的模型输入呈现为 50px 三轨概览、按 Step 分组的事件列表和互斥详情侧栏。Run 选择器首屏读取 100 条并提供 `More runs` 增量加载；头部已提交事件总数来自服务端 timeline 聚合，概览轨道本身仍只覆盖当前事件页。概览默认使用 Sequence 等宽投影，可切换为按记录时间映射全宽的 Time 模式；轨道始终填满可视宽度，Sequence 滚轮以指针为锚点放大（1–4×）且不会缩到 Fit 以下，右键拖拽平移，水平拖拽选择连续事件范围，所选类别与范围之外的事件弱化显示。Compact 只把事件块收窄为 8px 标记，不缩小轨道宽度。模型输入按调用折叠为一条 Prompt 记录，消息正文只在模型输入检查器中展开；列表列序为序号、事件、时间、摘要。当前已加载事件中，Step 起点到下一个 Step 或 Run 终态之间的无 Step 摘要也归入该可折叠区段，之前和之后的 Run 事件保持普通行。该归组只用于显示，不回写 Step 索引。折叠状态由组首记录标识，分页扩展时不会转移到另一个组；程序内工具事件仅在摘要提供父 Action 与调用索引时缩进，并保留原始详情可查。类别过滤、范围筛选、模型输入详情、重试组和跨段分页继续使用现有查询与读取边界；筛选或折叠隐藏选中事件时关闭对应详情。详情侧栏在窄屏下以对话框语义覆盖记录列表而不是压缩列表高度；Escape 或关闭按钮退出并把焦点还给触发行。Trajectory 页不渲染输入区，只保留前往 Activity 的消息入口。

看板通过受同一 Bearer 令牌保护的 [`session-metrics` 查询路由](../../../packages/session-metrics/notes/overview.md)读取各 Goal 的累计指标；已选 Goal 额外订阅指标 SSE。卡片展示 Goal 汇总；会话输入区下方以独立紧凑行展示 Goal 累计轮次、Step、模型用量、端到端输出速率、缓存命中率与当前模型上下文余量；窄屏在该行内横向滚动。点击 Goal metrics 打开 Popover，查看当前 Run 状态、完整指标与计量说明。输出速率在每条模型调用结束事实写入后更新，运行中的调用不参与速率计数；卡片与展开后的指标详情保留测量及排除调用数。未上报用量和不可计算的缓存命中率、输出速率、上下文余量显示为缺失值；部分用量覆盖单独提示，不将缺失值计为零。输出速率的计时范围和聚合规则由会话指标模块定义。

待处理交互由统一的交互区域承载，按已提交等待的种类、稳定引用与可用决定分派具体视图，整体替换旧的 AskUser／任务批准／工具批准表单：标题、请求正文与决定区都在 Activity 正文列内，停止 Run 是独立可达的操作，不使用阻塞模态弹窗。

问答视图提供问题导航与已答状态、单选／多选、逐题 Other 与提交前的完整答案审阅；整体回复是并列模式，切换时保留两份草稿且只提交当前方式。跳过以独立次操作展开后果并要求显式确认；文本框的 Enter／Escape 不隐式提交、批准、跳过或停止。任务审批在决定前展示完整目标、验收条件与完整有序候选阶段，批准是明确操作，非空反馈使提案失效后重新规划，反馈不构成批准。工具／沙箱审批在决定前按稳定引用读取并展示完整 canonical 输入、申请能力与授权期限，默认只批准本次；持续授权受完整审阅与既有可用性限制，拒绝必须携带非空理由。未知结果使用独立标题与「可能已执行、重试可能重复效果」警示，只提供单次 Retry action 与拒绝，不提供参数编辑或持续授权。详情读取失败时保留等待并禁用依赖完整范围的决定，不静默降级为批准。

交互决定经统一 `respond` 提交，页面区分编辑、提交中、待核验、已受理与失效：结果不明时冻结原 `inputId` 与载荷，只按原身份核验或重试；明确拒绝保留草稿并释放身份，后续新决定使用新身份；其他客户端已结算或出现新请求时，旧草稿不再可用。等待期间不接受普通续聊，当前 Goal 仍由原 Worker 持有；交互处理成功后 Activity 暂存非权限决定摘要，工具／沙箱授权及修订授权不进入输入区历史摘要。页面级摘要不跨刷新，也不把答案或完整参数镜像到 localStorage。

Activity 时间线在执行事件之前独立显示当前获批 Plan Run 的完整路线，包括阶段顺序、目标、验收条件、待执行/执行中/已接受状态及最近修订理由；该列表独立于执行事实展示。普通 Run 不显示路线列表；既有 Trajectory 活动仍单独可查。视图仅消费服务端的路线 DTO，不改变 Runtime 状态。

`npm run dev:web`（或 `npm run dev --prefix apps/goal-board`）只启动无后端授权的布局预览，不代理正式 Runtime API。真实操作须先构建静态页（`npm run build:web`），再从 `lazygoal web` 打印的本机入口打开。全局设置页仅管理受管 Provider 档案；页面不提供模拟 Goal、示例计划、虚构完成状态或项目分配。

已有会话刷新失败时，页面保留最后保存的消息、等待表单和当前草稿，并显示错误及重试入口；刷新错误期间禁用会话提交，成功读取最新快照后恢复。只有首次读取尚无会话时，错误才替代会话内容。SSE 暂无活动事件本身不表示保存的会话不可操作。

Goal 列表读取失败仍显示整页错误并提供重试；但当服务端报告部分历史 Goal 因本地快照与当前协议不兼容而无法读取时，看板保留可读 Goal 并在列表上方显示说明条，说明列表不完整，而不是让一条旧快照使整个看板不可用。

Activity 保持 Run、真实 Stage、Activity Group 三层：Run 承载整体状态与历史，Stage 只对应 Runtime 的计划阶段，Activity Group 承载工具操作及已有明确关联的调用。无真实 Stage 的工具活动直接位于 Run 下；助手消息、阶段边界和无法验证的来源间隔继续断组。

[`ActivityProjector`](../src/activity-projector.ts) 从固定 Activity 页与安全实时事件派生活动组；[`SessionTimeline`](../src/components/SessionTimeline.tsx) 保持真实来源顺序。同一 Action 的决策、审批、执行、重试与结果事实先按 Action 身份归入一个成员，授权申请、批准、重试与结果只在展开详情中显示；正在等待授权的组保持展开并明确显示 `Awaiting approval`。连续同阶段、同工具调用以工作描述为标题，以调用次数为辅助摘要，混合失败组同时保留成功与失败计数，完整结果计数在展开详情中显示；调用次数不代表不同文件数。失败后仍可合并连续同工具调用，但消息、不同 Action、阶段及来源缺口继续断组。运行状态与异常计数独立：有失败的组仍可正在执行，成功与失败并存的结算组显示部分失败。真实 Stage 标题来自服务端阶段上下文、已提交声明或获批路线，按 Run 与阶段身份关联。声明不在当前页时仍可恢复历史阶段标题；阶段和 Action 的 `completeWithinPage` 为 false 时，折叠状态也显示 `Details not fully loaded`。相邻页合并时保留上下文，加载齐来源跨度后清除提示。

所有 Run 的执行记录默认展开；折叠后只保留 Run 标题行，不再按来源类型保留部分内容。展开或折叠选择按 Run 身份保留，追加内容与结算不覆盖用户选择。运行或需处理的活动默认展开，成功活动及已接受阶段默认折叠；手动开合选择按稳定身份保留，异常计数和摘要不受折叠隐藏。展开成员可查看安全摘要、Think、授权／执行／重试／结果生命周期和来源，并定位 Trajectory 的真实执行单元。历史失败行仅使用同 Run 的安全终态摘要，缺失时明确不可用；数据边界见 [Browser Activity](../../../packages/browser/notes/overview.md)。

历史检索请求与结果按同 Run 的 `lookupId` 显示为一条活动，位置取最早已加载事实；展开显示安全请求类别、结果状态与白名单错误码。未命中表示检索完成但没有记录，失败表示检索未完成；只有单侧事实位于当前窗口时仍保留同一活动身份，不猜测缺失的请求或结果。

步骤折叠详情区分模型等待、正文生成、响应处理和工具活动，连接内最多保留二十条公开事件。来源开始时间与浏览器观察时间分别标注；正文分片只更新最近响应时间，不重置开始计时。模型连续六十秒无新公开响应时显示提示，心跳不算进展，不自动重试或取消。断线显示最后观察状态，重连清空旧连接的临时进度，Run 结束后停止动画和计时，不读取隐藏推理。

Activity 与输入区宽度由 Appearance 的 Activity width 控制，正文／活动标题／辅助字号为 14／13／12px。自动滚动状态由 Activity 窗口唯一持有：距底部 60px 内跟随；可滚动内容展开详情时暂停，短内容开合不暂停。当前窗口已到来源末尾时，暂停滚动仍会并入新回答、事实及 Run 状态；历史窗口仍有更新方向缺口时只累计提示，直到显式加载或跳转到最新。稳定来源锚点用于恢复分页和布局变化后的阅读位置。新消息以未读数及 Jump to latest 提示，重复刷新不重复计数。底部指标独立成行，Goal metrics 的 Popover 区分当前 Run 状态与 Goal 聚合指标，并展示缺失值、覆盖率及计量范围说明。New Goal 输入区只提交首个意图；已选 Goal 只显示结构化交互、停止与显式恢复操作。

## 控制 reducer

[`useControlIntents`](../src/hooks/useControlIntents.ts) 持有页面唯一的 `ControlState`：`snapshot`、`intents`、`toolActivities`、`resources` 与 `connection`。所有 Goal／Workspace 变更命令以 [`BrowserControlIntentCommand`](../../../packages/web-contracts/src/wire.ts) 提交到 `POST /api/control`，并在 [`reducer.ts`](../src/control/reducer.ts) 中按受理收据与 Runtime 事实流转 `pending → accepted → applied` 或 `rejected`／`unknown`；同一个 `intentId` 只保留首次冻结载荷。同步提交类命令在受理后直接完成，`create_session`、`session_input` 与只读 `action_review` 等待应用事实。

命令钩子不再分别维护 busy／unknown 状态：按钮忙碌态从待处理意图派生，结果不明时展示可由 [`verify.ts`](../src/control/verify.ts) 按既有资源身份核验的原身份记录；只有 `not_applied` 允许以同一身份重试，`applied` 结算为成功，读取失败保持 `unknown`。模型选择与默认偏好是一次 `model_selection` 命令，receipt 分别报告 `selection` 与 `defaultPreference`，部分成功保留同一意图身份重试。

`ApprovalSession` 与 `ToolActivity` 是纯 selector：审批阶段由 `pendingAction`、最近 `action_review` 意图与关联 `respond` 提交派生；工具活动以 `actionId` + `executionUnitId` 聚合尝试，工具返回停在 `result_pending`，只有 Observation 提交事实进入 `observed_committed`。窄 HTTP 和 SSE 只在当前 Goal 内比较 `commitRevision`，后继 Run 继续沿用同一修订序列。等待与终态增量触发窄状态确认，`state_committed.changed` 与 `stream_fault.resync` 触发对应投影定向读取。重连保留最后确认的内容和草稿。组合快照或恢复窄读取达到当前连接声明与已知提交修订后才恢复同步。审批预检按发起视图、Run 和等待身份使用。

实时进度按真实 `executionUnitId`／`actionId` 归入事件或工具步骤的折叠内容，不设独立进度面板。尚无已保存节点的真实执行单元先显示为当前 Run 内的临时步骤；没有执行身份的事件不按相邻位置猜测归属。连续执行节点使用 shadcn Trace，消息和待用户处理的交互断开步骤组；Run 使用独立的浅色标题条。实时正文在首次产生时确定位置，工具调用或新的模型阶段会关闭当前块，恢复输出创建新块；进度、正文与工具节点按同一首次出现顺序追加，已显示节点不因后续事件重排，只有当前活跃块显示流式光标，Run 到达终态后由已提交历史接管。单成员工具组的详情不重复组标题与成员状态。事件标题保持可见，诊断与进度在折叠内容内查看。Bash 标题由活动投影按简单命令前缀确定：Git 工作区、提交历史、代码变更和常见测试命令各有固定标题；复杂 Shell 表达式及未知命令使用 `Run shell commands`。连续 Bash 调用组合至多两种不同操作并提示其余操作数量，调用次数仍由辅助计数显示。服务端提供的有界命令摘要与执行结果只在成员详情中换行显示，超出服务端上限的原始命令通过 Trajectory 查看；计数、异常状态与展开按钮保持对齐。等待或终态后不再显示临时进度；已提交的完整历史由 Trajectory 提供，缓存事件不决定 Run 状态。

## Provider 设置与来源选择

设置页（`SettingsPage`）以紧凑行列出受管 Provider 名称、供应商、默认模型与激活标记；凭据圆点仅表示是否已保存密钥，不表示连接正常。`config.toml` 来源作为普通只读行展示。添加入口默认收起，展开后区分内置供应商和自定义 OpenAI-compatible API；后者要求 API 地址，不提供后端未支持的协议或模型目录编辑。每次只展开一个添加或编辑表单，高级参数默认折叠。表单从不回显已保存的明文密钥，编辑时留空保留原凭据；创建或更新成功后收起，失败保留草稿。取消后返回触发按钮。更多操作提供模型目录检查、激活与删除；目录检查结果仅说明目录可用性，不宣称推理调用成功。激活档案不可删除，删除其它档案需在行内确认并提示引用它的 Goal 在恢复时需要重新选择。写入期间锁定表单与档案操作，失败以稳定错误码呈现。

模型选择器（`ModelPicker`）在目录提供多个来源时先选 Provider 再选模型；切换来源即按 `providerProfileId` 重新读取该来源目录。两级选择结果分别写入草稿默认偏好（含来源标识）或 Goal 模型选择（含来源标识，仍受既有安全点约束）。

Provider 表单的 Fetch models 使用当前供应商、端点和密钥查询在线列表，无需先保存档案或填写默认模型。浏览器 API 通过 [`web-contracts` 绑定](../../../packages/web-contracts/src/generated/provider-models-binding.ts)校验响应并剥离未知字段；编辑时密钥留空可复用同一供应商档案的凭据，结果仅保存在编辑器中，选择后填入默认模型，仍允许手填。连接字段变化、关闭编辑器或卸载会取消查询并丢弃旧结果；空列表和失败就地提示，不触发保存或生成请求。
