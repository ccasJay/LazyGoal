# Goal Board

React 浏览器前端，呈现已提交会话及临时活动。通用 UI 采用 shadcn/ui（Radix 底座），按 [组件配置](../components.json) 将官方组件源码保存在 [components/ui](../src/components/ui/button.tsx)，由 Tailwind CSS 与 [品牌主题](../src/ui.css) 统一外观。业务状态仍由既有 Hooks、Context 和纯投影持有；通用弹层、菜单、单选、复选和折叠交互使用库组件。仅轨迹时间轴、记录网格、检查器分栏、详情正文、Markdown、像素动画及业务布局保留专用实现。

## 职责与使用

通过本模块的公开入口使用上述能力。状态或副作用由调用方在所属边界控制。

## 边界与限制

本模块不替代其依赖模块的协议或持久化职责；具体输入、失败语义与类型以链接的源码契约为准。

## 操作说明

运行前提、命令和结果示例见 [使用说明](./usage.md)。

## 页面交互

Activity 页以服务端固定水位窗口中的来源位置交错显示已提交消息、公开活动事实、Run 边界与终态。助手正文按安全 Markdown 边界渲染，用户正文按纯文本展示；阶段目标只来自已提交的阶段声明 DTO。公开生成按来源显示：普通正文增量留在当前 Run 的临时区域；完成候选使用其稳定身份显示完整预览。`message_committed` 只启动保存核验，只有固定 Activity 页出现同 Run、同 `previewId` 的已保存消息才会在相同展示 key 上替换预览并显示规范正文。明确作废的候选立即从临时显示中移除，并保留有限身份标记以忽略迟到片段。刷新、切换 Goal 或重建 SSE 连接会清除候选临时正文，已保存内容仍从 Activity／状态重新读取。模型正文、阶段接受和过程消息都不推断为 Run 完成；页面不读取供应商隐藏推理。

工作区外壳保留 LazyGoal 的白色薄荷绿主题和原始 Logo。侧栏以紧凑行提供工作区详情、搜索、新建 Goal、Goals 与最近八个未归档会话入口；最近列表沿用服务返回的顺序，可展开或收起，选中项显示当前位置。搜索支持 Cmd/Ctrl+K 打开、按标题过滤当前已读取的全部 Goal（含已归档项）、方向键选择、Enter 打开与 Escape 关闭；关闭后恢复原先焦点。工作区详情只展示当前目录和分支，不切换执行位置。侧栏底部的 Settings 入口打开 Provider 设置页，提供受管档案列表与按需展开的编辑器。切换设置页时保留已挂载会话及草稿；返回恢复原视图，选择 Goal、搜索结果或新建 Goal 会离开设置页。页面选择不持久化，刷新回到 Goals。侧栏通过主内容顶部的固定按钮完全隐藏或展开；隐藏后内容占满可用宽度，不保留图标栏。桌面侧栏右边缘支持拖动调整宽度，范围为 200–420px，并按窗口宽度为主内容预留空间；方向键微调，Home/End 调到边界，双击恢复默认 240px。宽度仅保存在当前页面，隐藏再展开保留，刷新重置。窄屏默认隐藏，展开时使用带焦点隔离的模态抽屉，点击背景、按 Escape 或选择导航项后关闭。项目名称与路径来自当前服务的工作区查询，仅展示当前执行目录，不提供多项目切换或多标签。看板使用等高列标题、浅底列容器和白色卡片；内容超出宽度时在看板内部横向滚动。阶段分组保留现有展开交互并显示明确的标题与状态。

`GET /api/project/workspace` 在同一访问边界内读取 Composition Root 的执行工作目录和当前 Git 分支、worktree 根路径；非 Git 工作区及 detached HEAD 明确区分。所有本机 Goal 共用启动工作区，这些值不表示 Goal 创建时的历史绑定。页面在打开会话、已提交会话刷新及重新获得焦点时读取位置，并在会话顶栏的紧凑一行中展示分支与 worktree；完整路径可悬停查看。

React 看板源码位于 [`apps/goal-board`](../README.md)，构建后输出到 `apps/goal-board/dist`，由上述同源静态路由提供；若产物未构建，服务分发内置引导页面提示执行 `npm run build:web`。源码采用职责明确的轻量架构：入口 `src/main.tsx` 只负责挂载，`src/components/WorkspaceShell.tsx` 装配侧栏、设置页与内容区，并保留会话内容的顶层渲染错误边界；`GoalSessionContext` 分别持有不含历史的 Goal 状态、固定水位 Activity 页和按需读取的完整会话；初次打开并行请求 `?view=state` 与 `/activity`，Plan、Trajectory 或 Goal details 视图再读取完整会话。指令调度与单飞锁排队状态机由 `RunControlContext` 隔离，避免全树重复渲染。网络流与状态流解耦为独立自治领域 Hooks（`useRunStream` 维护 SSE 重试与打字机聚合，`useGoalSession` 维护状态／Activity 同步、完整会话按需读取与草稿态，`useQueue` 只读取 Runtime 会话投影的已受理队列与暂停并提供单条删除和继续操作，`useRunCommands` 承载 Steer/Interrupt/Resume 统一分发降级）；样式入口包含 `ui.css`（Tailwind 与 shadcn 语义变量）、`workspace.css`（工作区与设置），以及 `style.css`（全局 token、看板与会话视图，含 `--font-size-xs/sm/base` 字号档位）与 `trajectory.css`（Trajectory 视图、50px 概览轨道与窄屏详情覆盖层）；视图层拆分为独立的 `GoalBoard.tsx`、`GoalSession.tsx` 及 `src/components/` 下的单职责子组件（`GoalCard.tsx`、`ModelPicker.tsx`、`MessageComposer.tsx`、`PermissionControl.tsx`、`WorkspaceContext.tsx` 等）。New Goal 先打开仅保存在页面状态的空白会话草稿；读取工作区默认模型后显示真实名称并允许发送，首条非空普通消息显式提交该草稿模型 ID，作为 Goal 意图和首条用户消息启动唯一 Run。草稿刷新即丢弃，不创建 Goal 或启动模型。页面复用 Slash Command Registry 识别 `/plan` 与 `/model`：前者设置创建模式或提交 Plan Mode；后者打开当前 Provider 的模型选择器，草稿明确选择会立即持久化为工作区偏好，已有 Goal 在安全文本等待点或 completed/failed/cancelled 终态提交到服务端。运行期间输入框可编辑：Enter 发送排入下一 Run 的消息，Shift+Enter 换行；唯一主按钮在有正文时排队发送，输入为空时受理 Interrupt 并暂停 Run，运行中的动态提示显示在 Activity 时间线，停止受理时显示暂停进度。页面将 Runtime 已受理队列与待应用 Steer 合并到一个默认折叠的状态框：框内显示消息与队列状态，并为每条普通排队消息提供删除和转为当前 Run Steer 的操作；Steer 转换按队列修订原子消费原消息。草稿保存在输入框，提交中由按钮状态表达，队列正文、待应用 Steer、暂停原因与修订全部来自 `GET /api/goals/:goalId` 的安全会话投影，刷新、多标签与断线后由服务端恢复顺序；当前 Run 完成后由 Runtime 按序创建后继 Run，等待人工交互时不出队，失败或取消后暂停，用户显式继续才从原队首启动，单条删除只移除目标待处理消息。普通消息、Steer、Interrupt、交互回答、恢复与队列控制统一提交到 `POST /api/goals/:goalId/inputs`，由 Runtime 会话所有者受理与去重；命令文本本身不进入队列。页面通过 Bearer 头调用 Goal 列表、会话、创建（携带稳定首条 `inputId`）、统一 inputs、模型目录与选择、Plan Mode 和授权管理接口，并用同一授权边界订阅 Goal 范围实时事件；Fragment 凭据不会写入本地存储。模型选择器支持名称/标识搜索，使用 shadcn Dialog 隔离背景、限制键盘焦点，并将关闭焦点返回打开控件。模型目录请求随选择器关闭或目标变化而取消，迟到结果不会覆盖当前选择器；保存错误保留原选择及结构化等待表单内容。会话 Activity 页是单列来源流：正文与公开事实按服务端 Run 内位置排序、按稳定 `itemId` 合并，Run 与终态边界保留在来源之间；阶段接受等事实不会自行结束 Run。Plan 路线显示在当前 Run 边界，只有已提交阶段声明的公开 DTO 提供阶段目标。执行事实开关只筛选工具与操作事实，不隐藏消息、Run／阶段／终态边界。完整历史视图仍用于 Plan 与 Trajectory；完整消息和步骤不随首屏 Activity 请求下载。Goal 与 Workspace 授权可在会话头部的 Goal info 面板查看和撤销；切换 Goal 时清空旧授权列表。实时文本只显示当前 Run 的临时正文；状态刷新以服务端 Activity 与 Goal 状态为准。

未限定 execution unit 的轨迹列表按服务端 cursor 每段最多读取 100 条。左右箭头在相邻段之间移动，已读取的相邻段最多保留 3 段；移出窗口的段返回时按 cursor 重读，使事件列表与内存中的页数据都有界。页脚显示当前导航段末的匹配事件序数/总量，返回上一段时序数随之回退。切换段时滚动到该段第一条实际渲染的事件，跳过列表隐藏的边界事件。限定 execution unit 的轨迹视图不提供跨段导航。

首屏 Activity 查询从文件来源构建一个固定水位、有界页；顶部提示页外仍有更早来源，但当前页面不自动加载旧页。游标翻页与阅读位置保持由后续历史窗口任务负责。实时文本增量先进入按帧合并缓冲再提交渲染，跟随滚动以帧节流，流结束后逐字一致（[live-text-batch](../src/live-text-batch.ts)）。会话内容区与 Trajectory 视图的渲染异常由 SessionBoundary 捕获：在视图内显示错误摘要与 Reload session 入口，错误与组件栈进入控制台，顶层 shell 不受影响（[error-boundary](../src/components/error-boundary.tsx)）。

轨迹页将同源 API 的 Run、事件摘要、事件详情及独立保存的模型输入呈现为 50px 三轨概览、按 Step 分组的事件列表和互斥详情侧栏。概览默认使用 Sequence 等宽投影，可切换为按记录时间映射全宽的 Time 模式；轨道始终填满可视宽度，Sequence 滚轮以指针为锚点放大（1–4×）且不会缩到 Fit 以下，右键拖拽平移，水平拖拽选择连续事件范围，搜索、类别与范围之外的事件弱化显示。Compact 只把事件块收窄为 8px 标记，不缩小轨道宽度。模型输入按调用折叠为一条 Prompt 记录，消息正文只在模型输入检查器中展开；列表列序为序号、事件、时间、摘要。当前已加载事件中，Step 起点到下一个 Step 或 Run 终态之间的无 Step 摘要也归入该可折叠区段，之前和之后的 Run 事件保持普通行。该归组只用于显示，不回写 Step 索引。折叠状态由组首记录标识，分页扩展时不会转移到另一个组；程序内工具事件仅在摘要提供父 Action 与调用索引时缩进，并保留原始详情可查。搜索、类别过滤、范围筛选、模型输入详情、重试组和跨段分页继续使用现有查询与读取边界；筛选或折叠隐藏选中事件时关闭对应详情。详情侧栏在窄屏下以对话框语义覆盖记录列表而不是压缩列表高度；Escape 或关闭按钮退出并把焦点还给触发行。Trajectory 页不渲染输入区，只保留前往 Activity 的消息入口。

看板通过受同一 Bearer 令牌保护的 [`session-metrics` 查询路由](../../../packages/session-metrics/notes/overview.md)读取各 Goal 的累计指标；已选 Goal 额外订阅指标 SSE。卡片展示 Goal 汇总；会话输入区下方以独立紧凑行展示 Goal 累计轮次、Step、模型用量、端到端输出速率、缓存命中率与当前模型上下文余量；窄屏在该行内横向滚动。点击 Goal metrics 打开 Popover，查看当前 Run 状态、完整指标与计量说明。输出速率在每条模型调用结束事实写入后更新，运行中的调用不参与速率计数；卡片与展开后的指标详情保留测量及排除调用数。未上报用量和不可计算的缓存命中率、输出速率、上下文余量显示为缺失值；部分用量覆盖单独提示，不将缺失值计为零。输出速率的计时范围和聚合规则由会话指标模块定义。

待处理交互由统一的交互区域承载，按已提交等待的种类、稳定引用与可用决定分派具体视图，整体替换旧的 AskUser／任务批准／工具批准表单：标题、请求正文与决定区都在 Activity 正文列内，停止 Run 是独立可达的操作，不使用阻塞模态弹窗。

问答视图提供问题导航与已答状态、单选／多选、逐题 Other 与提交前的完整答案审阅；整体回复是并列模式，切换时保留两份草稿且只提交当前方式。跳过以独立次操作展开后果并要求显式确认；文本框的 Enter／Escape 不隐式提交、批准、跳过或停止。任务审批在决定前展示完整目标、验收条件与完整有序候选阶段，批准是明确操作，非空反馈使提案失效后重新规划，反馈不构成批准。工具／沙箱审批在决定前按稳定引用读取并展示完整 canonical 输入、申请能力与授权期限，默认只批准本次；持续授权受完整审阅与既有可用性限制，拒绝必须携带非空理由。未知结果使用独立标题与「可能已执行、重试可能重复效果」警示，只提供单次 Retry action 与拒绝，不提供参数编辑或持续授权。详情读取失败时保留等待并禁用依赖完整范围的决定，不静默降级为批准。

交互决定经统一 `respond` 提交，页面区分编辑、提交中、待核验、已受理与失效：结果不明时冻结原 `inputId` 与载荷，只按原身份核验或重试；明确拒绝保留草稿并释放身份，后续新决定使用新身份；其他客户端已结算或出现新请求时，旧草稿不再可用。等待期间仍提供明确标注为 Queue next task 的普通输入，它只进入 Runtime 队列、不回答当前请求；交互处理成功后 Activity 暂存非权限决定摘要，工具／沙箱授权及修订授权不进入输入区历史摘要。页面级摘要不跨刷新，也不把答案或完整参数镜像到 localStorage。

Activity 时间线在执行事件之前独立显示当前获批 Plan Run 的完整路线，包括阶段顺序、目标、验收条件、待执行/执行中/已接受状态及最近修订理由；该列表不依赖 Execution steps 筛选开关。普通 Run 不显示路线列表；既有 Trajectory 活动仍单独可查。视图仅消费服务端的路线 DTO，不改变 Runtime 状态。

`npm run dev:web`（或 `npm run dev --prefix apps/goal-board`）只启动无后端授权的布局预览，不代理正式 Runtime API。真实操作须先构建静态页（`npm run build:web`），再从 `lazygoal web` 打印的本机入口打开。全局设置页仅管理受管 Provider 档案；页面不提供模拟 Goal、示例计划、虚构完成状态或项目分配。

已有会话刷新失败时，页面保留最后保存的消息、等待表单和当前草稿，并显示错误及重试入口；刷新错误期间禁用会话提交，成功读取最新快照后恢复。只有首次读取尚无会话时，错误才替代会话内容。SSE 暂无活动事件本身不表示保存的会话不可操作。

Goal 列表读取失败仍显示整页错误并提供重试；但当服务端报告部分历史 Goal 因本地快照与当前协议不兼容而无法读取时，看板保留可读 Goal 并在列表上方显示说明条，说明列表不完整，而不是让一条旧快照使整个看板不可用。

[`ActivityProjector`](../src/activity-projector.ts) 从固定 Activity 页与安全实时事件派生活动组；[`SessionTimeline`](../src/components/SessionTimeline.tsx) 保持真实来源顺序。单次操作展示动作与对象，连续同阶段、同工具调用以工作描述为标题，以调用次数为辅助摘要，混合失败组同时保留成功与失败计数，完整结果计数在展开详情中显示；调用次数不代表不同文件数。失败后仍可合并连续同工具调用，但消息、审批、阶段及来源缺口继续断组。运行状态与异常计数独立：有失败的组仍可正在执行，成功与失败并存的结算组显示部分失败。真实 Stage 标题只来自已提交声明或获批路线，不由工具类型推断。

当前 Run 执行记录默认展开，历史执行记录默认折叠；用户消息与最终回答始终保持可读，过程消息随执行记录折叠。运行或需处理的活动默认展开，成功活动及已接受阶段默认折叠；手动开合选择按稳定身份保留，异常计数和摘要不受折叠或 Execution steps 筛选隐藏。展开成员可查看安全摘要、Think、重试和来源，并定位 Trajectory 的真实执行单元。历史失败行仅使用同 Run 的安全终态摘要，缺失时明确不可用；数据边界见 [Browser Activity](../../../packages/browser/notes/overview.md)。

步骤折叠详情区分模型等待、正文生成、响应处理和工具活动，连接内最多保留二十条公开事件。来源开始时间与浏览器观察时间分别标注；正文分片只更新最近响应时间，不重置开始计时。模型连续六十秒无新公开响应时显示提示，心跳不算进展，不自动重试或取消。断线显示最后观察状态，重连清空旧连接的临时进度，Run 结束后停止动画和计时，不读取隐藏推理。

Activity 与输入区宽度上限为 840px，正文／活动标题／辅助字号为 14／13／12px。自动滚动状态由 Activity 窗口唯一持有：距底部 60px 内跟随；可滚动内容展开详情时暂停，短内容开合不暂停。当前窗口已到来源末尾时，暂停滚动仍会并入新回答、事实及 Run 状态；历史窗口仍有更新方向缺口时只累计提示，直到显式加载或跳转到最新。稳定来源锚点用于恢复分页和布局变化后的阅读位置。新消息以未读数及 Jump to latest 提示，重复刷新不重复计数。底部指标独立成行，Goal metrics 的 Popover 区分当前 Run 状态与 Goal 聚合指标，并展示缺失值、覆盖率及计量范围说明。输入框仍只有一个发送／暂停主按钮，持久化队列、Steer、授权及审批语义保持原有归属。

实时进度按真实 `executionUnitId`／`actionId` 归入事件或工具步骤的折叠内容，不设独立进度面板。尚无已保存节点的真实执行单元先显示为当前 Run 内的临时步骤；没有执行身份的事件不按相邻位置猜测归属。连续执行节点使用 shadcn Trace，消息和待用户处理的交互断开步骤组；Run 使用独立的浅色标题条。事件标题保持可见，诊断与进度在折叠内容内查看。工具组标题单行截断长命令，完整动作描述与结果在成员详情中换行显示；计数、异常状态与展开按钮保持对齐。等待或终态后不再显示临时进度；已提交的完整历史由 Trajectory 提供，缓存事件不决定 Run 状态。

## Provider 设置与来源选择

设置页（`SettingsPage`）以紧凑行列出受管 Provider 名称、供应商、默认模型与激活标记；凭据圆点仅表示是否已保存密钥，不表示连接正常。`config.toml` 来源作为普通只读行展示。添加入口默认收起，展开后区分内置供应商和自定义 OpenAI-compatible API；后者要求 API 地址，不提供后端未支持的协议或模型目录编辑。每次只展开一个添加或编辑表单，高级参数默认折叠。表单从不回显已保存的明文密钥，编辑时留空保留原凭据；创建或更新成功后收起，失败保留草稿。取消后返回触发按钮。更多操作提供模型目录检查、激活与删除；目录检查结果仅说明目录可用性，不宣称推理调用成功。激活档案不可删除，删除其它档案需在行内确认并提示引用它的 Goal 在恢复时需要重新选择。写入期间锁定表单与档案操作，失败以稳定错误码呈现。

模型选择器（`ModelPicker`）在目录提供多个来源时先选 Provider 再选模型；切换来源即按 `providerProfileId` 重新读取该来源目录。两级选择结果分别写入草稿默认偏好（含来源标识）或 Goal 模型选择（含来源标识，仍受既有安全点约束）。

Provider 表单的 Fetch models 使用当前供应商、端点和密钥查询在线列表，无需先保存档案或填写默认模型。编辑时密钥留空可复用同一供应商档案的凭据；结果仅保存在编辑器中，选择后填入默认模型，仍允许手填。连接字段变化、关闭编辑器或卸载会取消查询并丢弃旧结果；空列表和失败就地提示，不触发保存或生成请求。
