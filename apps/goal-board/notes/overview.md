# Goal Board

React 浏览器前端，呈现已提交会话及临时活动。本文描述当前实现、使用边界与限制。

## 职责与使用

通过本模块的公开入口使用上述能力。状态或副作用由调用方在所属边界控制。

## 边界与限制

本模块不替代其依赖模块的协议或持久化职责；具体输入、失败语义与类型以链接的源码契约为准。

## 操作说明

运行前提、命令和结果示例见 [使用说明](./usage.md)。

## 页面交互

显式 Think 按已提交的请求身份独立呈现活动组，展示目标、进行状态与已保存的 Markdown 分析，并可定位原始轨迹。未提交的输出不作为完成内容；有界会话正文被截断时提示读取完整事件。该展示不增加 Runtime Step，也不包含供应商隐藏推理。

工作区外壳保留 LazyGoal 的白色薄荷绿主题和原始 Logo。侧栏以紧凑行提供工作区详情、搜索、新建 Goal、Goals 与最近八个未归档会话入口；最近列表沿用服务返回的顺序，可展开或收起，选中项显示当前位置。搜索支持 Cmd/Ctrl+K 打开、按标题过滤当前已读取的全部 Goal（含已归档项）、方向键选择、Enter 打开与 Escape 关闭；关闭后恢复原先焦点。工作区详情只展示当前目录和分支，不切换执行位置。侧栏底部的 Settings 入口打开 Provider 设置页，提供受管档案列表与按需展开的编辑器。切换设置页时保留已挂载会话及草稿；返回恢复原视图，选择 Goal、搜索结果或新建 Goal 会离开设置页。页面选择不持久化，刷新回到 Goals。侧栏通过主内容顶部的固定按钮完全隐藏或展开；隐藏后内容占满可用宽度，不保留图标栏。桌面侧栏右边缘支持拖动调整宽度，范围为 200–420px，并按窗口宽度为主内容预留空间；方向键微调，Home/End 调到边界，双击恢复默认 240px。宽度仅保存在当前页面，隐藏再展开保留，刷新重置。窄屏默认隐藏，展开时使用带焦点隔离的模态抽屉，点击背景、按 Escape 或选择导航项后关闭。项目名称与路径来自当前服务的工作区查询，仅展示当前执行目录，不提供多项目切换或多标签。看板使用等高列标题、浅底列容器和白色卡片；内容超出宽度时在看板内部横向滚动。阶段分组保留现有展开交互并显示明确的标题与状态。

`GET /api/project/workspace` 在同一访问边界内读取 Composition Root 的执行工作目录和当前 Git 分支、worktree 根路径；非 Git 工作区及 detached HEAD 明确区分。所有本机 Goal 共用启动工作区，这些值不表示 Goal 创建时的历史绑定。页面在打开会话、已提交会话刷新及重新获得焦点时读取位置，并在紧凑的一行中展示分支与 worktree；完整路径可悬停查看。

React 看板源码位于 [`apps/goal-board`](../README.md)，构建后输出到 `apps/goal-board/dist`，由上述同源静态路由提供；若产物未构建，服务分发内置引导页面提示执行 `npm run build:web`。源码采用职责明确的轻量架构：入口 `src/main.tsx` 只负责挂载，`src/components/WorkspaceShell.tsx` 装配侧栏、设置页与内容区，并保留会话内容的顶层渲染错误边界；会话快照与时间轴通过 `GoalSessionContext` 隔离，指令调度与单飞锁排队状态机通过 `RunControlContext` 隔离，避免全树重复渲染。网络流与状态流解耦为独立自治领域 Hooks（`useRunStream` 维护 SSE 重试与打字机聚合，`useGoalSession` 维护快照同步与草稿态，`useQueue` 维护单飞防重锁与自动出队，`useRunCommands` 承载 Steer/Interrupt/Resume 统一分发降级）；样式集合分为 `style.css`（全局 token、看板与会话视图，含 `--font-size-xs/sm/base` 字号档位）与 `trajectory.css`（仅 Trajectory 视图的单层终态规则）；视图层拆分为独立的 `GoalBoard.tsx`、`GoalSession.tsx` 及 `src/components/` 下的单职责子组件（`GoalCard.tsx`、`ModelPicker.tsx`、`MessageComposer.tsx`、`PermissionControl.tsx`、`WorkspaceContext.tsx` 等）。New Goal 先打开仅保存在页面状态的空白会话草稿；读取工作区默认模型后显示真实名称并允许发送，首条非空普通消息显式提交该草稿模型 ID，作为 Goal 意图和首条用户消息启动唯一 Run。草稿刷新即丢弃，不创建 Goal 或启动模型。页面复用 Slash Command Registry 识别 `/plan` 与 `/model`：前者设置创建模式或提交 Plan Mode；后者打开当前 Provider 的模型选择器，草稿明确选择会立即持久化为工作区偏好，已有 Goal 在安全文本等待点或 completed/failed/cancelled 终态提交到服务端。运行期间输入框可编辑：Enter 打开发送按钮原位的 Steer/Queue 选择，Shift+Enter 换行；空输入时按钮发送 Interrupt 并立即显示 Stopping。页面显示尚未应用的 Steer 与 Queue 顺序。Queue 以内存状态为唯一真值，并按 Goal 以独立 key（`lazygoal.queue.<goalId>`，归属 `src/queue-persistence.ts`）镜像到浏览器 `localStorage`：刷新页面后重新访问同一 Goal 会自动恢复队列与暂停态，当前 Run 完成后按序创建后继 Run；等待人工交互时不出队，失败或取消后暂停，用户明确继续才发送队首。队列消费为空或 Goal 删除时删除对应镜像 key；`localStorage` 写入失败时静默降级为纯内存队列，队列状态机不受阻塞。命令文本本身不发送到消息接口。页面通过 Bearer 头调用 Goal 列表、会话、创建、消息、Steer、Interrupt、模型目录与选择、Plan Mode、结构化交互和授权管理接口，并用同一授权边界连接实时事件；Fragment 凭据不会写入本地存储。模型选择器支持名称/标识搜索，使用原生模态层隔离背景、限制键盘焦点并在关闭后恢复焦点。模型目录请求随选择器关闭或目标变化而取消，迟到结果不会覆盖当前选择器；保存错误保留原选择及结构化等待表单内容。会话视图按 Run 排列消息和已提交步骤：用户消息在步骤前，助手消息在步骤与终态之后；步骤详情可展开查看。Action 审批优先显示白名单内置工具的有界命令或目标摘要，其他工具显示有限输入预览；若预览被截断，用户需先读取当前 Action 的完整输入才能选择持续授权。Goal 与 Workspace 授权可在会话头部的 Goal info 面板查看和撤销；切换 Goal 时清空旧授权列表。实时文本只显示当前模型阶段，新阶段开始即清除上一阶段的临时文本；快照刷新后以新提交事实为准。

未限定 execution unit 的轨迹列表按服务端 cursor 每段最多读取 100 条。左右箭头在相邻段之间移动，已读取的相邻段最多保留 3 段；移出窗口的段返回时按 cursor 重读，使事件列表与内存中的页数据都有界。页脚显示当前导航段末的匹配事件序数/总量，返回上一段时序数随之回退。切换段时滚动到该段第一条实际渲染的事件，跳过列表隐藏的边界事件。限定 execution unit 的轨迹视图不提供跨段导航。

超长会话的 Activity 历史按完整 Run 边界渐进加载（[session-window](../src/session-window.ts)）：初始渲染包含最近一个完整 Run 且消息数达到阈值（50 条），窗口之外在时间线顶部显示"See earlier messages"按钮，按 Run 向上扩页并基本保持视口位置；无 Run 归属的更早消息始终渲染，窗口内消息时不出控件。实时文本增量先进入按帧合并缓冲再提交渲染，跟随滚动以帧节流，流结束后逐字一致（[live-text-batch](../src/live-text-batch.ts)）。会话内容区与 Trajectory 视图的渲染异常由 SessionBoundary 捕获：在视图内显示错误摘要与 Reload session 入口，错误与组件栈进入控制台，顶层 shell 不受影响（[error-boundary](../src/components/error-boundary.tsx)）。

轨迹页将同源 API 的 Run、事件摘要、事件详情及独立保存的模型输入呈现为三轨时间轴、按 Step 分组的事件列表和互斥详情侧栏。列表列序为序号、事件、时间、摘要；当前已加载事件中，Step 起点到下一个 Step 或 Run 终态之间的无 Step 摘要也归入该可折叠区段，之前和之后的 Run 事件保持普通行。该归组只用于显示，不回写 Step 索引。折叠状态由组首记录标识，分页扩展时不会转移到另一个组；程序内工具事件仅在摘要提供父 Action 与调用索引时缩进，并保留原始详情可查。搜索、类别过滤、时间轴缩放／平移／范围筛选、模型输入详情、重试组和跨段分页继续使用现有查询与读取边界；筛选或折叠隐藏选中事件时关闭对应详情。

看板通过受同一 Bearer 令牌保护的 [`session-metrics` 查询路由](../../../packages/session-metrics/notes/overview.md)读取各 Goal 的累计指标；已选 Goal 额外订阅指标 SSE。卡片展示 Goal 汇总；会话输入区下方展示轮次、Step、模型用量、端到端输出速率，以及最近一次当前模型调用结束后的上下文剩余比例。输出速率在每条模型调用结束事实写入后更新，运行中的调用不参与速率计数；卡片、摘要栏和详情弹窗均保留测量与排除调用数。未上报用量和不可计算的缓存命中率、输出速率、上下文余量显示为缺失值；部分用量覆盖单独提示，不将缺失值计为零。输出速率的计时范围和聚合规则由会话指标模块定义。

任务批准卡片会在批准按钮前列出 Plan Run 候选路线中的全部有序阶段、目标和验收条件；普通 Run 没有该路线清单。卡片只呈现候选内容，不自行赋予阶段身份或状态。

Activity 时间线在执行事件之前独立显示当前获批 Plan Run 的完整路线，包括阶段顺序、目标、验收条件、待执行/执行中/已接受状态及最近修订理由；该列表不依赖 Execution steps 筛选开关。普通 Run 不显示路线列表；既有 Trajectory 活动仍单独可查。视图仅消费服务端的路线 DTO，不改变 Runtime 状态。

`npm run dev:web`（或 `npm run dev --prefix apps/goal-board`）只启动无后端授权的布局预览，不代理正式 Runtime API。真实操作须先构建静态页（`npm run build:web`），再从 `lazygoal web` 打印的本机入口打开。全局设置页仅管理受管 Provider 档案；页面不提供模拟 Goal、示例计划、虚构完成状态或项目分配。

已有会话刷新失败时，页面保留最后保存的消息、等待表单和当前草稿，并显示错误及重试入口；刷新错误期间禁用会话提交，成功读取最新快照后恢复。只有首次读取尚无会话时，错误才替代会话内容。SSE 暂无活动事件本身不表示保存的会话不可操作。

已提交步骤与当前 Run 的安全公开实时事件由 [`ActivityProjector`](../src/activity-projector.ts) 组合成可重建活动组。它仅按同 Run、同阶段、相同白名单类别且来源相邻的调用聚合；未知工具保持独立成员。用户回复、等待、阶段变更、终态失败、未知活动及类别变化会断组。组内展开可查看成员顺序、已提交摘要、失败尝试与原始 Trajectory 定位入口。实时调用立即显示运行状态，Action ID 将其与随后保存的步骤合并；未提交实时结果会明确标记且不会写入会话历史。SSE 队列缺口会清除不完整的临时投影并读取最新 Snapshot。两种 Run 模式共用这一展示投影，Plan 路线仍单独展示；分组不修改授权、运行状态或评测事实。

## Provider 设置与来源选择

设置页（`SettingsPage`）以紧凑行列出受管 Provider 名称、供应商、默认模型与激活标记；凭据圆点仅表示是否已保存密钥，不表示连接正常。`config.toml` 来源作为普通只读行展示。添加入口默认收起，展开后区分内置供应商和自定义 OpenAI-compatible API；后者要求 API 地址，不提供后端未支持的协议或模型目录编辑。每次只展开一个添加或编辑表单，高级参数默认折叠。表单从不回显已保存的明文密钥，编辑时留空保留原凭据；创建或更新成功后收起，失败保留草稿。取消后返回触发按钮。更多操作提供模型目录检查、激活与删除；目录检查结果仅说明目录可用性，不宣称推理调用成功。激活档案不可删除，删除其它档案需在行内确认并提示引用它的 Goal 在恢复时需要重新选择。写入期间锁定表单与档案操作，失败以稳定错误码呈现。

模型选择器（`ModelPicker`）在目录提供多个来源时先选 Provider 再选模型；切换来源即按 `providerProfileId` 重新读取该来源目录。两级选择结果分别写入草稿默认偏好（含来源标识）或 Goal 模型选择（含来源标识，仍受既有安全点约束）。

Provider 表单的 Fetch models 使用当前供应商、端点和密钥查询在线列表，无需先保存档案或填写默认模型。编辑时密钥留空可复用同一供应商档案的凭据；结果仅保存在编辑器中，选择后填入默认模型，仍允许手填。连接字段变化、关闭编辑器或卸载会取消查询并丢弃旧结果；空列表和失败就地提示，不触发保存或生成请求。
